# 决策记录: SIMD 单条指令回退

状态: rejected — 通用单步接口的缓存行为未满足当前执行器边界，先直接覆盖热点指令

## 问题

[交互测量](../../proposed/testing/2026-10-11-交互卡顿测量与优化流程.md)的固定起点运行 `88BA9BA9-9AF9-4CBF-8EEE-4A4332BA9043` 中，1.813 秒窗口包含 Direct CPU 401.463 ms 和 Unicorn CPU 448.921 ms。Settings RenderThread 的两者分别为 34.290/175.826 ms。按首条指令分类，主要回退来自 SIMD 元素乘法、浮点比较、转换等。Mac App 被遮挡，结果用于计算路径诊断；宿主实际显示时间尚未采集。

当前遇到 Direct 未覆盖的指令后，Unicorn 会执行到 Linux 返回、异常或抢占边界。缺少一条浮点指令即可使后续已被 Direct 支持的代码继续在 Unicorn 中执行。整段回退保留了独占访问的进展条件，修改需要明确区分仍持有独占记录的情况。

## 提案

已尝试新增启动前实验开关 `shortSIMDFallback`，默认关闭，对应 `NCE_DIRECT_SHORT_SIMD_FALLBACK`。仅在首条指令属于 AArch64 SIMD/浮点数据处理组，且 Direct 返回的独占地址为 `UINT64_MAX` 时，以 Unicorn 的下一条 PC 退出地址执行当前指令。结束后沿用现有寄存器、异常、缺页、抢占与 Linux 返回处理，再回到 Direct。独占记录仍有效时保留原整段回退。

指令大类依据当前固定 Unicorn 源码 `qemu/target/arm/translate-a64.c` 的主解码：bits 28:25 为 `0x7` 或 `0xf`。此范围覆盖数据处理，访存与独占指令使用各自原分组。当前不扩大 Direct 解码范围，不改变 Unicorn 或内核 ABI。记录开关实际值、短回退次数和因独占记录保留整段回退的次数。

先用刻意包含未覆盖 SIMD 指令的客体用例检查寄存器结果、后续存储和独占循环完成，再验证单核/双核 CLI/GCD、ART 与完整桌面。性能使用同一构建开关、固定数据种子和同一绝对时间手势比较，记录完整帧、CPU 时间和实际输入时序。详细诊断与低开销对照分别解释；Mac 可见性及 iPhone 验收条件继续保留。

## 曾考虑的替代方案

- 逐个扩展 SIMD 解码：可减少对应指令的回退，但每组都需核对合法编码、浮点状态和宿主指令支持；后续按剩余耗时选择，先评估减少整段解释执行。
- 对所有未覆盖指令都单步：范围包含访存与独占状态边界，首版限定到测量中占主要时间的数据处理指令。
- 每次只执行固定数量指令后返回：可能持续打断包含未覆盖指令的独占循环，先保留活动独占记录对应的整段执行。

## 验收标准

1. 默认关闭；设置可持久化，运行前校验，请求和实际日志一致。
2. 单条 SIMD 回退后的向量、整数、浮点状态及后续内存操作正确；活动独占循环保持可完成，已有 ABA、代码更新、缺页、信号和抢占检查通过。
3. 同构建对照记录全部失败与波动；预期 Unicorn CPU 时间下降，交互帧与动作完成时间须有可重复改善。只减少回退区间或改变实际负载不构成性能通过。
4. 本机 CLI/GCD、桌面与持久化完成后，继续两端集成与集中设备验收。

### 本机验证进度

实验实现曾接入启动设置、请求、环境变量和实际运行配置，默认关闭。单核开关两组 CLI/GCD、双核开启 CLI/GCD、Bionic/ART CLI/GCD 成功；记录分别位于 `work/native-linux-nce/lkl-short-simd-1-core-v3/summary.json`、`lkl-short-simd-1-core-off/summary.json`、`lkl-short-simd-2-core-v3/summary.json` 和 `lkl-short-simd-1-android/summary.json`。核心用例覆盖 SIMD 结果、后续存储、浮点溢出标志及有界独占重试；单核开启记录包含 2 次短回退和 8 次独占保护回退。首版浮点状态用例沿原整段回退执行，后续增加系统调用边界，单核两种入口确认 3 次短回退和 8 次保护回退。配置检查覆盖默认值、保存值、环境往返、请求往返及已有构建依赖；报告检查成功。

首轮核心运行未执行新增用例：探针调用 `dynamic_code_tests()`，新增用例最初只挂在 `code_tests()`。验收器因缺少对应成功记录而失败，原始结果保留在 `work/native-linux-nce/lkl-short-simd-1-core/`。将用例移至实际入口后通过。第二版独占用例虽完成，但保护回退计数为 0；增加系统调用边界和有限重复后，确认两种入口各执行 8 次保护回退。后续实验核心验收加入短回退和保护回退计数检查。

完整桌面首版开启失败，`lkl-short-simd-1-desktop/summary.json` 在早期服务阶段记录客体取指故障并等待超时；同条件关闭开关的服务运行成功，见 `lkl-short-simd-services-off/summary.json`。检查固定 Unicorn 实现发现，`count=1` 与 `count=0` 交替会增加/删除全局指令钩子，删除时按曾记录的虚拟区域失效 TB，随后清空全部 TB。其与多个客体地址空间及填充回调的交互需要额外处理。首版不通过桌面验收。

候选调整为 `until = pc + 4`，计数参数保持原抢占配置。选定的 SIMD/浮点数据处理组没有正常分支，正常结束地址明确；非法编码仍沿现有异常路径处理。该方式复用退出地址，不切换计数钩子。浮点溢出用例增加系统调用边界，确保设置 FPCR/FPSR 后重新从 Direct 开始。核心 CLI/GCD 成功，记录在 `lkl-short-simd-until-1-core/` 和 `lkl-short-simd-until-2-core/`。

退出地址的独立用例 `work/native-linux-nce/interaction-preflight/until-cache.c` 先执行 `FMUL; ADD; SVC` 缓存整段，再从同一 PC 执行到 `pc+4`。第二次仍执行了 ADD 和 SVC，第三次才停在目标地址。固定 Unicorn 在退出时失效对应 TB，已有 TB 首次使用新退出地址时可以越界。完整桌面第二版在早期图形阶段持续运行，确认退出地址契约失败后主动终止该实验进程，报告返回 -15；该轮没有完成桌面检查。

两种公共 API 用法均未满足本候选验收。继续保持精确单步需要处理现有 TB、地址空间与钩子失效关系，预计增加切换和编译成本；本轮停止该方向，转向直接覆盖实际热点 SIMD 指令。移除实验设置和运行路径，保留通用向量/浮点/独占连续执行回归。失败报告、独立复现源码和数据仍放在原工作目录。恢复默认执行路径后，新增连续执行用例与核心 CLI/GCD 成功，结果在 `work/native-linux-nce/lkl-simd-continuation-core/summary.json`。

完整故障原因中，计数钩子失效与地址空间交互仍为推断；退出地址越界已独立复现。

### 复杂度审查

实际使用方为启动设置、benchmark 请求、翻译探针和执行循环。候选只增加一个启动布尔值、每客体线程的本次选择及每 CPU 两个计数；没有新增执行器接口或指令解释实现。每线程选择必须跨 SMP 的离开/重入保留，放在共享 CPU 临时字段会在切换后丢失；每 CPU 计数用于确认真实路径。删除独占条件会让尚未完成的原子序列持续跨执行器重试，因此保留。开关用于本轮对照；候选停止后与实现一同移除，后续候选独立记录。

## 风险

Unicorn 的退出地址可能增加 TB 编译或检查成本；频繁切换执行器也可能使总耗时上升。Direct 的独占记录必须准确传递到回退选择，错误缩短会影响原子循环进展。新增计数只描述所选路径，无法单独说明其性能收益。
