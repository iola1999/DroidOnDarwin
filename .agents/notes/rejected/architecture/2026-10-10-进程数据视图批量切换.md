# 决策记录: 进程数据视图批量切换

状态: rejected — 完整 Android 对照的映射耗时增加

## 问题

完整 Android 启动反复恢复同一宿主地址窗口。`demand` 减少了预先映射，但会触发大量宿主缺页；512 页的有限恢复对照增加了映射时间，整机收益尚未确认。需要验证能否复用每个进程已经建立的数据视图，在切换时减少宿主 API 调用。

## 提案

先做独立 Darwin 原型：为两个逻辑地址空间分别保留稀疏数据视图，每个视图包含不同的 RAM 别名和页面权限；通过一次 `mach_vm_remap` 替换执行窗口中的大段数据区。核对不同进程的私有值、共享值、空洞、只读权限和跨区域切换，并测量切换用时。

若平台原型通过，再设计 Linux PTE 到视图的同步。必须覆盖 fork/COW、mprotect、取消映射、页面回收和 mm 销毁。已有准备好的 JIT 执行页需要单独保留；本提案首先针对堆和线程栈所在的数据范围。每个 mm 的额外虚拟地址预留、Darwin 映射元数据和 iPhone 地址容量仍待测量。

### Linux 对照实现

曾增加 `shadow` 对照模式，范围从 `NCE_BRK_OFFSET` 到客体地址空间末尾，覆盖 brk、匿名堆和栈。ELF 与 ART 执行区继续使用已有恢复方式。每个 Linux mm 持有一个宿主数据视图；PTE 安装、清除和 TLB 范围刷新同步该视图。返回用户代码时，先恢复执行区，再整体替换数据范围。当前 mm 的 PTE 修改同时更新正在执行的窗口。

新增宿主接口仅负责视图分配、释放和激活；页面内容和权限沿用已有 RAM 别名接口。fork 的新 mm 从空视图开始，由 Linux 复制 PTE 的原流程建立映射；源进程的 COW 写保护由 TLB 刷新同步。销毁检查分配与释放数量一致。默认方式先保留 `demand`，完成同一负载对照后再选择。

## 曾考虑的替代方案

- 永久预先恢复所有访问过的页：已有完整启动测量显示映射开销较大。
- 全部按缺页恢复：降低预先映射量，但当前完整会话仍有大量宿主信号。
- 固定容量记录常用页：已实现对照；可继续测量，尚无足够结果作为默认方式。

## 验收标准

独立原型先证明跨多个 Darwin VM 区域的整体重映射实际可用，核对权限、共享和隔离，并保存结构化结果。只有平台调用语义通过后，才决定是否接入 Linux；接入后必须通过现有进程与完整 Android 回归。Mac 结果与 iPhone 地址容量、性能分别记录。

### 首轮平台原型结果

Mac 上 3 GiB 稀疏范围通过不同进程私有值、共享页、空洞、只读页、修改映射后再切换的检查。测试使用两个源视图和一个目标视图，没有分配 9 GiB 物理内存。结构化结果见 [Darwin 原型结果](../../../../experiments/native-linux/results-macos-view-swap.json)。

每组 128 次切换，16/128/1024 个分散页面的逐页与整段重映射用时保存在结果文件中。首轮原型中，稀疏小工作集没有收益，1024 页场景约为 1.64 倍；追加共享页写入检查后的复测数值以结构化文件为准。该原型未包含 Linux PTE 同步、代码区、COW 建立和 Android 调度，暂不据此推算整机提速。Linux 对照将比较取消重复缺页后的收益与额外视图成本。

## 风险

大范围 `mach_vm_remap` 可能仍随 VM 区域数增加开销。每个 mm 的视图需要额外地址空间和内核映射元数据；可用虚拟地址规模尚未在手机确认。PTE 与宿主视图同步遗漏会破坏进程隔离或页面保护。

### 完整 Android 对照与取舍（2026-10-10 07:25）

`shadow` 已通过基础 Linux 内存和 28 组进程交换检查，进入完整 Android 并报告开机完成。运行约 144.404 秒时，数据映射累计耗时 87.360 秒；SystemUI 服务在 60.356 秒出现 ANR。桌面检查随后因调用 Android 运行库缺少的 `Files.readString` 失败，这个独立问题另行修复。结果见 [完整启动对照](../../../../experiments/native-linux/results-macos-desktop-shadow.json)。此次未完成桌面和生命周期验收。

完整启动的映射耗时已超出继续采用的条件，撤下 Linux `shadow` 集成和三个宿主视图接口，保留独立 Darwin 原型与结构化记录供后续研究。`hot` 的完整启动对照同样没有确认收益，其固定页面缓存也已撤下。实际桌面继续采用 `demand`；基础隔离测试成功不能替代整机收益和生命周期验收。

复杂度审查：每个 mm 的额外虚拟地址视图需要同步 PTE、COW、取消映射和销毁，并增加宿主内存映射元数据。撤下后既有 PTE、按需映射和权限检查继续承担这些职责，避免为未采用的模式长期维护额外状态。独立原型只在显式运行时分配视图，产品入口没有使用方。
