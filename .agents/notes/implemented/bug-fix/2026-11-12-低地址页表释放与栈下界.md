# 决策记录: 低地址页表释放与栈下界

状态: implemented

## 问题

主线 `a26f96c` 的原 init lifecycle 在 CLI/GCD 退出后均记录三条 `BUG: non-zero pgtables_bytes on freeing mm`，数值依次为 16384、32768、32768。`544e15d` 的原 `/etc` 链接修复使用同一内核复验，告警仍然存在；对应原始日志保存在 `work/native-linux-nce/stock-init-main-original-ext4-v1/` 和 `work/native-linux-nce/stock-init-main-root-etc-v1/`。宿主上下文计数已全部回收，Linux 页表释放仍有缺陷。

`scripts/lkl_translation_patch.py` 从 `1d1042b` 起将 `FIRST_USER_ADDRESS` 设为 `nce_user_base`，用于保留低地址空洞和 `MAP_GROWSDOWN` 下界。`mm/memory.c` 的 `free_pgd_range()` 先将起点按 PMD 对齐，再与这个下限比较；64 KiB 起点被对齐为零后，首个 PMD 范围被跳过。4 KiB 页对应 `[0, 2 MiB)`，16 KiB 页对应 `[0, 32 MiB)`。上层页表释放也使用对齐后的起点与同一下限比较，低地址 PMD 表可能继续保留。这些路径同时跳过页表析构、延迟释放和计数扣减，符合现有告警规模；具体 PID 与表项对应关系尚未测量。

`pgd_alloc()` 已从 `93c4d0f` 起使用 `clear_page(pgd)`，每个用户 mm 独立拥有页表，内核映射使用 `init_mm`。固定映射、内存保护、固定重映射、低地址 hint、用户复制和 NCE fault 都有独立地址检查。修复前 `expand_downwards()` 直接使用 `FIRST_USER_ADDRESS`；`/proc/self/mem` 的 `access_remote_vm()` 可以经 `expand_stack()` 调用这个函数，因此修复须同时保留内部栈增长的地址下限。

## 决策

恢复上游 `FIRST_USER_ADDRESS=0UL`，按完整的用户页表范围释放。将栈增长的下限改为显式检查 `nce_user_base`，保留普通 Linux 的 `mmap_min_addr` 与栈保护间隔。16 KiB 单 CPU builder 会复用生成源码，补丁将已经生成的旧定义恢复为零；这个迁移块支持重复应用。4 KiB 和双 CPU builder 继续按原流程重新生成源码。构建摘要新增实际修改的 `mm/mmap.c`。

核心地址检查增加两个实际行为：同一 PMD 内两个不相邻 VMA 解除其中一个后，另一个仍可访问；合法栈扩展后，`/proc/self/mem` 可以读取栈内数据，对 `base-PAGE` 的读取返回 `EIO`。后一项直接覆盖内部栈扩展路径。核心与原 init 观察入口均检查内核释放告警，旧失败日志必须使验证失败。

首轮两种页大小的 core 已成功，独立审阅发现原配置的 `CONFIG_LSM_MMAP_MIN_ADDR=65536` 与 guest base 相同，LSM 的地址下限也会拒绝 `base-PAGE`。增加高地址独立检查：专属 guest base 使用 128 KiB，保留原 LSM 配置，使越界地址高于 LSM 下限。部分解除映射再经 `/proc/self/mem` 读取剩余页，确认 Linux PTE 仍提供对应数据。高地址检查使用工作目录内的实验副本，产品布局保持现有配置。

### 本机验证

环境为 Apple M5 Ultra、macOS 27.0（26A428），单 CPU、sparse guest、Direct flat/PTE/TBI、dual code memory、128 MiB 执行缓存、按页失效和 timer 抢占。`work/native-linux-nce/page-tables-16k-core-v2/summary.json` 与 `page-tables-4k-core-v2/summary.json` 的 CLI/GCD 分别通过 71/72 项检查，每次释放 70/70 上下文，页表告警为零。合法栈读取、越界读取、同 PMD 不相邻 VMA 的部分解除映射及剩余 PTE 数据均通过。

`page-tables-stock-init-v1/summary.json` 的 lifecycle 两入口各释放 2/2 上下文，original 分别释放 12/12、14/14，页表告警为零。原 policy/enforcing、原配置读取、服务 exec 失败与重启行为继续保留；原系统完整启动由[原 init 主题](../../proposed/architecture/2026-11-12-原始SDK36-init与rc启动实验.md)继续处理。此前 `stock-init-main-root-etc-v1/cli-lifecycle.log` 保留三条页表告警，SHA-256 为 `105f4bf3014e19ce3ebc19666fc8c31abbd4019b1d647afb271d1cbba05bf912`。以下回放接受 8 个成功报告，并对同一组结果加入原失败日志后拒绝全部 8 个：

### 复杂度审查与偏离

`FIRST_USER_ADDRESS` 的实际使用方为 Linux 页表释放与栈扩展。用户 mm 已独立拥有页表，释放路径继续使用上游零下限；栈扩展单独检查 `nce_user_base`，没有新增通用页表释放分支或宿主状态。移除独立栈检查会让 112 KiB 输入通过 `mmap_min_addr` 条件，后续路径仍受栈保护间隔、限额与访问规则约束，因此保留这个检查。原释放下限的历史定义仅用于生成源码迁移，迁移完成后不进入内核行为。

高地址专项执行了保留检查的两个入口。移除检查的运行在此前代理中未完成，本阶段保留其独立源码和构建记录，并记录源码消融分析；该内核的最终返回结果仍未验证。验证摘要明确 `selected_variants=[with-check]`、`ablation_verified=false`。本阶段以高于 LSM 下限的实际拒绝行为验证 NCE 栈边界，成功结果只包含实际执行的保留检查。

## 曾考虑的替代方案

- 保留非零释放下限，只清零 `pgtables_bytes`：页表析构和物理页释放仍被跳过，不能修复资源生命周期。
- 在通用 `free_pgd_range()` 中增加 LKL 专用对齐规则：扩大内存管理改动，并重复表达每个 mm 已独立拥有页表的约定。
- 仅恢复零下限并依靠 NCE fault 拒绝越界访问：`access_remote_vm()` 可以直接扩展栈，仍需内部地址检查。

## 影响

低地址用户 mm 退出后完成页表计数回收，内部栈扩展保留客体地址下限。本机功能与 iOS 编译已验证。Linux 分配器归还、Darwin 驻留内存下降和持续资源占用尚未单独测量；设备资源、JIT 授权与持续性能待真机验证。

## 风险

部分解除映射的释放范围受相邻 VMA 影响，不能通过只检查进程退出告警覆盖。栈增长下限的遗漏也可能只在内部访存出现，因此两项行为回归均保留。原 init 完整启动仍有独立的执行和系统服务问题，本次修复按页表和地址边界验收。
