## 问题

全新工作目录执行 `python3 scripts/probe_lkl.py --processes`，Linux 内核已生成，用户态构建在 `build_android_linker.py` 的 Scudo 归档 SHA-256 检查处失败。下载对象是 `platform/external/scudo` 固定提交 `e3a9ec51431e8a7afdba4004c3e4fde3d0ca8544`，实际归档摘要为 `7fdde5ce14bafb569aafe128532a8215e9e1eefa198752bcdba22814ba60316a`，记录值为 `93dace5f3fbdac5c70c81ac34990772d8d37a37666ca4e841979c7b82992eb9c`。历史归档摘要差异的原因尚未确定。

原始失败日志保存在 `work/project-audit-2026-11-12/offline-lkl-process-build.log`，下载文件保存在 `work/native-linux-nce/android/scudo.tar.gz`。

## 决策

通过 Git 取得同一固定提交，比较归档与 Git 树的全部文件路径、类型、权限和原始字节。只有确认内容和模式完全对应才更新归档摘要；保留旧摘要、实际摘要、Git 提交和比较结果。其他依赖遇到同类失败时逐个核对，继续执行已有摘要校验。

### 源码核对结果

2026-11-12 通过 `git fetch --depth=1` 取得清单中的固定提交，用 `git ls-tree -rz --full-tree` 枚举全部非目录项。归档中的普通文件使用原始字节计算 Git blob ID，符号链接使用链接目标字节；同时核对路径集合、重复路径、类型、可执行位及普通文件权限。Scudo 118 项、Bionic 3455 项、libbase 96 项、libziparchive 46 项、liblog 196 项，合计 3911 项全部一致，差异均为零。五个归档的实际 SHA-256 均与原清单不同，已经在内容核对成功后更新。

`core_header` 另按提交 `68be0c2c0006a0740d0b1809abe4717308f90d15` 的 Git blob 核对原始文件，内容和原清单 SHA-256 一致，保留其摘要。[验证摘要](../../../../experiments/native-linux/android-source-verification-2026-11-12.json)保存各项固定提交、Git 树、旧与新归档 SHA-256、文件数量和比较方式；一次性核对脚本保存在 `work/project-audit-2026-11-12/verify_android_sources.py`，其摘要一同记录。该核对覆盖下载源码，构建脚本后续的本地补丁由原流程处理。
