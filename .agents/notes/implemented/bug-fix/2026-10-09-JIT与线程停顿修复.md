# 决策记录: JIT 与线程停顿修复

状态: implemented

## 问题

主会话的早期设备测试出现多次闪退、运行长时间无进展及日志页面滚动卡顿。故障分布于调试器断开、代码授权地址、数据映射、线程信号与界面日志读取，后续需要保留各自的原因和有效回归范围。

本记录于 2026-10-10 补录，汇总已经发生且有实现与结果的缺陷。原始时间、包编号和参数见[N2 手机记录](../testing/2026-10-09-N2手机测试与故障记录.md)、[Linux 用户态与抢占](../architecture/2026-10-09-Linux用户态与抢占.md)及[Android 阶段记录](../architecture/2026-10-09-Android用户态与Metal阶段记录.md)。

## 决策

| 故障与触发条件 | 原因与处理 | 验证及剩余范围 |
| --- | --- | --- |
| 初版在请求调试器断开后立即断言退出 | 断开完成存在时序差；按原实现每 10 ms 检查、最多五秒，失败返回界面 | 已覆盖立即与延迟断开、持续连接、查询失败和回复长度异常；参数为历史修复值 |
| R1 在新重映射的 RX 地址取指闪退 | 崩溃报告包含 `KERN_CODESIGN_ERROR`；保持调试器最初准备的代码地址，通过 RW 别名更新内容 | R2 的固定地址执行与更新成功；R2 随后仍在 Linux 初始化时失败 |
| R2 的 `shmem_map` 中 `vm_remap` 失败 | 全部区域都曾交给调试器准备，数据映射受限为当时推断；R3 仅准备代码区，RAM 和目标数据区使用普通映射 | 原失败未记录具体 Mach 返回码；R3 加入返回码与目标映射预检，真机通过完整早期检查 |
| N2-B1 从 GCD 入口运行时无法完成计算线程测试 | 工作线程继承 `SIGUSR2` 屏蔽，客体线程收不到抢占；入口恢复所需信号 | CLI 与 GCD 回归成功；B2 真机完成 16 轮、139 次抢占，结果文件保留 |
| N3-S3 预留连续地址失败 | 约 16.58 GiB 预留失败；初始日志缺少 errno，具体系统拒绝原因未确定；后续缩至约 4.58 GiB 并调整分配器预留 | S5 真机验证了缩减后的地址、运行时和执行条件；容量继续随真实负载评估 |
| N3-S4 长时间停在准备 JIT 代码区域 | StikJIT 1.9.0 写入地址只保留低 36 位，且未检查写入回复；S5 使用完整地址并逐项检查回复，异常时退出 | 10 组协议回归覆盖地址边界及错误，S5 真机 97 个不同名称测试成功 |
| S5 日志页面滚动卡顿 | 主线程反复读取完整日志并重绘；S6 后台增量读取，预览最近 80 行，结束时停止轮询 | 5 组日志行为检查与构建成功；用户 2026-10-09 21:53 确认滚动恢复，Android 界面性能仍待验证 |

### 后续回归要求

代码授权或地址布局修改时保留完整地址、代码与数据映射边界、动态更新和执行失败恢复检查；线程或入口修改时覆盖实际 GCD 入口及抢占；日志实现检查增量读取、UTF-8 分段、文件替换及结束后的生命周期。

结果文件：[R1](../../../../experiments/native-linux/results-ios-n2-r1.json)、[R2](../../../../experiments/native-linux/results-ios-n2-r2.json)、[R3](../../../../experiments/native-linux/results-ios-n2-r3.json)、[B2](../../../../experiments/native-linux/results-ios-n2-b2.json)、[S5](../../../../experiments/native-linux/results-ios-n3-s5.json)。本轮只整理已存在的结果，没有重新运行设备或构建测试。

## 曾考虑的替代方案

早期整体准备可执行区域影响需要替换的数据映射，后续限定为代码区。仅测试命令行入口遗漏了 GCD 的信号屏蔽条件，后续增加应用入口回归。把完整日志持续放进单个文本视图导致重绘开销，改用后台增量读取与有界预览，同时保留完整导出内容。

## 影响

这些检查覆盖已知触发条件，新增运行方式仍需对应验证。逐页 JIT 写入检查增加准备阶段往返，保留这一取舍以明确失败；原生执行与完整 Android 的持续性能继续单独测量。
