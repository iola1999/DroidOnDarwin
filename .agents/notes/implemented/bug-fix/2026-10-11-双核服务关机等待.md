# 决策记录: 双核服务关机等待

状态: implemented

## 问题

继续性能优化时，工作区保留了[双核 Linux 集成](../../proposed/architecture/2026-10-11-运行时执行器与双核Linux.md)的未提交实现。前序服务回归已经完成 Android 服务与数据盘只读卸载，但宿主没有在 120 秒期限内退出。前序采样包含网络命名空间清理中的 `rcu_barrier()`；将网络清理队列排空加入 `machine_halt()` 后仍失败。

本轮从 `d21be84` 和已有未提交实现继续。先复现当前失败，区分 RCU 回调等待、工作队列等待与 CPU 停止等待，再修改已确认的生命周期顺序。当前没有其他运行中的本项目构建或测试进程。

## 决策

先使用独立双核构建运行服务负载，保持原有期限、数据持久化和资源释放检查。采样与必要的阶段日志用于定位等待位置。修复后依次验证服务 CLI/GCD、内核边界、Bionic/ART 和完整可见桌面，再恢复关闭诊断的性能对照。

## 曾考虑的替代方案

- 延长服务测试期限：当前退出停顿已重复发生，先查明等待原因；延长期限无法检查资源释放是否正确。
- 在宿主直接终止进程：会跳过 Linux 线程、RCU 和执行器资源释放，不满足干净关机验收。

## 验收标准

- 相同服务负载在 CLI/GCD 中完成全部检查、正常退出，用户上下文和地址表释放完整。
- 增加覆盖实际失败条件的回归，说明旧实现和修复后的行为。
- 完整桌面包含 Launcher、Clock、Files、持久数据与关机检查。功能成功后才能用于性能比较。
- 记录构建输入、请求与实际配置、原始结果路径及验证边界。

## 风险

RCU、网络清理和 CPU 停止存在顺序要求。过早停止 CPU 或中断会阻止回调完成；排空开始后若仍有生产者创建资源，也无法保证退出。修复需保留生产者停止和资源生命周期检查。

## 本轮复现

`work/native-linux-nce/lkl-direct-smp-services-resume/summary.json` 的首轮 CLI 服务检查成功，清理耗时 0.725184 秒。与前序 `lkl-direct-smp-services-netns-drain/summary.json` 比较，共同构建输入哈希一致；配置差异为关闭 `parallel_profile` 和仅运行 CLI。随后继续 CLI/GCD 交替重复。前序失败的并行计时设置需要单独恢复检查，尚未确定该设置与停顿的因果关系。

### CPU 停止确认

关闭并行计时的 CLI/GCD 三组共六轮全部成功。恢复计时后，CLI 第一轮和 GCD 第一轮成功，CLI 第二轮在清理阶段超过 120 秒。结果在 `work/native-linux-nce/lkl-direct-smp-services-resume-profile/summary.json`，失败期间的 `cleanup.sample.txt`、`cleanup.vmmap.txt` 和按本轮内核符号解析的 `cleanup.symbolized.txt` 保留在同目录。该组包含采样，仅用于功能与定位。

本轮调用栈显示宿主等待 `lkl_cpu_wait_shutdown()`；CPU 0 的 Linux idle 任务停在调度等待，`idle_host_task_loop()` 停在宿主信号量，全部剩余工作线程均在等待。这次采样没有正在等待的网络清理函数。内核映射基址由 `vmmap` 的执行段地址减去 ELF 段偏移得到，解析使用本轮 `lkl.so`。

`machine_halt()` 中的 RCU 等待允许调度。此前已唤醒的 idle host 任务可能在停止请求后成为 CPU 0 最后一个可运行任务；原 `cpu_put()` 在 `single_task_running()` 时释放 CPU 所有权后进入宿主等待。此时停止标记已经阻止新的中断取得 CPU，Linux idle 任务没有机会执行停止确认。修复在停止标记存在、宿主任务持有最后一层 CPU 所有权时强制调度，使 Linux idle 任务完成释放和确认。正常运行的宿主交接规则保持原条件。

对实际生成的 `cpu_put()` 增加最后一个宿主任务、嵌套持有和正常运行边界检查后，恢复失败时的并行计时设置，CLI/GCD 各三轮均成功。每轮用户上下文分配数与释放数一致，数据盘正常退出；结果在 `work/native-linux-nce/lkl-direct-smp-services-shutdown-handoff/summary.json`。双核核心检查随后在 CLI/GCD 中成功，结果在 `work/native-linux-nce/lkl-direct-smp-core-shutdown-handoff/summary.json`。完整可见桌面随后成功，Launcher、Clock、Files、持久数据、图形通道和数据盘退出检查均成功，1091 个用户上下文全部释放。结果在 `work/native-linux-nce/lkl-direct-smp-desktop-shutdown-handoff/summary.json`。

### 边界回归与复杂度审查

`scripts/test_lkl_shutdown.py` 提取实际生成内核的 `cpu_put()`，检查停止期间最后一个宿主任务必须调度、存在宿主等待者时仍需完成停止、正常运行的空闲交接、嵌套所有权和非宿主调用。修复版本成功；只移除停止条件的对照版本返回 1，并报告最后一个宿主任务没有调度。结果在 `work/native-linux-nce/lkl-shutdown-handoff-test/result.json`。这项检查只覆盖 CPU 交接条件，完整 Linux 生命周期由真实服务和桌面回归验证。

按 reclaim-code-entropy 审查：修复复用既有 `shutdown_gate`、CPU 所有权计数与调度函数，没有新增停止状态、线程或计时器。停止标记的实际使用方为 CPU 访问入口和 idle 退出；补充的读取使最后一个宿主任务遵守同一生命周期。移除条件会恢复回归中的等待路径。前序网络清理排空实现暂时保留，尚未完成其独立移除对照。

## 影响

本次提交只包含 CPU 停止修复、边界回归及对应记录，继续保留工作区已有的双核集成改动。结构化结果见 [macOS 关机回归](../../../../experiments/native-linux/results-macos-smp-shutdown.json)。在 Apple M5 Ultra、macOS 27.0 / 26A428 上，独立双核 Direct 构建、1 GiB 客户内存、128 MiB 执行缓存、16 KiB 页、2 ms 计时抢占配置的单轮完整桌面负载耗时 292.446387 秒，清理 0.419715 秒；100 ms 采样的 footprint 峰值为 3,485,896,640 字节。这一轮用于功能验收，尚未形成性能对照，iOS 产品仍待集成。
