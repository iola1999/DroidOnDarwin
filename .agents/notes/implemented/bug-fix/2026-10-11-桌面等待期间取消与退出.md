# 决策记录: 桌面等待期间取消与退出

状态: implemented

## 问题

`0.22.0-Mac-20261011-000945` 公共镜像实验第三轮在 300.117 秒请求停止。此时 `nce_surface_check()` 正在阻塞等待辅助进程，无法检查 `/data/nce/session-stop`。之后辅助进程退出状态为 9，Framework 检查进程以 109 退出，宿主 `run_program()` 的成功断言触发 SIGABRT，Linux 正常卸载步骤未执行。数据盘初次只读检查返回 4，经日志恢复后只读检查返回 0。

日志和原始内存采样保存在 `work/native-linux-nce/benchmarks/20261011-001050-a66d4b/617B27B5-1163-4293-B101-D538A8FE58E4/`，结构化摘要见[公共镜像实验](../../../../experiments/native-linux/results-macos-desktop-boot-image.json)。本记录覆盖取消与退出行为；该轮启动慢的原因尚未确定。

## 决策

让交互会话在等待首帧的辅助进程期间检查已有停止文件，收到停止请求后结束并回收辅助进程，进入已有 Android 服务组清理。取消期间不报告桌面就绪。正常退出、真实子进程失败与用户取消需要分别传递，真实失败仍保留原因，并在可继续执行时完成文件系统同步与 Linux 退出。

先完成线程局部入口的独立验证，再修改这条等待路径，避免同一次核心回归同时定位两种执行入口变化。后续用 Mac 自动化分别在系统服务启动及首帧等待阶段取消，检查停止事件、进程回收和 ext4。

### 实施边界

首帧辅助进程的等待改用 `waitpid(WNOHANG)`，交互启动同时检查已有停止文件；取消时结束并回收该子进程，将取消结果传回桌面启动和 Framework 主循环，由现有服务组清理处理退出。普通功能检查继续要求首帧辅助进程成功。

宿主的程序等待返回实际退出状态。普通回归仍显式检查成功；Android 服务检查失败时，停止输入和图形、向 `nce_lkl_run()` 返回失败，再执行已有只读重挂载、卸载和内核关机。结果继续报告失败。PID namespace 的 init 退出会结束该命名空间内的进程，此行为需要在实际辅助进程失败回归中确认，不能只靠宿主单测判断。

## 曾考虑的替代方案

- 延长 benchmark 时限：无法让阻塞等待响应已有停止请求。
- 忽略所有非零子进程状态：会丢失真实初始化失败的信息。
- 依赖宿主强制结束及后续磁盘修复：增加恢复步骤，无法满足可重复自动化的退出要求。

## 验证

1. 首帧等待阶段取消后，辅助进程和服务组结束，日志中没有新的桌面就绪事件。
2. 正常启动和真实辅助进程失败仍能区分；取消及可处理失败均完成磁盘同步和退出。
3. CLI/GCD 和真实 App 的启动、取消、再次启动检查成功；退出后的 ext4 只读检查返回 0。

### 当前实现与检查

`nce_wait_desktop_child()` 使用已有停止文件，每 100 ms 轮询子进程；返回实际 wait status，取消时回收子进程后返回 `-ECANCELED`，系统调用错误返回负 errno。桌面启动将取消传回 Framework 清理流程，在发出就绪事件前再检查停止文件。真实非零退出继续报告辅助程序状态。`run_program()` 将退出状态交给实际调用方，普通回归仍要求成功，Android 服务失败进入宿主清理并最终返回 1。

`scripts/test_desktop_wait.py` 编译实际桌面等待实现，使用真实子进程验证正常退出、非零退出、信号退出和取消回收，并在等待边界模拟 EINTR；同时检查取消与就绪事件顺序，九项检查成功。`scripts/test_desktop_stop.py` 在真实 App 的系统服务、首帧等待和正常运行阶段发送 SIGTERM，分别检查服务清理、ext4 和再次启动。`scripts/test_desktop_failure.py` 在独立生成的系统镜像中替换测试用 Java 辅助程序，让 ART 执行 `System.exit(7)`，检查 CLI/GCD 返回失败、上下文释放和磁盘卸载；检查成功后删除生成的测试磁盘。两项集成检查均已成功。完整桌面 CLI/GCD 各通过 219 次命名检查，数据持久化与正常退出成功。首次构建的输入检查发现验证期间源码变更，因此作废该次构建记录；源码固定后重新完成了两种入口的回归。

### 集成结果（2026-10-11）

Apple M5 Ultra / macOS 27.0 (26A428)，1 GiB/单 CPU，demand，nterp 开启，AOT、公共镜像与诊断关闭。真实 Mac App 分别在系统服务启动、首帧等待和桌面运行阶段停止，退出耗时为 1.200 / 1.461 / 2.911 秒；前两轮没有报告桌面就绪，首帧等待取消确认回收了辅助进程，三轮均完成服务清理及 ext4 只读检查，并复用同一数据盘连续启动。功能测试与构建、失败测试部分重叠，这些耗时只描述本次退出行为。

受控 Java 辅助程序在真正的 ART 中执行 `System.exit(7)`，Framework 报告辅助程序状态 `1792` 后退出。CLI/GCD 均最终返回 1，输出 `result: failed`，各自释放 568/568 个 NCE 上下文，数据盘完成只读重挂载和卸载，ext4 检查返回 0。两张独立生成的测试磁盘已清理；脚本可以从当前验证产物重建，原始日志与 DEX 保存在 `work/native-linux-nce/failure-checks/20261011-005622/`。

两端构建为 `0.24.0-Mac-20261011-005636` 和 `0.24.0-iOS-20261011-005625`，宿主生命周期、共享配置、内存采样、签名执行及包内资源检查成功。IPA 大小 485,041,454 字节，SHA-256 为 `b5fbc867a9879a4b486acce232dcd4d9922eeed89c0dd64dd62894405ee09606`；iPhone 执行待集成版本集中验证。完整配置、输入哈希、检查摘要与日志哈希见[退出检查结果](../../../../experiments/native-linux/results-macos-desktop-stop.json)。

### 复杂度审查

取消继续使用已有会话停止文件，没有第二套取消状态。等待函数由真实首帧辅助程序调用，测试使用相同实现；删除该函数会让取消再次等待子进程自行结束。宿主没有新增失败策略开关，各调用方按原有职责选择成功断言或将 Android 失败传给清理入口。测试用失败 DEX 只写入独立生成的镜像，生产二进制没有故障注入分支。真实 App 停止测试需要在指定阶段发送信号，失败测试需要替换 Java 辅助程序并接受非零退出；它们与普通性能矩阵的成功条件不同，保持两个独立脚本，复用现有 ext4 检查函数。

## 影响

Android 命令和服务注册也存在其他阻塞等待，需要按实际调用路径逐项检查。强制杀掉正在持锁的进程可能妨碍服务清理，取消顺序必须通过完整运行确认。
