# 决策记录: 缺页处理后的页表重试

状态: implemented

## 问题

公共 boot image 的可见窗口回归中，Clock 检查辅助进程在 `libart.so+0x3ab2bc` 的 `ImageSpace::PatchObjectVisitor::VisitClass` 写入对象时收到 SIGSEGV；CLI/GCD 两组成功。原始日志与输入哈希保存在 `work/native-linux-nce/processes/runnable-first-window-failure.json`。NCE 记录该地址的缺页返回值为 2，但此值可能来自 NCE 在查不到 PTE 时自行设置的 `VM_FAULT_SIGBUS`。原日志没有区分 Linux 原始返回值与后续转换，当前尚未确认崩溃原因。

检查固定 Linux 源码的 `mm/memory.c::wp_page_copy()`：复制期间 PTE 发生变化时，可以返回 0，让用户再次缺页。`nce_page_fault()` 在 `handle_mm_fault()` 成功但查不到 PTE 时直接报错，遗漏了这种重试。`nce_copy_user()` 同样依赖该函数恢复可读或可写 PTE，需要一起覆盖。

## 决策

保留 VMA 权限检查，Linux 返回真实故障时继续失败。返回成功但 PTE 尚未满足访问权限时，释放读锁后重新查询 VMA 并处理缺页；存在致命信号时结束重试。显式处理已经释放 mmap 锁的返回状态，不能再次解锁旧 VMA。诊断开启时记录重试次数和有限的原始返回值，正式性能配置不逐次输出。

用私有文件映射的写入与 `MADV_DONTNEED` 交错检查映射仍可用，并保留 COW、只读、PROT_NONE、取消映射和文件截断故障检查。真实桌面重跑若记录到缺页成功但 PTE 缺失的重试，可确认旧代码会对该次状态返回访问错误；先前那次崩溃仍按已有日志保留。

## 曾考虑的替代方案

- 只提高 Linux RAM：会改变压力条件，无法修正缺页返回状态的处理。
- 查不到 PTE 时直接返回成功：普通用户访问会再次触发缺页，但内核用户数据复制仍可能返回短复制。
- 固定次数后转成 SIGBUS：会把调度和回收时机变成新的访问失败条件，缺少依据。

### 验证

Mac 为 Apple M5 Ultra / macOS 27.0 (26A428)，Linux RAM 为 1 GiB，单 CPU、demand、nterp 开启。开启公共 boot image 与诊断的 CLI/GCD/可见窗口分别通过 219/219/220 次命名检查；同一核心关闭公共镜像和诊断的 GCD 通过 219 次。四轮都完成私有文件映射写入与 `MADV_DONTNEED` 交错、结束后私有/共享数据核对、再次丢弃后的内容恢复，以及文件截断后故障检查；已有 COW、只读、PROT_NONE、取消映射、桌面应用和持久数据检查继续成功。最后一次 `e2fsck -fn` 返回 0。实际输入、原始日志摘要与构建信息见[功能记录](../../../../experiments/native-linux/results-macos-runnable-functional.json)。

三轮开启诊断的最终 `fault_retries` 均为 1。当前日志级别没有导出重试的具体返回状态，因此暂时无法确认它们发生在 COW、回收还是终止阶段；先前公共镜像崩溃的原因仍未确认。`0.21.0` 的 Mac 与 iOS 包构建成功，Mac 宿主检查成功；iPhone 待集中验证。

复杂度审查：沿用现有缺页入口、mmap 锁和 PTE 查询，只增加重新查询所需的控制流与一个可关闭计数。固定重试次数缺少语义依据；独立重试队列会增加资源和生命周期，本次没有采用。

## 影响

VMA、PTE 和信号检查的顺序影响正确性。当前为单 CPU 内核；后续 SMP 仍需在页表锁和宿主映射更新之间建立同步。本次不增加多核。
