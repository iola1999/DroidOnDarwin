# 缺陷记录: 翻译器定时抢占后的指令状态

状态: implemented

## 问题

PTE 翻译变体扩大到 640 MiB 容量与 fork 检查后，2 ms 定时抢占在读取循环中出现 SIGSEGV。反汇编显示触发指令为 `ldrb w13, [x13, x10]`，失败地址为 `0x4000`；该指令同时使用 x13 保存地址与读取结果。同一客体文件改用指令计数抢占时，CLI/GCD 检查通过。前一阶段小型负载成功未覆盖这个边界，定时器变体的正确性结论限于当时负载。

## 原因

Unicorn 2.1.4 的 `tcg_gen_qemu_ld_i64()` 在内存读取后生成 `check_exit_request()`；`HELPER(check_exit_request)` 可从该处退出，`unicorn_fill_tlb()` 则会同步当前指令 PC。确定性回归在成功的 TLB 填充回调里请求停止，复现 PC 停留在读取指令、x0 已变成读取结果 41 的状态。恢复执行会再次使用这个 x0 作为地址。带地址回写的读取、成对读取和存储也未完成整条指令。相关上游位置见 [访存生成](https://github.com/unicorn-engine/unicorn/blob/2.1.4/qemu/tcg/tcg-op.c)、[退出处理](https://github.com/unicorn-engine/unicorn/blob/2.1.4/qemu/accel/tcg/tcg-runtime.c)和 [TLB 回调](https://github.com/unicorn-engine/unicorn/blob/2.1.4/qemu/softmmu/unicorn_vtlb.c)。

## 实现

[构建脚本](../../../../scripts/build_translation_engine.py)校验固定版本的源码压缩包并应用实验补丁。新入口 `nce_uc_emu_stop_at_tb()` 只写一个原子请求标记，由执行线程在下一次翻译块入口消费，再由该线程修改 CPU 的退出状态。正常 `uc_emu_stop()` 继续用于系统调用和错误回调。宿主互斥锁隔开定时器请求、寄存器操作和销毁。

早期补丁在异步线程同时设置停止类型与 CPU 退出标记。只改访存检查时，连续翻译块也跳过退出，生成代码等待信号的检查无法完成；给翻译块入口增加独立标记后，确定性回归和多轮集成通过，但随后一轮交替测试再次出现容量循环 SIGSEGV。代码中先读取停止类型、再读取 CPU 退出标记，两个读取之间可能收到异步请求。改为由执行线程独立处理退出状态，消除这个跨线程判断。失败经过记录于本节；该轮原始输出随对照重跑被覆盖。最终结果只采用当前实现重新运行的数据。

内核缺页仍直接退出引擎，不在 TLB 回调中执行 Linux 调度。该补丁当前只构建 ARM64 Mac 原型，iOS 执行内存与调度尚待适配。

## 验证范围

最小回归覆盖目标寄存器兼作地址的读取、带地址回写的访存，以及停止后的继续执行。旧入口必须能复现状态问题；新入口需通过回归及容量、COW、信号、运行时 ELF 的 CLI/GCD 检查。内核、翻译器依赖、补丁与客体均记录构建摘要，再进行性能对照。

## 验证结果

`python3 scripts/probe_translation_preemption.py` 对原版入口运行一轮，四项状态检查均复现失败；补丁入口连续 20 轮通过全部四项，并在停止后继续执行到 SVC。容量、COW、Linux 定时信号、运行时 ELF 和页切换的 32 轮交替 CLI/GCD 全部通过。原生 CLI/GCD 基础回归成功。该阶段未重跑完整 Android 桌面，iPhone 验证仍待后续集成。
