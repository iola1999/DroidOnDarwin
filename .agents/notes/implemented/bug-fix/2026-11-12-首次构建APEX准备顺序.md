# 决策记录: 首次构建 APEX 准备顺序

状态: implemented

## 问题

2026-11-12 恢复完整 Android 构建，`android_data()` 读取 `work/native-linux-nce/android/android36-modules/manifest.json` 时出现 `FileNotFoundError`。日志保存在 `work/project-audit-2026-11-12/offline-native-desktop-build-v2.log`。新目录尚未生成模块清单，负责准备 APEX 并生成接口头文件的 `android_service_interfaces()` 在 `android_data()` 后面才调用；已有缓存会掩盖这一顺序错误。

## 决策

把现有 `android_service_interfaces(out)` 调用移到 `android_data(out)` 之前，继续保留一次调用。固定 Android runtime 先完成提取与校验，随后准备对应 APEX 清单与接口，数据组装再读取模块清单。下载、版本和校验规则保持现有实现。

### 本机验证

从首次失败后仍无模块清单的目录继续执行完整构建：

```sh
NCE_MM_MODE=demand NCE_SYSTEM_SERVER_PROBE=1 python3 scripts/probe_lkl.py \
  --processes --graphics-angle work/angle-macos/prefix/lib
```

2026-11-12 在 Apple M5 Ultra、macOS 27.0 `26A428`、Xcode 27.1 `27A9275` 上成功。APEX 清单先生成，`android_data()` 取得对应模块并完成系统镜像。CLI/GCD 各完成 225 次检查，分别覆盖 153 个不同测试名；两轮都检查 Launcher、Clock、Files 的实际画面及正常退出。第二轮从同一 ext4 数据盘恢复时钟记录和 Keystore 密钥，两轮卸载后的文件系统状态均为 clean。iOS 核心交叉编译与用户态边界检查成功；本轮没有 iPhone 执行结果。

构建日志为 `work/project-audit-2026-11-12/offline-native-desktop-build-v3.log`。首次成功的报告和运行日志随后移入 `work/project-audit-2026-11-12/native-desktop-initial/`，供后续重新生成系统镜像时保留本轮结果；其中 `lkl-summary.json` 的 SHA-256 为 `aa98edb26676729e2266723c0c67a9888dbaa3a54c420856a24e6cd83da313f3`。报告记录 190 个源码输入、固定 LKL revision `d0f76a77e8c2ca68bd7d96190b8da09040eab072`，系统镜像 SHA-256 为 `7258dab13169f519703936a4a4fe0e9557b689296ddd2624b2c11732e3e94bba`。构建过程与其他本机工作并行，该轮仅用于功能与来源核对，不用于性能比较。

同轮系统镜像包含可选 APK 检查助手。上述原生运行未传入 APK 目录，未执行安装助手；Direct 安装、更新和重启结果由[APK 离线验证](../../proposed/testing/2026-11-12-通用APK离线验证.md)记录。

## 曾考虑的替代方案

- 手工执行 `prepare_android_modules.py` 后继续：只能补齐当前目录，下次首次构建仍会失败。
- 在 `android_data()` 增加第二次准备调用：可以生成清单，但会重复校验全部模块；调整已有调用顺序即可满足依赖。

## 影响

首次构建仍需下载固定 SDK 归档并校验内容。生成服务接口的时点提前，后续构建发生错误后会保留这些可复用产物；文件归属及清理规则保持不变。

复杂度审查确认，依赖顺序由现有单次调用表达，没有新增准备状态或重复下载入口。该修复覆盖清单尚未生成的首次构建；旧的不带 `--processes` 的 LKL 探针故障继续单独保留。
