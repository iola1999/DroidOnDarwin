# 决策记录: LKL 启动格式处理器生命周期

状态: implemented

## 问题

固定 LKL `d0f76a77e8c2ca68bd7d96190b8da09040eab072` 在 `arch/lkl/kernel/setup.c:fs_setup` 创建空的 0700 `/init` 并注册 `lkl_run_init_binfmt`。首次执行该路径后，处理器调用 `begin_new_exec` 和 `syscalls_init`，唤醒 `init_sem`，随后通过宿主 `thread_exit` 结束线程。`lkl_start_kernel` 在收到唤醒后释放 `init_sem`，格式处理器继续留在全局注册列表中。

该处理器只检查执行路径为 `/init`。后续无效 ELF 经普通处理器返回 `ENOEXEC`，仍可进入同一启动处理器，重复创建 host0/TLS 状态并访问已经释放的 `init_sem`。此轮根据实际生成源码确认调用路径；旧实现的异常重入未实跑。原 HyperOS 根链接准备与 `/system/bin/init selinux_setup` 的已有观察见[原盘记录](../../proposed/architecture/2026-11-12-HyperOS原始init的4KiB分区与启动观察.md)。

## 决策

沿用当前离线开发授权。`syscalls_init` 成功后、`sem_up(init_sem)` 前调用 `unregister_binfmt(&lkl_run_init_binfmt)`，使处理器只参与首次启动。`begin_new_exec` 失败或初始化尚未完成的路径保留原注册状态；初始化失败仍按现有逻辑 panic。普通 ELF 继续由 Linux `elf_format` 装载。

`fs/exec.c:search_binary_handler` 在调用 `load_binary` 前释放 `binfmt_lock` 的读锁，注销函数取得写锁后仅删除列表节点。启动 binfmt 为静态对象，`mm->binfmt` 中已有引用保持有效；当前 `setup.o` 为内建对象，生成配置关闭 `CONFIG_MODULES`。宿主回调调用 `pthread_exit`，执行器不会继续遍历已删除的列表节点。即使回调返回，`begin_new_exec` 设置的 `point_of_no_return` 和成功返回值也会结束遍历。独立只读审阅已核对这几项条件及 halt 路径。

补丁放入现有 `scripts/lkl_nce_patch.py`，生成的 `arch/lkl/kernel/setup.c` 加入 translation 内核构建输入摘要。回归放入 musl/Bionic 共用的 `userspace/file-tests.c`：创建独立的空 `/init` 和截断 ELF，各次执行必须返回 `ENOEXEC`；随后将 `/init` 链接到 `/bin/sh`，确认有效 ELF 正常退出。测试关闭可写 fd 后才执行，并先移除首次启动的目录项，使原 executable inode 引用不影响新测试文件。

### 复杂度审查

真实使用方为所有 LKL 启动入口和 Linux 后续 exec。注册列表已经记录处理器是否可被选择，注销后无需新增状态标志或 halt 清理。移除注销调用会恢复后续无效 `/init` 的启动处理行为；移除回归则无法检查普通格式错误返回和同一路径有效 ELF 执行。生成源码摘要用于区分实际参与构建的启动实现，源码补丁摘要继续参与缓存失效。

### 实施偏离

Direct core 此轮执行 musl，提案中的两页 Bionic 覆盖改为明确记录 16 KiB 原生 musl/Bionic 与 4 KiB Bionic 未验证。主线已包含 `185893b` 的 mmap ASLR，接收 HyperOS 固定阶段时复用该实现，未重复合入 `828d4eb` 的整份组合；独有的历史布局读取兼容继续保留。该兼容允许读取旧 64 GiB 报告，新正式 sparse 默认仍为 512 GiB。

## 曾考虑的替代方案

按 `is_running` 拒绝重复调用：该值在 halt 后清零，不能完整表达一次性启动处理器的生命周期。另加 initialized 或 registered 标志：重复表示注册列表中的状态，需要额外更新条件。更改启动路径：会影响根文件准备与调用方，并继续保留一次性处理器的注册问题。清除 `mm->binfmt`：静态对象仍然有效，当前缺少清除该引用的必要条件。

## 影响

该改动涉及首次 Linux 启动与所有后续 exec，CLI/GCD 和两种页大小的已述范围完成本机验证。正常 ELF 与启动回调共用 `/init` 路径，回归使用重新创建的 inode，并关闭写入 fd。iOS 编译只检查构建，设备授权、资源预算、完整系统启动与持续性能继续按[离线目标](../process/2026-11-12-离线开发目标与持续推送.md)验收。此次完成一次性 bootstrap 生命周期修复；HyperOS EROFS 文件解压、SDK36 原 vendor 完整启动、first-stage 与通用 APK 后续场景继续独立推进。
