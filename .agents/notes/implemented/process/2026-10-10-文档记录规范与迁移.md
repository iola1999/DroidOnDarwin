# 决策记录: 文档记录规范与迁移

状态: implemented

## 问题

项目文档以实验与阶段进展为主，长期决定分散在主会话和多份记录中。用户于 2026-10-10 要求参考 etf-watch，对所有非平凡变更、提案与缺陷修复建立记录约束，并迁移已有文档。

## 决策

采用 etf-watch 的 `.agents/notes/{生命周期}/{类别}/yyyy-mm-dd-主题.md`。生命周期为 proposed、implemented、rejected；类别为 feature、bug-fix、simplification、architecture、process、testing。固定文件头和章节见[改动记录约定](../../README.md)，根目录 [AGENTS.md](../../../../AGENTS.md) 作为协作入口。

已有 22 份文档迁入该结构。按原文保留实现、实验、日志、命令、版本、数值和限制；为每份记录补充问题、适用范围、已知备选与影响。上游设计和早期阶段明确注明历史范围。尚在实施的真实桌面位于 proposed；原有应用兼容层设计依据用户的当前范围归入 rejected，已发生的检查结果仍按历史记录保留。

轮次工作记录拆为当前摘要和[QEMU 与早期 NCE 实验记录](../testing/2026-10-07-QEMU与早期NCE实验记录.md)，实验正文完整迁入后者。根目录及组件 README 保留入口，结构化结果继续位于 `experiments/`。

补录[主会话协作决定](2026-10-07-协作与阶段交付约定.md)、[原生执行路线](../architecture/2026-10-08-转向原生Linux与NCE.md)、[已修复故障](../bug-fix/2026-10-09-JIT与线程停顿修复.md)和[性能风险提案](../../proposed/architecture/2026-10-10-HyperOS性能风险与验证.md)。主会话用户选择的 A/B/C 范围已补入桌面提案。会话来源带日期，历史截止时间与后续有效决定分别记录。

### 必要性与结构审查

现有阶段正文继续持有详细实现和测量；新增决定记录解释范围与选择，使用链接引用具体结果。相同决策后续直接更新原记录。目录树提供分类，轮次记录提供当前摘要，使用一份记录约定维护格式。没有新增文档生成器、配置文件或运行时组件。

### 验证

交付前检查记录文件头、状态与目录、必需章节、相对链接和原有正文迁移范围，并检查 Git 差异。没有运行构建、设备测试或修改运行代码。本次变更保持未提交，供与主会话的当前工作分别审阅。

## 曾考虑的替代方案

继续把决定只写在对话与实验日志中，会使后续难以确认现行范围和选择原因，用户要求写入仓库。把同一份正文复制到多个目录会增加维护量，因此每份记录只保存一次，通过相对链接引用。增加新的生命周期和分类会偏离用户要求，采用 etf-watch 已有约定。

## 影响

后续非平凡变更需要与记录同步提交，提案和失败也要留下可复查的原因与验收条件。文档迁移本身没有增加产品功能；完整桌面与 HyperOS 性能仍按各自阶段验证。
