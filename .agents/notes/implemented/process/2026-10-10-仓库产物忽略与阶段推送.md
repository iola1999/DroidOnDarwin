# 决策记录: 仓库产物忽略与阶段推送

状态: implemented

## 问题

2026-10-10 用户要求将整个仓库的变更提交并推送，同时配置应忽略的文件。检查发现 `work/` 和 `outputs/` 仅在本机 `.git/info/exclude` 中排除，克隆仓库无法继承该规则。当前工作区包含桌面开发、格式工具、测试与相关文档，完整桌面验收仍由主会话继续推进。

## 决策

在根目录 `.gitignore` 中记录 `/work/` 和 `/outputs/`，涵盖现有下载、系统镜像、原始日志、构建缓存和临时打包目录。Python 缓存规则覆盖各目录下的 `__pycache__`、字节码与 pytest 缓存；补充 Xcode 用户状态、归档目录及 SwiftFormat 缓存。现有 build、第三方构建目录和 IPA 忽略规则继续使用。

保留 `experiments/native-linux/results-*.json` 中的结构化结果、源码、构建脚本、测试、配置和决策记录。现有 StikJIT Framework 及应用图标属于仓库已有依赖和资源，继续按现有方式跟踪；`cacert.pem` 是应用使用的 CA 证书集合。

按用户授权提交当前开发状态，推送至 `origin` 的 `codex/hyperos-qemu-validation` 分支，包含此前尚未推送的本地提交。提交前沿用 C 系列与 Swift 格式 Hook，运行相关脚本测试和语法检查。阶段提交保留文档中尚未完成的桌面、应用及设备验收状态。

### 本次检查

`python3 scripts/test_precommit.py -v` 的 12 项测试和 `python3 scripts/test_nce_userspace.py -v` 的 21 项测试通过。变更中的 8 个 Python 文件通过语法解析，16 个 JSON 文件解析成功；20 个变更文档中的本地链接均可找到目标。`git check-ignore -v` 确认工作目录、输出目录、Python 缓存、Xcode 用户状态和格式缓存由根目录规则排除，结构化设备结果与 CA 证书集合继续保留。提交范围的常见私钥与访问令牌格式检查未发现匹配，`git diff --check` 通过。完整 Android 回归和本次阶段推送分别记录，测试结果不扩大桌面验收范围。

## 曾考虑的替代方案

- 继续只使用 `.git/info/exclude`：无法让其他克隆获得相同产物规则，因此改为提交仓库规则。
- 忽略所有 JSON 或二进制扩展名：会隐藏需要保留的结构化测试结果和已有依赖，采用实际产物目录与明确缓存类型。
- 等待完整桌面验收后再推送：用户本次要求保存整个工作区进展，当前功能限制随源码一起记录。

## 影响

后续克隆共享相同的产物忽略规则。原始镜像、IPA 和大日志继续保存在本机，远端保存实现与可供参考的结构化结果。此次推送保存当前开发阶段，正式交付条件保持原有约定。
