# 决策记录: C 代码格式化与文档段落约定

状态: implemented

## 问题

项目 C 代码的缩进、控制流和语句排版不统一。部分文档按行宽拆开自然段，阅读源码时会出现不必要的断句。用户于 2026-10-10 要求参考 `/Users/fan/project/embedded/radio-intercom` 引入格式化工具，并在开发约定中说明文件拆分与换行原则。

## 决策

沿用参考项目的 clang-format、根目录配置与 Shell 命令入口。当前 Mac 已安装 clang-format 22.1.7。项目使用四空格缩进，保留现有 C 代码常用的函数大括号和指针声明习惯；控制流和普通语句按结构展开。`ColumnLimit: 0`，注释与字符串保持原有分行，具体参数见 [.clang-format](../../../../.clang-format)。包含顺序和 C++ `using` 声明顺序保持原样；现有声明宏列入 `StatementMacros`，使连续宏调用分别排版，重复格式化保持相同结果。

[scripts/format.sh](../../../../scripts/format.sh) 默认处理 Git 中已跟踪和未忽略的新文件，支持 C、C++、Objective-C 及对应头文件。`--check` 只检查，末尾可指定文件或目录。缺少工具或检查失败时返回非零状态；文件名通过 NUL 分隔收集。第三方代码、Framework 头文件、自动生成的图形协议及上游补丁由 [.clang-format-ignore](../../../../.clang-format-ignore) 排除。

Markdown 一个自然段连续书写，编辑器负责显示折行。标题、列表、表格、代码块和语义分段继续保留。代码的换行以控制流、表达式和参数关系的可读性为准，具体约定写入 [AGENTS.md](../../../../AGENTS.md)及[记录格式](../../README.md)。

文件按职责组织，优先拆开可以独立维护和测试的部分；只有必要耦合或外部接口限制确实妨碍拆分时才保留大文件并说明原因。判断依据是维护成本，本次只增加开发约定，未改动模块职责。

### 并行开发范围

主会话仍在修改 NCE 调度、Framework 和相关回归。本轮格式化保留其正在修改的源文件，由主会话完成对应格式检查；其余自有代码进行机械格式化。截图中的文档只合并自然段，保留当时内容和测试状态。

本轮保留的文件为 [lkl-nce-signal.c](../../../../experiments/native-linux/lkl-nce-signal.c)、[lkl-process-host.c](../../../../experiments/native-linux/lkl-process-host.c)、[framework-test.cpp](../../../../experiments/native-linux/userspace/framework-test.cpp) 和 [host-poll-test.c](../../../../experiments/native-linux/userspace/host-poll-test.c)。这些文件继续适用同一格式配置，无需新增排除规则。

### 验证

2026-10-10 使用 clang-format 22.1.7 完成 237 个文件的格式检查，其中 207 个文件发生排版变化，30 个文件原已符合配置。7 个第三方、生成或上游补丁文件由排除配置保留。每次写入前核对文件内容未被并行修改，并用 Clang 原始词法输出比较格式化前后非注释、非空白单元；比较通过。重复格式化检查通过。

首轮检查发现 clang-format 默认重排 `using` 声明，写入前的词法比较阻止了该文件的更改；关闭重排后通过。连续宏调用最初需要反复格式化才会展开，添加现有声明宏后一次格式化即可得到稳定结果。修正后的已处理范围再次检查通过。

`bash -n scripts/format.sh` 与 `git diff --check` 通过；指定文件的检查成功返回 0，未知参数和空文件范围返回 2，缺少 clang-format 返回 1。全仓 `--check` 当前仅报告 `lkl-process-host.c` 与 `framework-test.cpp`，均属于上述主会话文件。处理清单与前后哈希保存在 `work/formatting/2026-10-10.json`，只存摘要。

README、轮次工作记录及截图中的缺陷记录共合并 15 个自然段，核对去除空白后的内容保持一致。相关文档检查章节、状态和本地链接。本轮验证范围为格式、词法单元和工具行为，未执行 Android 或真机回归。构建源码哈希会随排版改变，已有产物的结果仍对应原构建；后续构建按新源码重新生成记录。

### 复杂度审查

格式规则交给现成 clang-format，脚本只选择 Git 文件并转发检查或写入模式。本轮不引入 Node/Python 包管理项目、Git hook 或自定义代码排版器；需要调整排版时维护一份配置。文件拆分按职责评估，避免新增只负责转发的接口。
