# 决策记录: 恢复离线图形构建

状态: implemented

## 问题

本轮工作区没有旧 ANGLE / gfxstream 产物，恢复真实 Android 桌面需要重新构建图形库。`build_angle_ios.sh` 将 WebKit 源码与归档放在 `third_party/gpu/`、日志放在 `build/logs/`，Xcode 构建缓存未显式指定路径，与当前产物放入 `work/` 的约定不一致。

## 决策

将 ANGLE 的下载目录、原始构建日志和 Xcode DerivedData 明确放入项目 `work/`，保留固定 WebKit 提交、现有构建步骤和交付库的位置。Mac 库仍输出 `work/angle-macos/prefix/`，iOS 库仍使用现有打包器消费的 `build/ios-arm64/sysroot/`。先构建 Mac ANGLE 与 `macos-ios-api` gfxstream，后续按同一固定输入生成 iOS 库。

### 本机构建

2026-11-12 在 Apple M5 Ultra、macOS 27.0（26A428）、Xcode 27.1（27A9275）上依次完成以下构建，四个命令均返回 0。Mac 使用 SDK 27.0，iOS 使用 SDK 27.1。

```sh
bash scripts/build_angle_ios.sh macosx
python3 scripts/build_gfxstream.py --platform macos-ios-api
bash scripts/build_angle_ios.sh iphoneos
python3 scripts/build_gfxstream.py --platform ios
```

ANGLE 固定于 WebKit 提交 `2edaa071178a43a44dfaa4c37716247c43642c66`，gfxstream 固定于 `07ee40efb0e7037a9a9b7fe59071e7c4997e7cbe`。四个 manifest 中的脚本、补丁、宿主源文件及产物摘要均重新计算并核对成功。

### 复杂度审查

实际使用方为现有 Mac/iOS 构建与打包脚本。本轮只更改下载、日志和缓存目录，没有增加路径兼容层或运行时选项；交付库位置继续满足现有调用方。保留旧路径会使新产物分散到多个目录，符号链接又会增加路径关系，因此直接更改脚本内的路径。

## 曾考虑的替代方案

继续用旧脚本的源码和默认缓存目录：无法统一管理本轮下载和缓存。建立目录符号链接：额外增加实际路径与脚本路径之间的关系，当前工作区没有旧下载目录，直接修改两处路径并指定 DerivedData 更清楚。

## 影响

已存在其他目录的产物不由本次脚本迁移或清理；首次使用新路径需要重新下载和编译。库接口和运行行为继续由后续桌面验证确认。
