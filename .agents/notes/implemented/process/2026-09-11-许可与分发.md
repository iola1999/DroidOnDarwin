# 决策记录: 许可与分发

状态: implemented

## 问题

记录当前随包组件的来源、许可文本及分发检查入口。

## 决策

项目的 GPL-2.0-or-later 源文件保留 SPDX 标识，GPL v2 全文位于根目录 [LICENSE](../../../../LICENSE)。复用代码及参考关系集中记录在[开源致谢](../../../../ACKNOWLEDGEMENTS.md)，原有版权与许可声明按来源保留。

`scripts/package_notices.py` 收集 Linux/LKL、Android、musl、dash、LLVM、gfxstream、ANGLE 等组件的许可，按实际源码路径写入 `ThirdPartyNotices.txt`，并复制 Android 的 `NOTICE.xml.gz`。iOS 包额外收录 StikJIT 的 MPL-2.0 和其内部 idevice 的 MIT 许可。必要许可文件缺失时打包失败。

两端设置中的开源致谢页可阅读来源说明及导出许可文件；Mac 关于窗口使用同一页面。StikJIT 框架的版本、来源归档摘要及公开对应源码链接保存在致谢中。修改第三方源码时，需要同步保留修改、来源版本和适用许可；分发应用时应同时提供适用许可要求的对应源码与构建材料。

## 曾考虑的替代方案

仅保留仓库中的许可文本会让应用使用者难以查阅，因此两端应用同时提供来源说明和随包许可导出。具体旧依赖组合的评估保存在 Git 历史中。

## 影响

macOS 当前为本机 ad-hoc 签名构建；iOS 由侧载工具重签安装。当前组件组合和源码来源以打包清单、文件 SPDX 及各依赖许可为准。正式分发前需要按实际发布产物检查对应源码、第三方声明、签名与安装条件。
