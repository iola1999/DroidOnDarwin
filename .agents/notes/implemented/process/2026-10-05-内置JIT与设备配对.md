# 决策记录: 内置 JIT 与设备配对

状态: implemented

## 问题

记录 DroidOnDarwin 当前 iPhone 应用的 JIT 连接、配对文件和签名要求。

## 决策

设置中的「JIT 连接」提供内置 JIT 助手和 StikDebug 两种方式。内置方式需要导入这台 iPhone 的配对文件，并保持 LocalDevVPN 已连接。配对文件可按 [StikDebug 指南](https://github.com/StikDebug/StikDebug-Guide/blob/main/pairing_file.md)准备。文件由 `JITPairingFileStore` 保存于应用的 `Documents/StikJIT/pairingFile.plist`，属于设备敏感数据。

启动时，内置助手加载 Developer Disk Image 并通过 StikJIT 附加到主进程，执行随包 `jit.js`。主进程先准备需要执行的地址区间，再分离调试器并检查执行权限。选择 StikDebug 时，启动流程打开外部应用，用户启用 JIT 后返回 DroidOnDarwin。

### 扩展与签名

`JITHelper.appex` 是主应用中的独立进程，使用 `com.apple.ar.viewer` 扩展点及 `JITHelperHandler` 入口。主应用通过 NSExtension 接口启动扩展，并传递 PID、配对文件与脚本；调试器无法同步调试自身，因此需要独立进程。

主应用从 `PlugIns/JITHelper.appex/Info.plist` 读取实际扩展包标识，支持侧载工具在重签时调整包名。应用、扩展和 `StikJIT.framework` 需要一起签名；主应用需要 `get-task-allow`。打包时的 ad-hoc 签名用于校验包完整性，安装由侧载工具重新签名。

默认主应用包标识为 `app.droidondarwin.ios`，扩展为 `app.droidondarwin.ios.JITHelper`，URL scheme 为 `droidondarwin`。版本与资源由 `scripts/package_native_linux_ios.py` 生成。

### 来源与验证边界

JIT 双映射、断点协议、扩展及通信代码复用与参考 Husk、AetherPS4-iOS、StikJIT 和 LiveContainer，具体关系见[开源致谢](../../../../ACKNOWLEDGEMENTS.md)。设备执行权限及外部调试器交互需要真机验证。Node 协议检查、两端构建与宿主执行检查分别记录，当前包的实际验证结果见[项目整理记录](../simplification/2026-10-10-DroidOnDarwin命名与项目整理.md)。

## 曾考虑的替代方案

上游曾使用以应用标识命名的 ExtensionKit 扩展点，侧载改名后无法找到扩展。现有实现沿用可在安装后读取标识的 NSExtension 方式。此处按当前实现整理操作说明，历史修改见 Git 记录。

## 影响

iPhone 首次运行需要完成 JIT 连接设置；重新签名必须保留扩展与框架。配对文件、DDI 缓存及应用数据位于新包标识对应的应用容器。
