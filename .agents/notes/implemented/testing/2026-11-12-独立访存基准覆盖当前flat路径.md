# 决策记录: 独立访存基准覆盖当前 flat 路径

状态: implemented

## 问题

当前独立基准的 `Probe::memory()` 只提供 `map_page` 回调和 4 KiB 页配置，没有传入 `page_table` 或 `flat_pages`。其整数、数组读写和原子循环可以比较原生与缓存访存执行，尚未覆盖当前产品使用的 16 KiB `flat` 路径。旧微基准结果因此无法直接说明当前平坦表访存的成本。

用户已允许离线架构实验。本轮在 Mac 上建立当前访存路径的独立对照，覆盖短功能检查与正式性能测量。完整性能轮次由主会话串行执行，没有进行 iPhone 测试。

## 决策

在现有 [direct/benchmark.cpp](../../../../experiments/native-linux/direct/benchmark.cpp) 增加局部测试数据和执行入口，复用 [translation/kernels.S](../../../../experiments/native-linux/translation/kernels.S) 的整数与数组访存汇编、`NceDirectMemory` 和已有平坦表布局。新入口比较原生、缓存访存和平坦表访存，三者使用相同的 16 KiB 数据页、64 KiB 数组和初始内容。原有 `tests`、`bench`、`all` 入口保持行为。

Direct 两组固定使用 128 MiB 代码缓存、256 项数据和跳转缓存、原生独占访问与跨页处理；关闭选择性写检查、代码检查复用、跳转 epoch、跳转保留、访存合并和 SIMD 实验。固定代码通过测试自身的版本计数提供代码身份。该版本计数只用于测试中同步修改的代码，未模拟产品的物理代码页写入跟踪。平坦表组为两个地址空间分别提供一张 4 MiB 表，缓存组通过相同数据映射回调取页。

增加 `memory-check` 与 `memory-bench` 模式。前者以少量迭代检查三种路径、同一客体地址的私有数据隔离、共享页可见性和重复切换，不输出执行耗时；后者记录一次预热后的三个计时样本，核对返回值和完整数组，并记录实际配置、代码和依赖摘要。CLI 与 GCD 均覆盖。新模式拒绝其未采用的旧入口调优参数非默认值，防止请求参数与实际配置不一致。

### 测量范围

每个 backend 与入口组合使用独立进程，三个计时样本在该进程内依次执行。CLI 顺序为 native、cached、flat，GCD 顺序反转。整数负载每个样本执行 64,000,000 次循环；数组访存负载每个样本执行 32,000,000 次循环，每次读取并写入一个 64 位元素，在 64 KiB 数组内循环。整数预热为 64 次循环；访存预热为 8192 次循环，遍历完整数组。

墙钟和线程 CPU 计时只包含地址空间 0 的执行调用。Direct 每 1,000,000 条指令的预算退出及再次进入计入执行耗时；初始化、地址表建立、空间切换检查和原生结果核对位于计时之外。Direct 计数自测试结构建立以来累计，包含功能检查和预热。

footprint 以阶段采样，覆盖初始化、预热、三次执行和原生结果核对。阶段均值为采样值的算术平均，峰值为采样峰值，末次值来自该阶段最后一次采样。其范围与墙钟、线程 CPU 的执行计时不同。报告另存 RSS 和进程生命周期 RSS 峰值。

### 实现偏离与首轮失败

首轮将原子循环也纳入新对照。`cached` 开启原生独占访问后，在首次 `STLXR` 的写映射填充中返回宿主，随后在下一次 `LDAXR` 返回 `NCE_DIRECT_UNSUPPORTED`，客体 PC 为 `0x10004`。这个返回符合执行器的独占监视约定；继续执行需要回退。原始失败与诊断位于 `work/native-linux-nce/direct-memory-check/`。

新对照改为整数与普通数组访存，空间切换检查也使用同一普通访存函数。Direct 两组保留原生独占访问配置；原有 `bench` 的原子负载与独占语义测试继续保留。新增对照没有测量原子性能，也没有加入回退执行。

### 功能与回归结果

Apple M5 Ultra、macOS 27.0（26A428），使用 Clang `-O2` 与 `dual` 代码内存。以下短检查的三种路径均通过 CLI/GCD；六次运行分别检查空间切换、整数结果和完整数组，未采集执行耗时。结果与源码、依赖和二进制摘要位于 `work/native-linux-nce/direct-memory-check-v2/summary.json`。

```sh
python3 scripts/probe_direct_execution.py --mode memory-check --code-memory dual --output work/native-linux-nce/direct-memory-check-v2
python3 scripts/test_direct_memory_benchmark.py --report work/native-linux-nce/direct-memory-check-v2/summary.json
```

结果验证器接受上述六次运行，并拒绝从实际结果构造的 72 个错误记录，覆盖模式、CLI/GCD、采样间隔、缺少或重复的负载、页粒度、迭代数、检查类型、短检查混入计时字段、缺少空间切换检查与失败行。`memory-check` 配合 `--simd-math 1` 在构建前以退出码 2 拒绝。Python 语法、相关 C 系列文件格式和差异空白检查成功。

旧 `tests` 入口使用相同双映射代码内存完成回归，CLI/GCD 均以退出码 0 完成，各有 89 条成功测试记录，包含权限、代码替换、原子访问和并行语义。结果位于 `work/native-linux-nce/direct-regression-20261112/summary.json`，命令如下。

```sh
python3 scripts/probe_direct_execution.py --mode tests --code-memory dual --memory-interval-ms 0 --output work/native-linux-nce/direct-regression-20261112
```

### 正式性能结果

2026-11-12 在同一台 Apple M5 Ultra、macOS 27.0（26A428）运行。编译参数为 `-std=c++20 -O2 -g -Wall -Wextra -Werror -DNCE_DIRECT_DUAL_MAP`，代码内存为 `dual`，footprint 采样间隔为 100 ms。主会话等待并行构建结束后串行执行以下命令；该轮没有记录温度、功耗或 CPU 频率。基线提交为 `35d3d7f39d2cda17e46e52d3ae9d5b5db28ae3ef`，基准实现尚未提交，实际运行源码以结果中的 SHA-256 为准。

```sh
python3 scripts/probe_direct_execution.py --mode memory-bench --code-memory dual --memory-interval-ms 100 --output work/native-linux-nce/direct-memory-bench-20261112
```

### 复杂度审查

新增局部结构只由独立访存入口使用。两份私有数据和两张平坦表用于检查同 VA 隔离与空间切换；共享页用于检查跨空间修改可见。移除第二份状态会失去这两个边界。代码与映射版本分别对应代码替换和空间切换，不能共用后忽略其中一类变化。基准复用既有编译、执行、CLI/GCD、内存采样和结果报告，没有新增运行时接口或产品配置。结果验证的负例使用实际短检查报告，修改记录字段后确认拒绝，不再次启动执行器。

## 曾考虑的替代方案

- 直接采用旧独立性能结果：旧入口没有调用平坦表访存，缺少对应关系。
- 先恢复完整 Android 后再比较：系统构建与桌面启动增加准备时间，也会引入与普通访存无关的变化。本轮先隔离执行成本，系统负载仍需后续验证。
- 同时加入只读别名 `view`：该配置属于历史候选，当前先比较已采用的平坦表与原缓存路径。
- 抽取通用页表测试框架：本轮只需两份小型地址表和已知 RAM 布局，局部测试结构可以表达全部所有权与生命周期。

## 影响

当前 flat 普通访存仍有可测量的成本。继续增加指令覆盖率对减少回退可能有帮助；本轮结果没有验证它能减少已在 Direct 内执行的普通访存成本。下一步真实 Android 调查应先恢复固定的 Settings 交互，结合现有[线程采样分析](../../../../scripts/analyze_nce_profile.py)和[交互帧分析](../../../../scripts/analyze_interaction_profile.py)，分别记录执行器、内核、图形、IPC 与等待所占时间，再决定优化对象。若 Direct 占主要 CPU 时间，应检查最常执行的代码块中的访存、间接跳转、代码检查和回退退出，并把这些次数与 CPU 时间及交互耗时一同比较。

本轮只对地址空间切换做功能检查。真实多 mm 的建表、切换和更新仍需复用 [mm-bench.c](../../../../experiments/native-linux/userspace/mm-bench.c) 的进程与线程对照，并记录 2～16 MiB 数据规模、共享比例和页面访问方式，结合实际 flat 表更新次数测量。该负载在计时前完成子进程私有页 COW，计时范围包含 pipe 往返、调度和页面访问；解释结果需要保留这些条件。

该独立基准没有运行 Linux 调度、Binder、页表更新、缺页、Unicorn 回退或 Android，也没有测量 iPhone。测试的两个地址空间共享宿主 RAM 存储，通过各自的表访问不同私有页；这里没有建立 Linux mm 或执行 fork/COW。每百万条指令的预算退出与产品定时抢占不同。结果只用于比较固定代码中的普通计算和访存成本，不能换算 Android 整体耗时、整机帧率、功耗或持续热状态。
