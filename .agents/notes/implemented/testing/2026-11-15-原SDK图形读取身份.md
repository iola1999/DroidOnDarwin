# 决策记录: 原 SDK 图形读取身份

状态: implemented

## 问题

原 SDK 后期 syscall 采样包含 524288-byte read 的 EAGAIN。整组负结果计数和末次参数分别记录，末次 errno 无法确定全部历史调用的来源。固定源码有 `QemuPipeStream::commitBufferAndReadFully` 的立即重试路径，修复前需要核对实际任务、FD 和执行地址。

## 决策

独立 v13 在 syscall `63`、请求 `524288 bytes`、返回 `-11` 且 trace index 至少 `65536` 后，每个 original 入口采集一次当前任务身份。诊断保存完整 800-byte 寄存器，最多 40 次临时 syscall、四次清理调用预算和一页映射；每次 syscall/copy 和整次采样分别恢复原状态。查询失败、截断、原 errno、关闭与解除映射分别记录。

在主工作区的 `work/sdk-plain-validation-v1/read-identity-original-init-v13-180s` 目录运行 `python3 -B run.py --build build-03`，原六入口、SDK 图形盘和 v12 内核继续使用冻结输入。两个 original 各观察 180 秒，原 Binder/SIGQUIT 条件保持 450 秒。准备失败、最终编译、输入和实际运行来源见[阶段报告](../../../../experiments/native-linux/results-sdk-read-identity-init-20261115.json)及[独立结束审阅](../../../../../../../../work/v13-read-identity-result-review-v1/final-summary.json)。

六入口观察、实际退出 0、进程组回收、同盘恢复和原 SQLite 检查成功，3457 项输入保持。两个 original 停止后的 data 需要恢复，两项 recovery 后 data/metadata 均为 clean。完整 boot、原 ashmem original 检查为 failed，Binder/SIGQUIT 保留 incomplete，wrapper 返回 1。总耗时 406.31362462509423 秒包含诊断与恢复，未用于性能比较。

CLI 为 PID255/TID342、trace index12567840；GCD 为 PID245/TID332、trace index9413605。两项均取得 `/system/bin/surfaceflinger`、原 FD `10`、dup FD `12`、路径 `/dev/goldfish_pipe_dprctd` 和 `F_GETFL=133122/0x20802`，含 `O_NONBLOCK`。每入口 20 次诊断 syscall、三次 close 和 16 KiB munmap 成功，全部寄存器恢复成功。PC 为 libc `read+8`、ELF vaddr/file offset `0xd2b08`；LR 为 `/vendor/lib64/egl/libEGL_emulation.so` 的 `qemu_pipe_read+0x14`、偏移 `0x1a344`。

两份 SDK manifest 对应 `arm64-v8a-ps16k-36_r07.zip`，archive SHA1 为 `dda632745023567113d9954101709c6526a3c250`。原 libc SHA256 为 `d3f8599b8b3f00101a31f94ac170ceb5875ee8446c201cb18382b2e02df84301`，原 EGL SHA256 为 `ee7addbb4d7830bec69023e55906accea85036f765ad5eb104df96fc83edc54f`，与保留来源和 ELF 可执行段核对成功。动态 FP 链、进程 starttime、PID namespace、原 FD_CLOEXEC 和客体全部映射文件字节未采集；该结果只描述本次两项 read。

## 曾考虑的替代方案

根据日志末次 errno 解释整组计数会丢失各次调用的差异。宿主后台读取所有任务或长期缓存身份需要额外处理 Linux 调度和地址映射的生命周期，本次只在当前执行任务中进行一次查询。直接修改全部设备 read 的等待行为会改变其他非阻塞使用方的契约，实际叶函数与上层方法继续分别验收。

## 影响

本阶段交付读取身份结果及实际失败，图形等待实现、完整开机、桌面、通用原始签名 APK、HyperOS 和持续性能继续开发。iOS 编译只覆盖本机语法与对象构建，设备 JIT、资源与热状态待真机验证。v13 清理前先独立保存后续 SDK 所需输入，清理结果另行更新。
