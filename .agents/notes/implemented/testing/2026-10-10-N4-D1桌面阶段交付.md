# 决策记录: N4-D1 桌面阶段交付

状态: implemented

## 问题

用户选择方案 A：在 iPhone 内独立运行真实 Android 桌面，支持触摸与系统导航、两个应用启动和切换，以及应用数据跨宿主重启保留。此前提前包已在 iPhone 17 / iOS 27.2 启动，用户反馈滑动还算流畅；日志同时暴露时钟依赖和 Wi-Fi 设置页异常。

## 决策

原始 IPA 已清理。复现该构建需检出对应历史提交，按本文记录的依赖、镜像和配置重新打包；当前构建入口见根目录 README。

交付版本为 `0.12.0 (80)`，构建 `N4-D1-iOS-20261010-101029`，主应用与 JIT helper 的构建号一致。IPA 为 `Husk-NativeLinux-N4-D1.ipa`，大小 487,196,628 字节，SHA-256 为 `5c37d95514ac8146919d24ee2b2c39dac1fdb2e25d00b5298e3dcbb7fc6b9987`。完整打包清单位于 `work/native-linux-nce/ios/package.json`，记录输入、内核、系统镜像和图形库哈希。

当前使用 1 GiB Linux RAM、demand 映射、Launcher3、AOSP DeskClock、DocumentsUI 和 gfxstream/ANGLE Metal。iOS 入口跳过性能压力测试，启动后保持 Android 会话；返回、主页和最近任务通过实际 Android 输入处理。手机运行所需内核、系统镜像、数据盘种子和图形库随包提供。

### 本机检查

CLI、GCD、可见窗口均完成 Launcher、时钟闹钟页、Files、密钥与应用数据检查，旧 Google 时钟记录得到保留。三轮均正常停止，ext4 clean 与只读 e2fsck 通过，Android 日志无 Java 主线程崩溃或 ANR。构建期间源码变化检查和全部输入哈希检查通过。详细配置、组件计时与检查结果见 [results-macos-n4-d1-desktop.json](../../../../experiments/native-linux/results-macos-n4-d1-desktop.json)。

Release 构建、固定执行地址与 JIT 脱离辅助检查、10 项 JIT 协议回归、Swift 日志读取检查、应用及依赖的 codesign 验证和 IPA ZIP 校验通过。当前包的真机运行状态为 pending。可见持续会话已实际完成桌面上滑、闹钟页打开、秒表启动和暂停、Files 侧栏与返回、主页和最近任务切换；从 Files 切回 Clock 后，秒表仍暂停在 46.95 秒。首次明确启动时钟会出现 Android 通知权限提示，选择后可继续。关闭宿主窗口后 Android 正常停止，1,008 个 NCE 上下文全部释放，145 个图形通道全部关闭，ext4 clean 与只读 e2fsck 检查通过。

可见持续会话关闭映射及故障详细计数，启动期间与打包编译重叠，未用其耗时评价性能。结束 Framework 后的 Mac 采样为峰值 RSS 1,649,000,448 字节、当时 footprint 1,826,409,976 字节；手机运行期内存仍待测量。Files 浅色页面底部的 Android 导航图标对比度偏低，宿主导航按钮可用。

### 设备反馈与待确认项

[提前包真机记录](2026-10-10-N4-D1提前包真机体验.md)已经确认真实 Launcher 与触摸。SystemUI StartServices 为 62,230 ms，Launcher 首帧为 67,259 ms；两项覆盖不同组件，不能相加作为总启动耗时。完整帧时间、运行期内存和持续热状态尚未测量。

正式包集中验证：从桌面上滑打开应用列表，操作 Clock 和 Files，并通过主页与最近任务切换；在新时钟中保存一个闹钟，使用宿主的停止 Android 按钮，结束宿主后重新打开并启用 JIT，检查闹钟是否仍在。导出完整日志时同时记录明显卡顿、闪退或发热情况。

## 曾考虑的替代方案

单独补入 GoogleServicesFramework 后首次启动通过，宿主重启仍在 Google 时钟中触发缺失 provider。APK 资源确认该版 GSF 默认将相关提供者交给 Play 服务。携带完整 Play 服务或改写 GSF 内部资源会扩大当前本地应用目标的依赖与维护范围；本阶段采用同版 SDK 的原始 AOSP 时钟，保留其签名。选择与失败过程见[桌面组件记录](../../proposed/architecture/2026-10-10-Android桌面组件选择.md)。

### 复杂度复核

AOSP 时钟继续使用已有固定 SDK 提取、哈希校验和应用复制流程。`verifyRecord` 复用原有数据库内容检查，同时覆盖旧 Google 时钟与新 AOSP 时钟；没有加入数据库迁移实现。删除旧 APK 会使现有数据目录的升级保留取决于 PackageManager 的卸载处理，因此本阶段继续携带并停用它。控件与像素联合检查覆盖已复现的启动图标提前通过问题，连接与回调线程随检查结束释放。

## 影响

正式包沿用 `com.husk.app`，可通过 iLoader 覆盖提前包并继续使用数据目录。Google 时钟 APK 与数据保留，通过 Android 包管理器停用；桌面显示 AOSP 时钟，两者数据未迁移。升级检查验证了旧测试闹钟继续存在。

冷启动仍慢，当前本机测试的计时不能转换为 iPhone 或旧 QEMU 的加速倍数。Wi-Fi 设置页仍缺少完整服务与硬件接口；网络、APK 导入、完整外部存储功能和 HyperOS 3 集成继续按后续阶段评估。当前交付范围保持方案 A。
