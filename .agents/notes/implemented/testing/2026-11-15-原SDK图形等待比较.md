# 决策记录: 原 SDK 图形等待比较

状态: implemented

## 问题

[读取身份阶段](2026-11-15-原SDK图形读取身份.md)已确认 SurfaceFlinger 的非阻塞图形 FD 出现 524288-byte read 的 `-11`，固定 Common 源码存在立即重试路径。需要比较 Common 原实现重建基线与等待候选的实际启动记录，同时保留完整系统的原验收条件。

## 决策

本阶段交付 [Common 比较结果](../../../../experiments/native-linux/results-sdk-common-read-wait-20261115.json)，包括两变体六入口、既有 v15 参照、共享输入、数据恢复、启动消息和采集缺项。等待代码继续在独立目录构建，完整 Linux / Android、桌面、通用原始签名 APK、HyperOS 与持续性能继续验收。

### 来源与运行条件

比较使用同一 v15 CLI/GCD、内核与宿主图形库，通过系统盘选择 Common baseline/wait；两个变体从同一 v15 种子分别用 `cp -c` 克隆 data/metadata，先完成 baseline，再运行 wait。每个变体依次执行 CLI/GCD lifecycle、CLI/GCD original、CLI/GCD recovery。两个 original 各观察 180 秒，宿主超时为 240 秒，其他入口为 90 秒，工具总超时为 1200 秒。原 PID1/Binder/SIGQUIT 的 450 秒条件保持。

两项 summary 记录 Apple M5 Ultra、`macOS-27.0-arm64-arm-64bit-Mach-O`、系统构建 `26A428`，Direct、TBI、16 KiB guest/host 页、单 CPU、1 GiB guest RAM、128 MiB 翻译缓存、`instruction_batch=50000`、2 ms 定时器抢占间隔与 100 ms 内存采集间隔。共享 v15 CLI/GCD 的 SHA、内核构建和 ABI 引用保存在结构化结果中。

### 启动消息与全局 read 计数

v15 与重建 baseline 的 CLI/GCD 均记录 DisplayManager phase 100 开始，缺少该阶段及 PackageManager 的完成消息。wait 的两个入口记录这两项完成，最后保存的阶段消息均为 `startCoreServices`，该方法的完成消息尚未采集。

| wait original 入口 | DisplayManager phase 100 日志耗时 | WaitForDisplay 日志耗时 | StartPackageManagerService 日志耗时 | 最后保存的阶段 |
| --- | ---: | ---: | ---: | --- |
| CLI | 1900 ms | 1902 ms | 53463 ms | `startCoreServices` |
| GCD | 2333 ms | 2334 ms | 37887 ms | `startCoreServices` |

这些毫秒值来自原 `SystemServerTiming` 的具名服务区间；完整 Android 启动、帧时间和持续交互性能尚未验收。

计数按宿主中的 syscall 编号与结果正负分组，包含全部已记录服务与 FD。普通样本没有 PID/TID；参数只保留各组前 64 次和后续 2 次幂索引，具体图形 FD 的调用总数未单独采集。负结果包含 `-512`、`-514` 等 guest 内核重启结果，末次 errno 只描述末次调用。六份身份快照均取得 SurfaceFlinger 的 FD 10、`/dev/goldfish_pipe_dprctd`、`F_GETFL=133122/0x20802` 与 `O_NONBLOCK`，PC/LR 文件偏移分别为 `0xd2b08`、`0x1a344`。本轮 FP 链与 GOT 值未采集，Common 等待分支和该 FD 的动态调用关系继续核对。

### 原验收与缺项

| 结果 | baseline | wait |
| --- | --- | --- |
| 六入口退出、观察与进程组回收 | 六项退出 0，检查成功 | 六项退出 0，检查成功 |
| 同盘 recovery 与最终 data/metadata | 成功，最终均为 clean | 成功，最终均为 clean |
| SQLite 文件格式、quick_check 与 schema | 成功 | 成功 |

两个变体的 original 停止后 data 均需要恢复；各两项 recovery 完成后 data/metadata 均为 clean。导出的 `persistent.sqlite` 均为 94208 bytes，SHA256 为 `11b04f927300f8a61ce7f4c715906319172d8c3d4539fcf817e4de29f7ec8eed`，`quick_check` 为 `ok`，schema 含 19 项。查询使用独立克隆与 `mode=ro`，连接关闭和临时查询目录回收完成。

四份 original 的 observer 文件部署校验已有记录，`/local/tests/system/<boot_id>` 的对应结果目录均缺失，19 项内部查询结果未采集。属性 `sys.boot_completed=1` 是否触发、observer 是否在读取 boot_id 或创建目录前退出，均待后续采集确认。完整启动继续按唯一完整 `result.passed.tsv`、19 项输出与 boot_id 一致性验收。

wait 的 taglog 达到 128 条上限，CLI 的 `seen/recorded/omitted` 为 `129/128/1`，GCD 为 `200/128/72`；baseline 两入口各为 `120/120/0`。`seen/omitted` 仅统计符合本轮固定 tag、优先级和阶段选择条件的消息，每条最多复制 2048 bytes；已有记录缺少后续完整阶段。450 秒 PID1/Binder/SIGQUIT 条件超过本轮 180 秒 original 窗口，本次保留 `incomplete`。

baseline/wait 验证总耗时分别为 432.14442762499675 秒和 433.8520387499593 秒，包含可写盘克隆、六入口、停止回收、导出、capture 重分析和输入检查，计时使用 Python `time.monotonic`。这两个数值未用于启动性能比较，Android 启动完成秒数保持未采集。

## 曾考虑的替代方案

[比较计划](../../../../../../../sdk-plain-validation-v1/common-sdk-comparison-v1/plan.json)记录了三项备选。复制整个 SDK 和 frozen tree 会增加重复产物，既有宿主已能通过环境变量选择系统盘，因此本轮共享只读输入并分别克隆可写盘。分别重编译宿主会增加构建差异，本轮复用已核对的同一 v15 CLI/GCD。仅检查顶层 import 会遗漏同目录动态读取的 `pid1_validation.py`，准备阶段改为执行完整离线分析并记录实际依赖。

## 影响

本阶段固定已完成的比较结果，原运行报告的整体状态和完整 boot 均保留 `failed`。wait 已记录的显示及 PackageManager 完成消息、全局负 read 计数变化支持继续验证等待候选；当前采集仍缺少上层 FP 链、GOT 和成功 poll 的动态关系。后续按具体调用与启动阶段继续采集，完整系统验收条件保持。iPhone 安装、JIT 授权、设备资源、持续性能和热状态待真机验证。
