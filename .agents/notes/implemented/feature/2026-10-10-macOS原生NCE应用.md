# 决策记录: macOS 原生 NCE 应用

状态: implemented

## 问题

2026-10-10，用户授权实现可从 Finder 打开的 Mac App，保留 NCE 动态代码执行与 ART JIT，并选择布局 A：Android 画面与底部导航占据窗口，状态与日志放菜单。本次增加独立 Mac 使用场景，Mac 与 iPhone 分别运行完整 Linux / Android、各自保存数据。iPhone 目标继续按[路线决定](../architecture/2026-10-08-转向原生Linux与NCE.md)和[桌面提案](../../proposed/feature/2026-10-09-Android可交互桌面.md)推进。

## 决策

### 交付行为

新增[SwiftUI 与 AppKit 入口](../../../../experiments/native-linux/macos/Application.swift)，共享 N4-D2 的 LKL、NCE、Android 用户态、图形与输入代码。当前包面向 Apple Silicon，使用 1 GiB Linux RAM、4 GiB 客体地址窗口、demand 映射、360×640 Android 显示及 gfxstream / ANGLE Metal。桌面沿用 SDK Android、Launcher3、AOSP DeskClock 和 DocumentsUI。HyperOS 3 继续按现有兼容性工作推进。

内核、系统盘和空白数据盘种子位于 Contents/Resources，动态库位于 Contents/Frameworks。可写数据放在 ~/Library/Application Support/app.droidondarwin.mac，首次复制到临时文件，fsync 成功后启用。目录通过 flock 独占，同一个数据盘同时只能由一个宿主使用。替换应用包后继续使用已有数据。每次运行生成独立日志，菜单可打开日志与数据目录。

Mac 入口管理准备、启动、运行、停止与结束阶段。后台执行核心，桌面就绪标记出现后启用鼠标输入和三个导航按钮。关闭窗口、菜单退出与 Cmd-Q 通过现有停止接口结束 Android；停止入口尚未注册时每 0.5 秒重试，主线程继续处理窗口事件。宿主退出前等待核心返回，目录锁保留到进程退出，因为启动失败时内核资源可能仍在使用。重新打开应用可再次启动 Android。

窗口保持 Android 画面宽高比，按显示区域转换输入坐标。ANGLE 根据 layer.bounds 决定渲染尺寸，因此固定 Metal 子图层为 360×640，用 transform 缩放显示。鼠标点击与拖动、返回、主页和最近应用为当前输入范围；物理键盘、中文输入和触控板滚轮仍需适配。

### 构建与签名

[打包脚本](../../../../scripts/package_native_linux_macos.py)校验 lkl-summary.json 的源码、生成物、内核和动态库哈希，并要求已有 CLI/GCD/窗口桌面回归成功。打包编译相同核心源码，修正包内 rpath，提供图标与第三方许可，生成 package.json 文件清单。--rebuild-kernel 可调用原有回归，--replace 只替换未运行的工具生成包。用法见[Mac 入口说明](../../../../experiments/native-linux/macos/README.md)。

当前 gfxstream 的最低部署版本为 macOS 27.0，ANGLE 为 macOS 15.0，因此包声明 macOS 27.0。实际验证设备为 Apple M5 Ultra / macOS 27.0（26A428）；其他系统版本尚未确认。

当前 memory.c 使用 vm_remap 建立代码读写与执行别名。Hardened Runtime 无例外或只有 allow-jit 时，执行检查收到 SIGKILL；allow-unsigned-executable-memory 下，指令更新、访问故障、重映射失败恢复和信号处理器恢复成功。现有映射保留，Android ARM64 用户代码继续由 NCE 执行，ART 按当前支持范围 JIT 编译。Apple 的 [JIT 文档](https://developer.apple.com/documentation/apple-silicon/porting-just-in-time-compilers-to-apple-silicon)和[可执行内存权限](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.cs.allow-unsigned-executable-memory)是签名实验的参考。

本机 ad-hoc 签名库在默认 library validation 下因 Team ID 校验无法加载，增加 disable-library-validation 后成功。最终包开启 Hardened Runtime，保留 allow-unsigned-executable-memory 与 disable-library-validation 两个例外。Developer ID、公证和其他机器下载后的启动另设发布验收。

### 验证与偏离

宿主检查由 [test_native_linux_macos.py](../../../../scripts/test_native_linux_macos.py)执行。检查资源缺失、模拟 ENOSPC、首次复制中断恢复、磁盘占用、符号链接与损坏盘拒绝、数据保持、坐标缩放、边界坐标、就绪前输入、导航顺序、实际 App 入口的初始/横向窗口布局，以及停止入口延迟注册。签名执行与图形库加载分别检查；包内资源大小、全部文件哈希、源码哈希和签名一并核对。

实际窗口曾出现画面与底部导航重叠，原因是 AppKit centerY 约束偏移方向。已修正，并用实际 App 入口的布局检查覆盖。首版布局按用户选择完成；同进程重启改为退出后重开，避免增加内核、图形与信号状态的重新初始化路径。

打包未抽取 probe_lkl.py 的内部构建函数。已有摘要能校验所有核心输入，独立打包脚本即可复用源码和生成物，保留现有回归调用方式。M1、M2、M3 共同组成可体验的本地交付阶段，实现与记录一起提交。

### 复杂度审查

按 reclaim-code-entropy 检查实际调用并进行移除思想实验：App 管理一个会话，Display 管理尺寸与输入，Storage 管理磁盘与占用锁，各自有直接使用方。去掉临时文件会让首次复制中断产生可被误用的半成品；去掉锁会允许多个宿主写同一 ext4 文件；去掉固定图层尺寸会改变 ANGLE 渲染目标。状态仅保留阶段与 AppKit 终止等待标记，两者分别控制操作和回复契约。

共享执行核心保持原文件和输入哈希。AppKit 同进程显示沿用已有接口，无需 helper、XPC、通用平台接口或另一份核心。现有 window-test.mm 继续承担回归；新增替身只用于 Host Checks.app，测试源码不进入交付包。


### 本机结果

最终构建为 Mac-M1-20261010-122830。`python3 scripts/package_native_linux_macos.py --replace` 与 `python3 scripts/test_native_linux_macos.py --app 'work/native-linux-nce/macos/final-check/Husk NCE.app'` 成功。包移动到 final-check 后，清空调用进程环境并通过 LaunchServices 启动，Launcher、Clock、Files 均正常显示。放大窗口后点击 Files、还原窗口、返回与最近应用完成实际操作；8:30 闹钟增加 Saturday 重复日后，正常退出再启动仍显示该设置。

使用最终包同批编译的核心对象、现有 dispatch-test.c、包内内核/系统盘/动态库和相同签名权限，执行两轮 NCE_SYSTEM_SERVER_PROBE=1、NCE_MM_MODE=demand 回归。每轮 138 项不同名称的 passed 检查成功，第二轮闹钟记录与 Keystore 密钥 restored=true。此入口验证签名后的核心与 GCD；原有 CLI/GCD/窗口基线分别为 138/138/139 项，打包校验其输入哈希，本次没有修改共享执行源码。

隔离数据目录中的最终 App 经 SIGKILL 后重新启动成功。强制退出后的只读 ext4 检查报告待恢复的计数与 orphan 标记；重新启动并通过关闭窗口正常结束后，e2fsck -fn 的五阶段检查成功，无上述错误。此次验证只覆盖已落盘数据和本次恢复条件。恢复会话释放 852/852 个 NCE 上下文、80/80 个图形通道，linux_data_readonly_shutdown 与最终 result 成功。

宿主检查覆盖了数据与布局失败边界；实际缺少 Metal 设备时的弹窗分支只做源码检查，当前机器具有可用设备。图形动态库加载失败由签名对照实验覆盖。启动期间 Cmd-Q、桌面就绪后的 Cmd-Q、关闭窗口和异常终止后恢复分别执行。

无参数 LaunchServices 启动成功，首次创建默认 Application Support 数据目录，菜单显示 Android 正在运行，通过菜单停止后释放 944/944 个 NCE 上下文、78/78 个图形通道，数据盘只读关闭和 ext4 检查成功。重复启动的第二个宿主未打开数据盘或运行日志。最终包已移回标准输出位置并重新核对签名和全部输入、包内文件哈希。结构化结果见 [Mac M1 检查结果](../../../../experiments/native-linux/results-macos-app-m1.json)。

原始日志、签名实验与 package.json 位于 work/native-linux-nce/macos；结构化结果随代码提交。复现签名核心检查时，重新打包后将生成的核心对象与 dispatch-test.c 链接，图形库指向包内 Frameworks，使用 DroidOnDarwin.entitlements 签名，将包内 seed 克隆到隔离数据盘，按上述两个环境变量连续运行两次。该入口与 App 的界面检查分别报告。

### 验收条件

1. App 在声明的 Apple Silicon/macOS 环境中从 Finder 启动，移动位置后仍可使用包内运行文件和独立数据目录。
2. Launcher、Clock、Files 可显示与切换，正常停止后再次启动保留闹钟和密钥；缩放后输入坐标正确。
3. 覆盖资源、磁盘占用、磁盘创建失败、执行权限、启动中退出和正常退出；强制终止后验证重新启动和 ext4 恢复。
4. 最终签名条件覆盖动态代码、Linux、ART 和图形。共享核心沿用已经通过的 CLI/GCD 回归，新增检查区分实际 App 与测试入口。

## 曾考虑的替代方案

- 直接交付现有测试 App：仍需命令行内核参数、外部库路径和环境变量，无法满足 Finder 启动条件。
- iOS 包或 Mac Catalyst：需要调整 UIKit 入口和 iOS 二进制依赖；仓库已有 AppKit 显示与输入实现，选择复用。
- 首版增加多宿主进程、多核或 helper/XPC：改变调度、共享内存和图形资源管理，缺少当前使用场景支持；先交付同进程 App。
- MAP_JIT：会改变当前固定地址与别名布局；现有映射已经通过目标签名条件检查，本次保留。

## 影响

同进程执行核心故障会结束宿主应用。当前只确认本机签名与运行，其他机器、公证、不同系统版本和完整 HyperOS 桌面仍有独立验证条件。
