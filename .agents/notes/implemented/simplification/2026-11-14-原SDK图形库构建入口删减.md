# 决策记录: 原 SDK 图形库构建入口删减

状态: implemented

## 问题

原 SDK 图形候选 v3 曾替换 `libqemupipe.ranchu.so`，原 EGL 和 OpenGL common 自身包含 qemu pipe 实现，独立库替换未建立它们的实际传输。后续 v4 使用原 qemupipe ELF，通过 LKL 字符设备连接 renderer。当前图形库构建脚本和补丁只剩历史候选复现使用方，但字符设备 probe 仍导入该脚本的只读 ELF 契约检查。

本次按 reclaim-code-entropy 核对构建函数、CLI、导入、动态库、测试及历史来源。详细审查为 `work/sdk-plain-validation-v1/qemupipe-complexity-review-v1.json`，原库接入与启动结果见[图形提案](../../proposed/architecture/2026-11-14-原SDK图形服务与宿主传输.md)。

## 决策

把 `_elf_contract` 的原函数体移到唯一使用方 `probe_lkl_graphics_pipe.py`，来源清单改为实际使用的 `llvm-readelf`。移除本轮新增的独立图形库 builder 和专用补丁；当前原库路径及其九个导出保持。`guest-pipe.c` 继续供 `build_nce_userspace.py` 生成 `libnce-qemupipe.so`，egl/gralloc/display/framework 的实际 `LD_PRELOAD` 检查继续使用它。

移除前在 `work/sdk-plain-validation-v1/qemupipe-source-history-v1/` 保存九份必要源码，共 70,373 bytes，包括实际 builder、补丁、guest pipe、原 631-byte 地址头，以及 run-v4 的 probe/fixture。原头逐字节恢复后与旧构建清单的摘要一致；原 v3 库、失败报告、run-v4 和原摘要保持。该清单保存原构建命令、来源摘要与路径条件；在其他工作树复现，需要重新生成源码匹配的 core 并使用对应 runner 路径。

原 SDK 与历史 v3 ELF 的契约读取、无效 ELF、缺少 SONAME、摘要冲突拒绝，以及归档 CLI 导入检查成功。函数体 AST 比较相同，重新运行修改后的 probe，no-listener、backlog、protocol、original 四种模式在 CLI/GCD 共八轮均验证成功，实际退出 0、进程组清空。482 项来源前后保持，变化范围为 probe 本身与 builder 到 `llvm-readelf` 的来源项。实际结果为 `work/sdk-plain-validation-v1/graphics-pipe-probe-v1/run-v5/result.json`，生成目录清理见 `work/cleanup-2026-11-14/run-v5.json`。

### 复杂度审查

只读 ELF 检查有实际使用方，移除它会失去原库符号、SONAME、依赖和 LOAD 对齐的检查。独立 builder 的构建行为只供历史 v3 使用，保留全部构建入口会使当前 probe 继续导入额外的构建工具。函数移到当前使用方后减少了这项依赖，未增加转发模块。历史来源单独保存，用于重建已失败的候选。

共享地址、字符设备、原 DSO 与 renderer 的协议检查继续保留；`guest-pipe.c` 的四类动态使用方仍存在。本次没有移除这些实现或其验收条件。

## 曾考虑的替代方案

- 删除整个 builder 而保持原 import：字符设备 probe 仍消费 `_elf_contract`，会在导入阶段失败，先移动该函数。
- 另建一个 ELF 工具模块：当前只有一个使用方，直接放在 probe 内可以减少模块与导入关系。
- 删除历史 v3 的全部源码和候选：原失败需要可核对的复现来源，先保存原函数、补丁、旧头、命令和摘要。
- 删除 `guest-pipe.c`：既有四类图形检查仍动态使用生成库，继续保留。

## 影响

当前 v4 使用原 qemupipe 的行为保持，删减后字符设备八轮验证成功。原 v3 的失败状态和旧构建标识保持；本次仅处理本轮构建入口的维护成本。完整 boot、显示缓冲区分配、原 APK 操作和 iPhone 持续性能继续由对应阶段验证。
