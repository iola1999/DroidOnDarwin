# 决策记录: 宿主与客体数值地址范围分离

状态: implemented

## 问题

稀疏客体地址已允许原始 SDK36 Bionic 完成 8.25 GiB Scudo 预留并进入 main。改动前，宿主 RAM alias 与 backing 要求位于 64 GiB 客体上界以上，Mac 的 Mach 分配实际落在 448 GiB。iOS 历史已有大连续 VA 预留失败，宿主地址的数值下限需要独立验证。

实现基点为主会话集成提交 `4439e99`，包含标准动态代码映射、sparse、数据 TBI 和原始 ART runner。实现使用 `work/offline-stock-bionic`、分支 `codex/offline-address-domains`，主工作区源码保持不变。主会话已授权最小原型和功能验证。

## 决策

保留默认分配策略及配置，仅解除 translated 的宿主/客体地址大小关系。`current->thread.nce_state` 已决定 uaccess 使用宿主缓冲区或当前客体 mm 的 PTE；`mm == &init_mm` 已决定页表更新是否执行宿主映射。这两个已有上下文足以表达首轮使用范围。

`linux-execution.c` 的 `shmem_map` 在 translated 模式只接受实际 RAM/VMALLOC reservation，完整检查起点、长度和溢出；`revoke_pages` 的旧 window 分支限定为非 translated。删除宿主 RAM backing 与 guest_end 的大小比较，删除 translated 内核初始化和 prepare 的 physical_base/guest_end 大小比较；对齐、宿主地址上限、RAM 物理偏移与真实预留范围检查保留。旧 window 的地址分类保持原值。

新增独立测试驱动，复用成功 sparse 报告中的编译命令与环境，生成宿主执行与客体边界检查源码副本，将测试 guest_end 扩为 512 GiB。宿主分配继续从 64 GiB 查找，实际 reservation 与 backing 必须完整位于测试 guest 数值范围内；未形成重叠就报告失败。生成源码、二进制、内核和输入哈希进入报告，产品保留 64 GiB sparse 范围和原分配策略。校验函数 `sparse_end` 为仅关键字参数，只接受 64/512 GiB，512 GiB 仅由测试脚本传入。

首轮保留 16 KiB、单 CPU、PTE/Direct flat、标准 VM、数据 TBI。范围分类改动也允许 low 布局的宿主地址数值落入 guest 范围；实际重叠功能检查使用 512 GiB 测试副本，4 GiB low 的真实重叠布局未测。增加 guest 同 VA 私有页 COW 与共享页检查，复用既有高位地址、权限、动态代码和 uaccess 负例。测试单独检查正常退出及准备失败后的实际 reservation 区间。

### 验收条件

1. CLI/GCD 的普通 host 与 sparse core 成功；原有默认数据 TBI 行为保持一致。
2. 强制重叠的 sparse core 两入口成功，报告真实 reservation、backing、guest 范围和源码身份。实际宿主低数值缓冲区通过 `openat/write/pread`；客体未映射同值地址访问失败，宿主内容保持原值。
3. 客体同 VA 私有页的 fork/COW 与共享页行为正确，子进程退出和父进程撤销后再访问失败，宿主源缓冲区保持原值。
4. 正常退出的整个 reservation 已释放；准备失败覆盖创建前后，完整 Mach 区间检查及末页残留负对照成功。
5. 原始 SDK36 Bionic 在重叠配置下完成 linker help、main 和五项组件检查。输入原始字节和清单保持一致。
6. 验证器拒绝宿主 reservation/backing 相互重叠、地址溢出、配置缺失和重复项；translated 的宿主/guest 数值重叠被明确接受。

### 实施偏离与最初失败

首次生成副本将 `mach_vm_map` 的 `VM_FLAGS_ANYWHERE` 查找起点设为零，返回地址仍为 `0x7000000000`；改为 `mmap(NULL, ...)` 后同样返回该地址。两次测试均在 Linux 启动前正确拒绝未形成重叠的分配。轻量固定地址探针使用 `VM_FLAGS_FIXED` 且没有 `OVERWRITE`：一次 4.5 GiB 起点成功，随后同时查找两个所需区间的运行未取得 4–64 GiB 内的可用区间。后一次扫描的源码和输出保存在归档及 `work/native-linux-nce/address-domain-allocation-probe.log`，无法据此推断 iOS 可用地址。

主会话确认采用 512 GiB 客体测试范围覆盖真实 448 GiB 宿主区间。该对照可以检查数值重叠和高地址 PTE 访问，iOS 的实际低地址分配仍需设备验证。测试源码搬到输出目录后，首轮编译因 `interaction-profile.h` 的同名 include 顺序失败；改用 `-iquote translation` 保留原局部头文件解析。首次成功运行还被通用验证器拒绝，因为测试析构输出在原 `result=passed` 之后；测试验证器现单独检查固定三行尾部记录，并保留原产品记录的最终结果检查。

### 实际验证

本机为 Apple M5 Ultra，macOS 27.0 / 26A428。全部运行属于功能验证，同期允许其他独立构建，没有性能比较。默认 host 对照关闭数据 TBI，其余 sparse/512 GiB 运行开启数据 TBI；均为单 CPU、16 KiB 页、PTE/Direct flat、dual 执行内存、128 MiB Unicorn cache、timer 抢占、page exec/TLB invalidation、code-watch、cross-page、native-exclusive 开启。完整配置、命令、源码哈希、内核哈希与原始输入身份保存在报告。

四次重叠运行均使用 `guest_base=0x10000`、`guest_end=0x8000000000`，宿主 `physical_base=reservation_base=0x7000000000`，预留长度 `0x44000000`，RAM backing 为 `0x7044000000`、长度 `0x40000000`。两个实际宿主区间均位于 guest 数值范围内，彼此不重叠。每次记录 9 次 VMALLOC 映射、1 次撤销，退出后 Mach 区间检查确认 reservation 和 backing 均已释放。`ram_reclaims=0`，本轮没有验证实际 RAM reclaim 调用。

core 的动态栈和 TLS、末页及跨上界访问使用测试客体上界；这些访问覆盖超过 64 GiB 的软件 PTE 路径。未映射的 host RAM alias、backing、宿主缓冲区同值地址的 load/store 和 `openat/write/pread` 均拒绝。客体在宿主缓冲区的同值 VA 建立私有页后，子进程写入只改变子进程页；共享页的子进程写入在父进程可见，撤销后访问失败，宿主原缓冲区内容保持原值。

原始 SDK36 四文件与清单保持原字节；清单 SHA-256 为 `4b1a45b0ee51725c68f1c29765958d0b60b45a5f2325bedfc61764cd49232249`。512 GiB 组件运行实际申请 `8,858,370,048` 字节 PROT_NONE，CLI/GCD 返回 `767557632` / `758710272`，随后五项检查成功。上述数据只检查地址容量与组件行为。

准备失败检查各入口覆盖 kernel、Unicorn、Direct 三个执行内存准备点和末页残留负对照，共 8 组成功。创建前失败要求零次预留和释放，创建后失败要求一次完整释放；末页保留被检测为未完全释放。正常退出另以 CLI/GCD 各一次末页残留验证，产品结果保持 `passed`，测试的完整区间验证正确拒绝两份报告。地址布局 198 个负例、core 与 Bionic 报告各 294 个变异负例、TBI 74 个负例成功；格式检查、Python 语法检查和 `git diff --check` 成功。

## 曾考虑的替代方案

- 继续使用 `physical_base >= guest_end`：现有 Mac 路径可运行，但延续了高位宿主地址要求，无法验证较小 iOS 地址范围的可行性。
- 全面引入带地址域标签的指针类型：现有 syscall 来源和 mm 上下文已有必要信息，当前修改点无需增加贯穿多层的新表示。
- 改默认 sparse allocator：本阶段先通过测试副本验证数值重叠，默认分配选择保持原值，减少与其他集成验证的配置差异。
- 每 mm 建立完整宿主别名：增加 VA 预留，并引入 4 KiB 客体/16 KiB 宿主粒度与可写代码别名问题，当前实验不需要该结构。

## 影响

本轮实际运行所覆盖的 Linux uaccess、VMALLOC 和动态栈路径已通过重叠验证；其他通用 Linux 路径若继续通过 TASK_SIZE 判定内核或用户地址，需要结合调用来源核对。初轮只验证已约束的单 CPU translated 配置；SMP、read-view、4 KiB 客体、真实 iOS 和完整 Android 保留后续验收。任何新增范围检查都不能拒绝合法 guest 同值映射，也不能允许客体绕过 PTE 访问宿主。

复杂度审查使用 reclaim-code-entropy：当前删除重复的数值分类，保留权限与物理范围检查；测试复用实际构建命令，不新增产品开关或通用框架。文档按 humanizer-zh 核对，性能结论不在本阶段范围。
