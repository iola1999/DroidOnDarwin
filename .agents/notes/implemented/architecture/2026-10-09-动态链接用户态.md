### 当前结果与接口决定

已经运行 musl 1.2.5 的 AArch64 动态链接器、DT_NEEDED 依赖、dlopen 和
动态 TLS。dash 0.5.12 通过动态 libc 运行，完成管道、重定向、外部 exec、
信号 trap 和后台 wait。安装包同时包含 [N2d](2026-10-09-Linux信号与用户态程序.md)
实现的 Linux 信号帧、异常返回、系统调用中断与重启。

Linux 继续加载 ELF、维护文件映射与权限；musl 负责重定位、符号解析和
TLS。执行地址由构建时登记的 ELF 布局确定，代码保留 x18，使用 16 KiB
段对齐。九个 ELF 共用 64 MiB 客体地址窗口，每个文件占用一个 2 MiB
布局范围，mmap 区域从窗口内 32 MiB 处开始，初始参数栈放在窗口末尾。

这批改动扩大了实际可运行的用户态范围。完整 Android 尚未启动，持续交互
性能和发热仍需后续集成测量。C1 的两次手机运行及适用范围见
[N2c 记录](2026-10-09-地址空间与用户内存.md)。

### 实现

#### ELF 与文件映射

Linux ELF 入口接受登记的 PT_INTERP，并在替换当前进程前检查主程序和
解释器布局。解释器与共享库使用已准备的地址；首次映射采用
`MAP_FIXED_NOREPLACE`，具体 ELF 段继续通过 Linux 文件映射装入。

AArch64 的 mmap 参数使用字节偏移，新入口校验对齐后转换为页偏移，再
调用 `ksys_mmap_pgoff`。可执行文件映射须对应已登记的 ELF；可执行匿名
mmap 及同时可写、可执行的 mmap 返回 `EACCES`。当前实现服务于受控程序，
任意 ELF 的执行地址选择、通用可执行 mprotect 与 ART 动态代码仍待开发。

构建阶段检查解释器路径、段边界、入口、指令区和 x18 使用。LLD 生成的
AArch64 PLT 使用 `SHF_AARCH64_PURECODE` 标记指令；其余指令区继续依赖
`$x` / `$d` 映射符号。musl 共享库包含所需 compiler-rt 算术函数，最终
`llvm-nm -u libc.so` 无未定义符号。

#### 执行视图与缺页

SVC 和 TLS 指令只改写宿主执行视图，Linux 文件页和页缓存保持原内容。
一次映射请求跨越代码与数据时，按执行区边界分别复制代码或重映射数据。
只有 Linux 映射携带执行权限时才改写指令，允许动态链接器先读取整个 ELF。

fork 可以省略只读文件代码的页表。宿主对应区域清零后，首次取指触发 UDF，
Linux 装入缺失代码页后恢复执行。已有有效页中的非法指令递送 SIGILL。
已删除宿主每个代码页的物理页偏移数组，以及把改写代码复制回 Linux RAM
的路径。文件内容一致性检查在静态与动态程序运行后分别执行。

#### 信号与宿主恢复

N2d 的 Linux 信号处理用于动态程序和 shell。覆盖备用栈、嵌套信号、
寄存器恢复、EINTR、SA_RESTART、异常信号帧、停止与继续、pthread 取消，
以及没有系统调用的循环接收 ITIMER_REAL 信号。

JIT 执行预检的异常恢复改用 `sigsetjmp(..., 0)`，通过 `pthread_sigmask`
仅恢复当前线程的屏蔽状态。这样与 LKL 的 `_setjmp` / `_longjmp` 调度
约定保持一致，相关平台原因和回归见 N2d 记录。

### 复杂度审查与偏离记录

按 reclaim-code-entropy 检查了新增状态、接口用途和删除后的影响。
重定位、符号查找及 TLS 继续使用 musl，信号队列与文件映射继续使用 Linux，
宿主仅实现原生执行、固定地址代码更新和数据映射。

新增文件布局查询用于把 musl 的 mmap 与预先准备的执行地址对应起来；
去掉这个步骤会让 Linux 自选地址，无法满足当前 iOS 固定 RX 地址的要求。
映射分段用于处理同一次 mmap 涉及代码与数据的情况，现有动态程序会触发
这个条件。代码页偏移数组与回写 RAM 的路径已经移除，当前回归均通过。

宿主上下文的独立信号屏蔽测试保留：原实现可重现跨线程屏蔽，新实现通过。
ELF 校验新增两项测试，分别检查动态程序/共享库入口与 PLT 的指令标记。
其余新增检查直接运行真实 Linux 信号、shell 或动态程序。

相对原计划，N2d 的手机包推迟到动态链接完成后一并交付。没有新增中间
手机测试。N2e 缩小了每个登记 ELF 的布局范围并移动初始参数栈，以容纳
九个文件；这些限制集中在布局头文件和构建器中。
