# 决策记录: iOS JIT 执行条件

状态: implemented

## 问题

iOS 应用需要在受代码签名约束的地址范围内运行动态准备的 ARM64 代码，执行权限依赖设备系统和调试器配合。

## 决策

当前实现通过调试器准备调用方预留的 RX 地址区间，再使用 `vm_remap` 建立可写别名。相关代码位于 `src/ios-jit/ios-jit.c`，调试脚本位于 `src/app/Resources/jit.js`。

断点协议使用 `brk #0xf00d`，`x16=1` 请求准备区间，`x16=0` 请求分离调试器，参数为 `x0/x1`，结果通过 `x0` 返回；`brk #0x69` 用于检查调试器响应。应用提前安装信号处理函数，使未处理的 JIT 请求返回零，其他信号交回原处理函数。

区间地址和大小需要按 16 KiB 对齐。准备时检查 RW 写入能否通过 RX 别名读回；所有区间准备完成后分离调试器，再由执行核心通过信号保护检查实际执行。内存准备结果与执行结果分别判断，保留失败原因和运行日志。已准备的映射可能持续到进程退出，因此 iPhone 连续会话的生命周期仍按[后续提案](../../proposed/feature/2026-10-10-iOS连续重启Android.md)处理。

上游的双映射实现注明 AetherPS4-iOS / shadPS4 来源，本项目保留该来源和 Husk 的修改关系，见[开源致谢](../../../../ACKNOWLEDGEMENTS.md)。

## 曾考虑的替代方案

早期执行方式及探测代码见 Git 历史。当前调用方预先确定执行区间，按固定地址准备，并在分离后检查执行权限；所需行为由现有运行和失败场景检查决定。

## 影响

JIT 协议检查可在 Mac 上运行，iOS 的实际映射权限、调试器分离和侧载安装条件需要真机验证。设备和构建信息必须与运行结果一起记录。
