# 决策记录: 用户数据 TBI 与原始 Scudo

状态: implemented

## 问题

[稀疏客体实验](../../implemented/architecture/2026-11-12-稀疏客体地址与原始Bionic.md)已使 SDK36 r07 原始 libc 的 8.25 GiB 预留成功，随后在 `main` 前访问带 `0x02` 顶字节标记的地址并收到 SIGSEGV。两入口的实际 PC 对应原始 libc ELF 地址 `0x5f0a8`，位于 `scudo::Allocator<AndroidNormalConfig>::allocate`。二进制在 `0x5f084` 把 `0x0200000000000000` 合入 `x11`，`0x5f0a8` 执行 `stur x8, [x11, #-16]` 写 chunk header。所测 libc Build ID 为 `2445fc73ede03b9536eef49355aff375`，SHA-256 为 `d3f8599b8b3f00101a31f94ac170ceb5875ee8446c201cb18382b2e02df84301`。

本地固定 Scudo 源码 `standalone/combined.h` 的 `addHeaderTag` 使用 `addFixedTag(Ptr, 2)`，与这次二进制指令对应。Bionic `malloc_tagged_pointers.h` 的公开堆指针固定标签为 `0xB4`，需 `libc_init_mte.cpp` 的 `PR_SET_TAGGED_ADDR_CTRL` 成功后启用；这是另一项 ABI 条件。当前 LKL 未定义 SET/GET_TAGGED_ADDR_CTRL，沿用 `kernel/sys.c` 默认 `-EINVAL`。

## 决策

### 语义范围

先实现 AArch64 Linux 普通用户数据访问的 TBI：地址转换忽略位 63:56，保留位 55:0，再按现有客体范围、页权限与 RAM 偏移检查。保持客体寄存器、指针计算结果和写回地址的原始值；故障诊断继续记录原始带标签地址。`p + 2^48`、低地址空洞、guest_end、越界及溢出继续失败。

取指访问保留独立处理，不对 PC 应用数据地址转换。MTE 标签存储、同步/异步标签故障不在本阶段实现，HWCAP 不增加 MTE。内核 tagged-address ABI 的 prctl 继续拒绝；`write`、`openat` 等传入带标签用户指针仍按现有内核规则返回错误。后续另行实现线程状态、fork/clone 继承、exec 清除、用户复制与内存管理参数的不同规则。

这些边界来自本地 Linux 源码的 `Documentation/arch/arm64/tagged-pointers.rst`、`tagged-address-abi.rst` 与 `arch/arm64/include/asm/uaccess.h`：普通用户地址翻译的 TBI 默认存在；需要内核访问的 tagged 用户指针由线程 prctl 启用；`mmap`、`brk`、`mremap` 新地址等参数保留例外。本阶段只改变执行器的数据地址翻译。

### 最小实施

Direct 增加明确的用户数据 TBI 状态位。`--data-tbi 0/1` 默认 `0`，脚本传入 `NCE_TRANSLATION_DATA_TBI`；开启后 Linux 翻译入口设置该位。启用实验参数要求单 CPU，并拒绝 read-view；默认关闭保留既有单/双 CPU 和 read-view 路径。独立执行器默认行为保留。flat 上界判断、PTE stub 和 C++ 数据页回调使用相同的 56 位数据地址，原始地址继续用于寄存器与故障报告。高地址仍可超过 flat 覆盖区并进入现有 PTE 查询。缓存映射在 TBI 状态变化后清空，防止带标签映射跨模式复用。Unicorn 建立 tagged 数据项后记录缓存状态；下一次相关映射变化执行完整 TLB 清理并清除该状态，未建立 tagged 项的运行继续按页失效。tagged 数据项去除执行权限，取指需独立查询。

Unicorn 软件 TLB 回调区分读写与取指，仅将数据地址转换后查询 PTE；缺页请求用无标签地址完成 Linux 页处理，诊断保留原始地址。检查 Unicorn 的地址缓存及回退指令行为，不能只测 Direct 已支持的整数访问。跨页回调、DC ZVA、普通/原生独占访问均需保持同一数据地址语义。read-view 暂时拒绝与该状态位组合，后续需要单独核对 Mach fault 到原始地址的恢复。

候选在 `work/offline-stock-bionic` 的 `codex/offline-data-tbi` 分支，从 `4daada27a2b38081adc6db1ba5db52829b0cadc1` 开始。沿用 sparse 的内核与原始四文件输入，主树只增加本提案。标准 VM、4 KiB 客体与 ART 候选分别推进。

在 Apple M5 Ultra、macOS 27.0、构建 `26A428` 上完成功能验证。Linux 使用 16 KiB 客体页、1 GiB RAM、单 CPU、128 MiB 翻译缓存、dual 代码内存、timer 抢占和按页代码/TLB 失效。Direct Linux 组启用 flat、code-watch、跨页处理和原生独占，关闭跳转复用、访存分组、vector-table 与 simd-math。各组 CLI/GCD 独立启动一次；执行期间有其他功能构建，本轮没有性能比较。

独立 Direct 检查覆盖 cached、refill、PTE、flat 的低/高地址，标签 `0x02`、`0xB4`、`0xFF`，原始寄存器与 NZCV、post-index 写回、跨页与跨 flat 上界、DC ZVA、权限和范围失败、不同标签指向同一地址的独占访问、关闭 TBI 后的缓存失效，以及 tagged PC 的直接和间接取指失败。原生独占测试使用 PTE/flat；cached/refill 仍受已有返回宿主后独占监视失效约束。

`translation/tbi-guest.c` 的固定 `LDTR/STTR` 指令由 Unicorn 执行；报告中实际记录 `0xf8400949` 和 `0xf8000949` 回退计数。相同程序检查普通读写、跨页、`mprotect` 后首次写入、解除映射后首次读取、重新映射后的内容，以及 `p | 2^48`、位 55 的拒绝。sparse 组另在 `0x200040000` 执行这些检查。带标签读取代码页后再取指仍失败；数据 TLB 项没有执行权限。stderr 保留带标签的原始故障地址，例如 `0xff80000200040000`。

`PR_SET_TAGGED_ADDR_CTRL`、`PR_GET_TAGGED_ADDR_CTRL` 返回 `EINVAL`；带标签 `write/pread64/openat` 返回 `EFAULT`，合法无标签页内容保持。信号标签暴露规则、MTE、SMP 的 TBI 和 read-view 的 TBI 未在本阶段验收。

首次 sparse core 的所有功能记录通过，但报告初始化与清理各输出了一条 TBI 统计，唯一性校验拒绝该报告。移除初始化阶段的重复统计后重跑成功，原始结果留在 `work/native-linux-nce/tbi-sparse-core-v1`。最终参数接口变更后重新生成全部 Linux 正式报告；早期固定开启 TBI 的试验结果未用作最终构建身份。

`test_translation_tbi.py` 使用五份最终 core 报告，通过 262 项负例，覆盖配置缺失/重复/错误、错误布尔类型、缺失功能记录、零或无效回退计数、TBI 关闭后出现 tagged 统计、启用参数的不兼容组合，以及默认参数继续进入既有参数校验。`test_translation_guest_layout.py` 的 198 项负例、`test_stock_bionic.py` 的 7 项检查、定向格式检查、Python 编译和 `git diff --check` 成功。新增 Direct 源码按 `arm64-apple-ios26.0`、dual 配置编译成功，未运行 iOS 产物。

另一会话只读复核地址转换、独占地址比较、tagged TLB 状态与权限处理，未发现阻止当前单 CPU 候选提交的明确缺陷。标准 VM 候选的 IC IVAU helper 位于另一分支，合并后仍需检查其操作数的标签语义。

### 原始 SDK 组件结果

两入口均完成 `linker_help` 和 `dynamic`，成功进入 `main`，`page_bss`、`allocation`、`allocation_contents`、`thread_tls`、`dynamic_libm` 五项全部成功，动态子进程退出码为 0，`component_compatible=true`。Scudo 的 8,858,370,048 字节预留分别返回 `758775808`（CLI）和 `813694976`（GCD）；上下文各分配和释放 4 个。

运行使用 SDK36 r07 原始 `linker64/libc.so/libdl.so/libm.so`，四文件 SHA 与前两阶段相同。输入清单 `android36-runtime.json` 的 SHA-256 为 `4b1a45b0ee51725c68f1c29765958d0b60b45a5f2325bedfc61764cd49232249`。客体内核沿用 sparse 阶段的 `289128f342cbfb46278e3cb8e9daf9d51825c0aa804a7d71cd96c3e65316c722`；本阶段没有重建原始 libc 或 Scudo，也没有合入标准 VM 候选。

合并标准 VM/IC 修复、稀疏地址和原始 ART runner 后，主工作区 host、TBI 关闭的 core CLI/GCD 各通过 62 条检查，上下文 68/68 释放；sparse、TBI 开启的两入口各通过 68 条检查，上下文 69/69 释放。两组都使用单 CPU、Direct/PTE/flat、dual 128 MiB、timer、pages、code-watch、跨页和原生独占。包含每入口 27 个标准 JIT 用例；当前 cache 操作数使用无标签地址，带标签操作数的联合检查随后复现并修复了旧代码缓存未失效，见[缓存操作修复](../bug-fix/2026-11-12-带标签缓存操作数的代码失效.md)。两组只核对功能，没有性能对照或 iPhone 执行。

### 复杂度审查

按 reclaim-code-entropy 核对实际使用方。独立 Direct 的状态位由 Linux 实验入口启用，保留其他使用方的原始地址契约；`--data-tbi` 和 env 区分已验证的执行语义，默认路径继续支持现有配置。`tagged_tlb_active` 对应实际安装的 tagged 数据项，完整清理后重置；删除该状态会让按无标签地址区间失效遗漏 tagged 别名。跨页回调、汇编 PTE stub 与 flat 分支分别服务既有执行路径，均按同一个状态位执行，未新增地址转换框架。新增客体文件只负责数据 TBI 与内核 ABI 边界检查，复用既有运行器、配置记录和清理流程。

## 曾考虑的替代方案

- 重建 Scudo 并定义 `SCUDO_DISABLE_TBI`。项目旧 libc 已使用对应重建路线，本阶段需要保留原始 runtime 字节并验证 AArch64 数据地址语义。
- 清除所有高位。会改变位 55:0 的合法性检查，可能让非法地址访问低地址页，本阶段只忽略顶字节并保留完整范围检查。
- 同时接受所有 tagged syscall 参数。Linux ABI 区分普通数据访问、线程启用的用户复制和内存管理参数例外，本阶段先保持现有内核拒绝行为。

## 影响

64 GiB 稀疏客体范围配合用户数据 TBI 已满足本轮原始 SDK Bionic 的初始化与五项组件调用。原始 ART 可以在固定输入下继续开展标准 JNI 组件验证；ART 的低地址引用、内核 tagged-address ABI 和普通可执行映射仍需分别检查。当前输入没有要求启用公开堆指针标签，不能由 Scudo header 标签访问成功推导完整 tagged syscall ABI 已可用。

参数默认关闭。开启后仍限制单 CPU，并拒绝 read-view；未验证的 SMP 和 Mach fault 地址恢复需要单独验收。内核系统调用规则、MTE、HyperOS 4 KiB 加载、完整 Android 桌面、通用 APK 与 iPhone JIT/地址容量、持续性能和热状态均保留各自的验证范围。
