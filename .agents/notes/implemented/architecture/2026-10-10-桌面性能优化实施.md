# 决策记录: 桌面性能优化实施

状态: implemented

## 问题

用户要求基于[启动性能定位](../../implemented/testing/2026-10-10-桌面启动性能定位.md)深入检索并实施优化，新增埋点按需开启，并控制其性能影响。当前地址恢复和信号处理开销明显；ART 的 C++ 解释执行也需要进一步处理。用户已授权实现和本机对照，设备测试集中到阶段版本。

## 决策

实现已存在 Linux 页的数据映射快速恢复：仅在当前线程拥有 Linux CPU、当前 mm 与宿主窗口一致、PTE 存在且满足访问权限和访问/脏页状态时，在宿主信号处理期间恢复数据映射并返回原寄存器现场。该路径不分配新的 Linux 用户页、不等待 Linux 锁、不调度，也不处理代码页；其他情况沿用完整 Linux 缺页、COW、信号与返回流程。复用现有 PTE 和宿主映射记录，不新增每进程页缓存。支持关闭该优化以进行同构建对照。

同步将故障 PC 和系统调用分支区查找改用已有有序程序索引。可选统计记录 mm 切换、扫描页数、已有页与缺失页/COW、快速恢复命中、恢复页数；默认关闭，启用时累计并由现有日志线程每 10 秒输出。关闭状态不读取统计时钟、不更新 MM 原子计数及返回入口命中计数；扫描循环仍维护局部页数。手机“连接与日志”页新增默认关闭的“性能统计”，须在启动前开启。

随后按测量评估 ART：nterp 需适配高地址对象引用、方法调用、异常和 GC 栈扫描；boot image / AOT 需处理镜像引用、重定位、执行区登记和编译覆盖。先研究匹配版本的实现，分别验证，不将调低 JIT 阈值作为重复实验。当前完整系统阈值 16 已记录无收益。

### 实现与测量顺序

已有页快速恢复、二分查找及可选 MM 统计已实现。首轮 CLI/GCD/可见窗口分别完成 132/133/133 个命名检查，数据盘 clean。这轮先验证功能；完整桌面收益由下面的独立对照确认。

新的 MM 统计显示，完整启动早期累计 19,047 次窗口切换对应 307,791,419 次页表扫描；同时命中已有数据页快速恢复 4,232,847 次。随后在 demand/lazy 模式中实现只重查已有宿主映射，以及 `mm->context.accessed` 明确要求恢复的页面。其余页面的 installed 和 desired 均为零，本次切换仍保持缺页状态，无须遍历全部 VMA。沿用现有位图及页表，不增加页面缓存；diff/full 模式保持原扫描方式。页数、权限和 COW 的对照必须确认这一收缩条件。

用户提供的[性能风险与验证](../../proposed/architecture/2026-10-10-HyperOS性能风险与验证.md)继续作为范围依据：R1 地址空间为本轮实现项，R4 ART 已核对匹配源码并保留后续适配；R2 多核需要先解决同地址窗口并发，R5 图形传输与 R6 内存容量按新的实际交互测量安排。已失败的热页表和批量视图结论继续保留。

### ART 与映射的后续取舍

匹配 Android 16 的 `runtime/interpreter/mterp/arm64ng/` 中，对象字节码会从 32 位 DEX 寄存器直接形成地址，并使用 `UNPOISON_HEAP_REF` 读取对象字段；本项目的引用需要加上 `nce_art_reference_base`。适配范围包含对象/数组操作、方法接收者、Quick/JNI 参数和返回值、异常与 GC 引用栈，以及标记寄存器约定。已有 NCE JIT 使用的寄存器和 Mark-Sweep 配置也须一起核对。先完成当前映射对照，再以解释执行占比决定是否进入这项实现。

另一候选是把撤销数据映射从固定匿名 `mmap(PROT_NONE)` 改为 `mprotect(PROT_NONE)`。当前空闲 RAM 回收会替换 RAM backing 和 Linux direct-map 两个视图，若旧用户别名仍引用原物理对象，可能保留已回收内容的物理存储；因此本轮继续解除原映射。采用保护修改前需设计旧别名释放条件并测量实际 footprint，不能仅比较单次系统调用耗时。

## 曾考虑的替代方案

- 再扩大预恢复热页缓存：此前 512 页缓存和批量数据视图已增加完整系统成本，先统计实际故障类别。
- 在信号处理器里执行完整 `handle_mm_fault`：可能分配 Linux 页面、加锁及调度，保留为普通缺页路径。
- 直接启用 nterp 或去掉 restricted 编译条件：当前对象引用编码及部分 IR 尚需适配，须完整处理和回归。
- 一次修改 nterp、AOT、地址空间和调度器：无法确定收益和失败归属，按依赖关系分阶段集成。
- 每事件输出 trace：事件数量达千万级，采用可关闭的累计统计。

## 影响

默认启用已有页快速恢复和减少扫描，保留关闭开关供对照。验证覆盖 fork/exec、COW、共享页、mprotect、取消映射、栈增长、信号和代码更新，以及 CLI、GCD、完整桌面和持久数据。以下结果区分带统计的诊断轮次与关闭统计的启动对照。

### 整合后的关闭统计对照

相同主机、宿主二进制、内核和系统镜像；已有数据盘沿用，未清除宿主文件缓存。两轮均关闭 `NCE_MAP_PROFILE`、故障逐项日志和 ART 线程栈采集。基准设置 `NCE_DIRECT_FAULT=0 NCE_SPARSE_SCAN=0`，优化轮将两者设为 1。程序二分查找在两轮都已启用，因此本表只对比两项 MM 改动。

| 测量范围 | 关闭两项 MM 优化 | 开启两项 MM 优化 |
| --- | ---: | ---: |
| 宿主进程创建至 `android_desktop_ready` 日志输出 | 168.914 s | 118.191 s |
| system_server StartServices | 32,338 ms | 22,901 ms |
| SystemUI StartServices | 76,499 ms | 13,257 ms |
| Launcher Displayed | 82,316 ms | 41,832 ms |

本轮桌面就绪等待减少 50.724 秒，约 30.0%，时间比为 1.43。两轮均正常退出，没有输出可选统计，也未记录 Java 主线程崩溃或 ANR。优化窗口实际完成上滑打开应用列表和主页返回。单轮结果不能描述长期分布；本次也未测连续交互帧时间和热状态。

总时间从 `libproc` 的宿主进程创建时间计至最后一条桌面就绪输出落盘，包含 JIT 内存准备、系统启动和桌面检查。首轮外层采集脚本最初匹配了错误的 phase 名；发现后用仍在运行的进程创建时间和刚写入的就绪日志时间恢复该值，并核对末行确为 `android_desktop_ready`。随后修正为 session 字段，优化轮自动采集。计时辅助代码和哈希、原始日志及计时 JSON 的位置均在结构化结果中记录。Android 自带组件计时独立保留。

### 可选统计的含义

通过 Mac 的 `NCE_MAP_PROFILE=1` 或手机“连接与日志”中的“性能统计”启用。默认关闭；Mac 显式设置 `NCE_MAP_PROFILE=0` 也会关闭。统计只在启动前选择，沿用日志线程每 10 秒输出，退出时补一份 MM 累计值。各字段独立原子读取，报告没有跨字段的一致快照保证。

| `linux_mmu` 字段 | 范围 |
| --- | --- |
| `switches` | 当前宿主窗口所属 mm 的变更次数 |
| `scanned_pages` | 刷新窗口时检查候选地址 PTE 的次数；重复查询累计，空页表区域仍可跳过 |
| `present_faults` | 普通缺页流程开始时已有有效 PTE，且满足本次读写权限；仍可能需要更新访问位、脏页或其他 Linux 状态 |
| `linux_faults` | 普通缺页流程开始时没有有效 PTE，或写访问需要处理只读 PTE；包含缺失页和 COW 等情况 |
| `fast_faults` | 信号处理期间已有数据页恢复成功次数 |
| `restored_pages` | 快速恢复与普通缺页恢复安装的页数；重复恢复累计 |

统计没有逐指令日志，也没有新线程。`host_mapping` 保留原有 Mach 操作墙钟计时，包含宿主调度等待。关闭统计后的完整启动另行测量；带统计的轮次用于定位调用次数和成本。

### 复杂度审查

按 reclaim-code-entropy 检查本次执行入口与状态：

- `installed`、`desired`、`view_chunks` 和每个 mm 的 `accessed` 继续承担原有映射职责；减少扫描直接复用这些记录。另建热页表会重复页面状态，未采用。
- 快速恢复仅由受控客体指令的 SIGSEGV/SIGBUS 入口调用；共享的缺页函数通过一个新标志选择该路径。没有新增第二套页表、任务调度器或进程生命周期。
- `nce_mmu_profile` 的实际使用方为 Linux 计数、宿主日志和离线分析；只有启用统计才向内核提供指针。独立头文件使宿主与内核共享字段布局，去掉它会产生两份 ABI 定义。
- 两个优化开关用于同构建消融对照；原 VMA 扫描仍供 full/diff 使用。移除这些路径会缩减现有运行配置及对照条件，当前保留。
- 寄存器检查复用原信号测试的初始化与断言宏；新增用例在 64 次进程切换后读取私有页，并检查通用寄存器、guest x18、NEON、NZCV、FPCR 与 FPSR。其目的为发现返回现场损坏，检查实际状态，不检查函数实现形式。
- 手机统计开关仅保留本次应用进程中的一个布尔值，启动后禁用，避免运行过程中改变计数条件。没有另建设置持久化或日志线程。

### 剩余风险

宿主信号处理只恢复已有 Linux 用户页，不调用 Linux 页面分配、锁等待或任务调度。Mach 映射仍可能涉及宿主内核工作及调度等待。PTE 权限、访问位、脏页与 COW 处理必须保留，代码缓存恢复也有独立生命周期。Mac 上信号恢复成功仍需在阶段 IPA 验证 iOS；该条件不阻止本机能完成的开发。

### 后续开发顺序

N4-D2 已完成默认关闭统计的对照与集成包。下一轮针对剩余启动时间补充已登记 ELF 和 ART 代码的采样归属，分别确认解释器、字节码验证、编译和系统服务等待。统计应继续按需启用，采样文件在会话结束后离线解析。

若未编译方法的解释执行占主要部分，再实施 nterp 的完整高地址适配；若大量时间用于每次启动的类/方法准备，再实施匹配修改版 ART 的 boot image 与 AOT。两者均保持 JNI、Java 异常、GC、对象/数组和跨进程回归。R2 多核需要新的地址空间并发约定；R5 图形和 R6 资源则需要真实交互帧时间及手机内存/热状态，继续由性能风险记录跟踪。
