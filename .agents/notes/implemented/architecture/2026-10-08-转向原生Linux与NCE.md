# 决策记录: 转向原生 Linux 与 NCE

状态: implemented

## 问题

旧 QEMU 路线经过多轮执行、访存、代码缓存与图形优化，完整 HyperOS 的交互仍未达到用户要求。用户希望获得可能接近硬件虚拟化量级的改善，允许大规模架构改动，并要求对高投入方向做实际调查。

本记录于 2026-10-10 补录。主会话在 2026-10-08 19:39 要求广泛评估并结束低收益工作，20:07 明确要求实现原生 Linux 内核与 NCE 的可行性原型。来源为[主会话](codex://threads/01a114af-bacd-73d3-b151-61eda7486078)及[QEMU 阶段结束评估](2026-10-08-QEMU性能路线结束评估.md)。

## 决策

采用宿主原生编译的 Linux 6.12 LKL，并扩展用户进程、内存和异常执行支持。Android ARM64 用户代码通过 NCE 执行，必须处理的系统调用、TLS 与平台指令经过适配。Linux 继续管理进程、文件、内存、futex 和 Binder；图形使用 gfxstream 与 ANGLE Metal。运行所需组件在 iPhone 内完成工作。

实施按可运行阶段推进：Darwin/iOS 执行条件、Linux 用户进程、Bionic 与 Binder、ART、系统图形和真实桌面，再验证 HyperOS 厂商组件。当前用户已经选择真实 Android 桌面方案 A，具体验收见[桌面提案](../../proposed/feature/2026-10-09-Android可交互桌面.md)。

### 已获得的结果与边界

- 早期 iOS 原型已确认固定准备的代码地址、代码更新、普通数据重映射及 Linux 进程执行，见[原型记录](2026-10-08-原生Linux与NCE原型.md)。
- N3-S5 已在 iPhone 17 / iOS 27.2 通过 97 个不同名称的测试；N4-G1 已通过 102 个命名测试，并使用 Apple A19 GPU。结果见[Android 阶段](2026-10-09-Android用户态与Metal阶段记录.md)。
- 后续标准 EGL、缓冲区、Composer 和 SurfaceFlinger 的合成像素检查已在 Mac 完成。完整 Android 桌面和新路线 HyperOS 的持续交互表现尚待验证。

implemented 指执行路线已采用且已有实现，完整产品的可用性仍按对应提案验收。受控循环与直接执行接近，只描述该计算负载；整机收益由实际系统测量决定。

## 曾考虑的替代方案

| 路线 | 当时结论 |
| --- | --- |
| 继续 QEMU 局部缓存、指令和访存优化 | 已有局部收益，M33 完整系统仍未达到目标；结束该轮优化，保留源码与实验记录 |
| HVF、系统级修改或直接启动 Android | 在当时核对的 iPhone 17 / iOS 27.2 普通侧载条件下，缺少已经运行验证的访问路径；该结论有设备与时间范围 |
| 仅运行 Android 应用的兼容层 | 用户当前选择完整 Linux / Android，范围已明确 |
| Mac 与 iPhone 联合承担运行 | 用户要求手机独立运行 |
| 因原生内核移植工作量大而结束调查 | 用户明确允许大规模修改，并要求可行性原型；选择依据转为可验证的运行条件与整体收益 |

详细接口调查及其他候选保留在[执行架构调研](2026-10-07-HyperOS执行架构调研.md)。这份记录不重新宣称第三方项目的当前支持范围。

## 影响

项目需要承担 Linux 宿主接口、ARM64 ABI、代码授权、ART 地址适配、Android 服务与图形集成的维护。现有单 CPU 和共用地址窗口会影响多进程成本，需要按真实负载评估。后续可能需要重新设计这些部分，具体条件见[性能风险与验证](../../proposed/architecture/2026-10-10-HyperOS性能风险与验证.md)。

旧路线结束的历史结论与本次新路线采用分别保留。源码、测量条件和失败原因可用于后续比较；大文件按用户要求管理，当前开发以本地构建产物为准。
