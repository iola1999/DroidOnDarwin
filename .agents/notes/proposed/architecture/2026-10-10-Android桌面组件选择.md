# 决策记录: Android 桌面组件选择

状态: proposed

## 问题

当前 API 36 SDK 的 PixelConfigOverlayCommon 为 Smartspace、ContentCapture、预测和搜索配置了 com.google.android.as 的服务，当前系统未安装这些服务。实际 Launcher 启动后反复绑定失败，system_server 记录 Slow dispatch。Pixel Launcher 同时请求缺席的 Google 搜索提供者。此依赖组合增加了完整桌面验证中的后台工作。

## 提案

采用 Android SDK AOSP API 36 revision 2 的原版 Launcher3QuickStep，并携带现有同版 SDK 的 com.android.launcher3 权限配置。移除 Pixel 的 Framework 配置覆盖，让 framework-res 原有 config_recentsComponentName 使用 com.android.launcher3/com.android.quickstep.RecentsActivity，预测、内容捕获等组件回到其原有默认值。保留现有 Framework、应用、SystemUI 和底层库。

来源为 Google SDK 仓库的 arm64-v8a-36_r02.zip，810,736,863 字节，SHA-1 为 62ad6714df790f89c8a8ad32552ffe20bb16fe87；Launcher APK 的 SHA-256 为 6cc60c3bc96317097579445d5b71d7d2604d68a3163025e2f121367ed3dc0f8f。构建时核对归档和目标 APK，提取后清理临时镜像。新 APK 包名为 com.android.launcher3，目标 SDK 36，原签名保留。

## 曾考虑的替代方案

- 同时替换 AOSP SystemUI：两个 SDK 的 SystemUI 签名不同，需要进一步核对平台权限与持久包信息，当前先保留已运行的 SystemUI。
- 加入缺失的 Google 服务：会增加产品当前不使用的应用和依赖，本阶段目标为完整 Android 桌面与本地应用。
- 新建资源覆盖 APK：当前 framework-res 已包含 Launcher3 的最近任务组件，删除 Pixel 配置覆盖即可先做对照，暂不增加自建覆盖包。

## 验收标准

实际 Home 和 Recents 使用 Launcher3；原版 SystemUI 能启动；桌面触摸、滑动、应用启动与切换通过。时钟数据和 Keystore 继续跨运行保留。核对先前的 AiAi 绑定重试，记录冷启动与实际交互，性能变化以运行结果为准。

## 风险

两个输入同为 API 36，但 Launcher 使用内部 Framework 接口，需要完整运行检查。移除 Pixel 覆盖可能改变导航、显示或服务默认配置，必须通过可见窗口复核。当前变化不扩大方案 A 的产品范围。

### 首次组合检查（2026-10-10 07:55）

移除 Pixel 覆盖后，Framework 的模块元数据配置恢复为 com.android.modulemetadata，现有镜像只包含 com.google.android.modulemetadata。PackageManager 未能读取模块元数据，system_server 在 getInstalledModules 时抛出 IllegalStateException 并终止。下一轮同时采用 AOSP SDK 的 ModuleMetadata APK；该组件保存系统模块元数据，继续核对实际加载。相比新建并签名资源覆盖 APK，此选择复用 SDK 已有组件与 Framework 默认名称。

08:00 的本机组合已加载 AOSP 模块元数据，SystemUI StartServices 用时 21,804 ms；上一轮 Pixel 组合为 87,172 ms。两个轮次均使用 demand、1 GiB RAM 和 JIT 阈值 1024，数据盘经过前序运行，尚非完整性能基准。AiAi 默认服务绑定重试已消失。本轮尚未完成 boot_completed：Launcher3 的 Home Activity 需要用户解锁，镜像未携带 Settings 中可在解锁前启动的 FallbackHome，因此 WindowManager 反复报告 No home screen found，用户仍处于锁定状态。按 [AOSP FallbackHome](https://android.googlesource.com/platform/packages/apps/Settings/+/refs/heads/android16-release/src/com/android/settings/FallbackHome.java) 的启动关系，加入现有同版 SDK 的 SettingsGoogle APK；其 FallbackHome 等待用户解锁后结束，让正常 Home 接管。继续验证实际启动和数据保留。桌面截图检查的目标包名也同步为 com.android.launcher3。

AOSP ModuleMetadata APK 的 SHA-256 为 6c433bbf5663c51f1082d48252a252b5b4eff265747fca873ac70566f428248d。两个 APK 使用同一固定 SDK 归档，构建共用提取和哈希检查，打包携带对应 NOTICE。临时归档和分区镜像在提取后清理，保留所需输入文件。
