# 决策记录: 原始运行库稀疏布局打包

状态: proposed

## 问题

主线 `d17162f` 的原始 SDK36 运行库候选已完成 sparse、TBI、Direct flat 的 CLI/GCD 桌面和同盘数据恢复，报告为 `work/native-linux-nce/stock-runtime-special-mapping-desktop-v1/summary.json`。`translation_package.py` 仍要求 host 布局，并从固定 `work/native-linux-nce/processes/system.img` 选择系统盘。原库候选及独立基准的验证结果尚未进入应用包。

`RunConfiguration` 从包内 `Runtime.json` 校验执行器与 CPU；`LocalRuntime` 设置系统盘和用户配置，再调用 `nce_lkl_run`。`TranslationConfiguration.environmentKeys` 尚未包含 `NCE_TRANSLATION_GUEST_LAYOUT` 和 `NCE_TRANSLATION_DATA_TBI`，包内执行 metadata 也没有这两个字段。当前参数传递无法复现已通过的 sparse/TBI 配置。

## 提案

系统盘从通过 CLI/GCD 的桌面报告选择。报告含原库候选时，重新校验候选清单并使用其中的已验证系统盘；其他报告使用自身摘要清单中唯一的系统盘。保留源码、生成物、数据种子、持久化、图形、应用和退出检查，不从默认目录补入不同构建的系统盘。

`Runtime.json.execution` 增加来自验证报告的 `guest_layout` 和 `data_tbi`，并将执行参数纳入运行组件标识。系统盘和执行参数的不同组合具有各自标识；导入设备继续由现有启动前标识检查处理，数据盘和设备记录保持原值。缺少这两个字段的现有 metadata 沿用 host 和关闭数据 TBI 的既有默认行为。错误类型、未知布局及未经验证的 CPU/布局/TBI 组合在准备数据盘之前返回错误。

这两个字段由包内运行组件提供，用户配置继续只记录已有选项。启动入口从同一资源检查取得实际环境变量，Mac 父进程与实际 worker 使用相同参数；加入现有环境清理列表，防止继承其他运行配置。现有 Direct flat、缓存、失效、预编译限制、线程入口与目录锁继续生效。

在独立 `work/stock-runtime-package`、`codex/stock-runtime-package` 中实施，以 `a677dd4` 为起点。先用实际桌面报告检查资源选择与 metadata，再验证真实宿主参数传递、无效 metadata 失败和数据保持。通过后生成 Mac 应用和 iOS 包；本阶段不安装或测试 iPhone。当前完整桌面仅有 16 KiB 的本轮结果，HyperOS 4 KiB 全系统由对应工作树继续推进。

## 曾考虑的替代方案

- 继续只生成组件运行库：已有原库桌面已通过，应用仍缺少实际参数传递，无法交付同一运行配置。
- 给地址布局和 TBI 增加用户选项：这两个字段属于已验证运行组件，额外选项会允许用户选择与包内构建不一致的组合。
- 把原库候选写回默认系统盘：基准仍用于原生 NCE，也有独立来源和已有数据，保留已核验候选即可完成资源选择。
- 保存另一份运行组件配置到设备记录：包内 metadata 已提供执行参数，重复保存需要维护两份状态；导入记录继续只保存现有运行组件标识。

## 验收标准

1. 实际原库桌面报告的系统盘、数据种子、资源和输入摘要核对成功；缺失、变化、多个未确定的系统盘及候选身份变化均被拒绝。
2. host 默认 metadata 和 sparse/TBI metadata 的实际启动参数符合各自配置；Mac 父进程与 worker 传递相同值。
3. metadata 类型错误、未知布局及不支持的组合在核心调用和数据盘准备之前失败，既有导入版本检查与目录锁回归成功。
4. Mac 宿主完整启动、桌面、退出和同盘重启成功；iOS 构建与包内文件摘要核对成功。原始 APK 保留签名字节，设备运行与持续性能注明待验证。
5. 按 reclaim-code-entropy 核对实际使用方、metadata 和用户配置的职责，保留一份运行参数来源；文档、注释与提交描述按 humanizer-zh 审阅。

### 实施与本机边界检查

在 `a677dd4` 上完成系统盘选择、执行 metadata 和宿主参数传递。`RunConfiguration.environment(validating:)` 合并资源检查与实际环境变量取得，Mac 管理进程与 `LocalRuntime` 都在准备数据盘或创建运行进程之前调用。新增解码结构只读取运行参数，不保存到设备或用户配置；缺失字段沿用 host/关闭 TBI，显式 `null`、数值代替 Bool、无效布局和多 CPU 组合会失败。

候选通过现有 `prepare_stock_android.verify` 重新核对，与桌面报告完整记录相同后选取镜像。其他报告需要唯一系统盘，内核和数据种子必须已列入验证摘要；同盘重启需要初始/最终摘要连续。构建结束后重新核对资源与构建输入，重叠输入的摘要不同也会失败。实际编译使用的两份宿主 ELF 头加入构建输入清单；当前文件已与桌面基准逐份比较，字节一致。

原有 Python 两类检查与 Swift 配置检查作为基线均成功。新增后 Python 七类检查成功，覆盖 host/low/sparse、TBI、身份变化、候选选择、未验证及多系统盘、编译前后文件变化和数据盘摘要连续。测试准备最初使用 macOS `/var` 临时路径，返回路径解析为 `/private/var`，两项路径比较失败；测试目录改为解析后的绝对路径后成功，产品路径检查保持原值。Swift 配置检查成功，覆盖六种有效配置、十五种错误字段或组合、旧 metadata 默认值与现有配置约束；完整应用编译与运行尚待完成。

按 reclaim-code-entropy 核对真实使用方，布局/TBI 的来源保留在包内 metadata，用户配置继续由现有结构保存。移除包内字段会使原库无法复现 sparse/TBI；另存到设备或用户配置会增加同步要求。资源检查直接返回启动所需值，两处启动入口均使用该结果。解码结构只负责 JSON 类型与旧字段缺省，保留资源输入和版本检查。

相对提案增加 iOS 的 `--output`，约束与 Mac 独立输出相同；新的包可保存在专属目录，已有 iOS 产物保留。新增构建输入记录和数据盘摘要连续检查用于本次固定构建交付。运行核心与已验证的 C 访存、信号、内核路径保持本阶段基准。

## 风险

本轮原库桌面继续使用已有服务启动和非隔离 namespace，原 init 的完整系统启动由 ASLR 及后续实际失败继续推进。新的运行组件标识会使已有导入设备按现行规则提示版本不匹配，原数据保留；内置数据盘跨版本兼容需要单独验证。iOS 地址预留、JIT 授权、资源、持续交互性能与热状态仍待真机验证。
