# 决策记录: Direct 向量查表执行

状态: proposed

## 问题

[后续提速评估](2026-10-10-后续提速与多核可行性评估.md)已包含 ART nterp、扩大 JIT、快速基线编译和 boot image 的实现与对照。当前继续检查双核 Direct 执行器。`work/native-linux-nce/lkl-direct-smp-services-resume/summary.json` 中，单轮服务负载的未支持指令计数包含 `0x4e020324` 1795 次、`0x4e010281` 550 次和 `0x4e0202c4` 243 次；三者均为 TBL。回退执行使用 Unicorn，双核实现会在回退期间取得共享执行排他锁。减少这类回退可能减少双核等待，收益需要负载对照确认。

## 提案

先只增加 TBL/TBX 向量查表指令，复用执行器已有的向量寄存器保存和原生指令生成。设置在创建执行器之前选择，同一二进制支持启用和关闭，默认关闭。请求配置、执行器实际配置和 benchmark 报告均记录该选项。编码范围依据仓库锁定版本的 Oaknut 指令定义核对，不扩大到其他 SIMD 指令。

## 曾考虑的替代方案

- 同时增加 PMULL 和标量 ADDP：服务负载也出现这些指令，但各自的边界和收益需要单独验证，本次先检查频次较高的查表指令。
- 全部未知 SIMD 编码直接交给宿主：包含未提供给客户系统的扩展、保留编码和宿主不支持的指令，无法保证异常行为。
- 直接替换默认行为：会失去同一构建的关闭对照。先保留实验设置，完整桌面对照后再决定默认值。

## 验收标准

- TBL/TBX 与 Unicorn 结果一致，覆盖 8/16 字节目标、1–4 个源寄存器、源寄存器环绕、目标/索引/表寄存器重叠、索引越界，以及向量高位和其他寄存器保存。
- 关闭设置时，执行器在指令之前返回未支持且状态保持完整；相邻保留编码继续返回未支持。
- 执行器边界及 Bionic/ART 在 CLI/GCD 中成功，配置记录与实际选择一致。
- 同一输入和构建交替测量开关，记录回退次数、阶段耗时及内存；完整桌面完成 Launcher、Clock、Files 和退出后才能评价桌面收益。

## 风险

服务指令频次无法预测完整桌面收益，内核同步、代码页保护和映射开销可能仍占主要部分。增加设置会影响配置契约，需同步检查请求与实际配置。此项仍属于独立 Direct 原型，尚未集成 iOS 产品。

## 实施与首版局部对照

已经接入 `NceDirectConfig.vector_table`、`NCE_DIRECT_VECTOR_TABLE` 和 `--direct-vector-table 0|1`，默认关闭。编码识别只接受 TBL/TBX 的 Q、长度、寄存器和扩展位组合；其他固定编码位继续校验。关闭时仍在原指令前返回未支持。没有新增向量寄存器副本、缓存或回退协议。

`python3 scripts/probe_direct_execution.py --mode tests --vector-table 1 --output work/native-linux-nce/direct-vector-table-tests` 的 CLI/GCD 检查成功，包含开关两侧的行为、两种目标宽度、全部源起始寄存器、表长度、重叠和越界索引。`benchmark_android_translation.py --comparison direct-vector-table --repeat 2 --reuse-engine-build --output work/native-linux-nce/android-direct-vector-table-matrix` 的八轮 CLI/GCD 成功。

局部对照使用 Apple M5 Ultra、macOS 27.0（26A428）、Clang `-O2`，双 Linux CPU、1 GiB RAM、16 KiB 页、2 ms 定时抢占，每 CPU 的 Direct 与 Unicorn 缓存各 128 MiB。flat、原生独占、跨页处理开启，普通数据复制允许并行；代码页信号跟踪、额外并行计时和代码校验复用关闭。ART 使用 nterp，expanded JIT / fast baseline 关闭，内存每 100 ms 采样。每个开关值四轮，使用同一二进制、内核与 Android 输入，CLI/GCD 顺序交替。

| 阶段耗时中位数，秒 | 关闭 | 开启 |
| --- | ---: | ---: |
| Bionic | 1.3788645 | 1.2747200 |
| ART | 1.7724990 | 1.6268745 |

该组中位耗时分别减少约 7.6% 和 8.2%。后续审查发现关闭设置时的编译发现范围仍受新指令分类影响，修复后必须重新测量；这组结果只保留首版观察。benchmark 已支持 `--workload android|services|desktop` 和 `--entry both|cli|gcd|window`；服务与桌面每轮创建新的测试数据盘，记录初始/最终摘要并检查正常卸载，桌面使用可见窗口和 Metal。首轮完整桌面对照在准备阶段主动中止，原始日志及原因保存在 `work/native-linux-nce/desktop-direct-vector-table-matrix/aborted.json`，未将其纳入性能比较。

## 后续测量

前一轮完整桌面中，两 CPU 的代码内容比较分别为 162,736,503 次和 213,949,930 次。已有 `reuse_code_checks` 可以在一次执行调用内复用权限和内容检查；此前单核 Bionic/ART 未显示稳定收益，默认关闭。双核现在由执行登记、PTE 更新停止协议和共享代码标记维持该调用内的映射及代码内容，完成当前查表对照后单独检查这个现有选项。先测量已有设置，再判断是否需要新增跨调用代码版本状态。


### 关闭设置时的编译范围

首版只在生成单条指令时将关闭的 TBL/TBX 转为未支持，前面的基本块发现仍按已支持指令继续扫描，可能提前编译后续指令并改变代码缓存占用。现在让基本块发现、入口标记与指令生成使用同一局部分类函数。新增检查在未支持指令后放置一页 NOP，对照未定义指令与关闭的 TBL；两者必须生成相同大小的回退代码。这个检查覆盖关闭组的编译边界，现有完整状态对照继续覆盖运行行为。修复完成后重新运行局部与桌面对照。


### 修复后的局部对照

`work/native-linux-nce/direct-vector-table-final-tests/summary.json` 的 CLI/GCD 检查成功，包含关闭设置时的编译边界。`work/native-linux-nce/android-direct-vector-table-final-matrix/summary.json` 的八轮检查也成功；环境、负载和顺序与首版相同，使用修复后的同一构建。

| 阶段耗时中位数，秒 | 关闭 | 开启 |
| --- | ---: | ---: |
| Bionic | 1.3213960 | 1.2935570 |
| ART | 1.6318725 | 1.6390475 |

Bionic 中位耗时减少约 2.1%，ART 增加约 0.4%，范围存在交叠。开启组一轮有 2650 次回退，其余三轮为 273、271、295 次；关闭组为 286、283、280、297 次。当前结果不足以确认稳定收益，默认继续关闭。完整样本与配置摘要见[结构化结果](../../../../experiments/native-linux/results-macos-vector-table.json)。启用后的完整可见桌面也已成功，结果见下节。


### 完整桌面与当前选择

`work/native-linux-nce/lkl-direct-smp-desktop-vector-table/summary.json` 完成 Launcher、Clock、闹钟、Files、持久数据和正常退出检查。环境与前述双核配置一致，TBL/TBX 开启，额外并行计时关闭；完整桌面执行为 292.644916 秒，清理为 0.819899 秒，100 ms 采样的 footprint 峰值为 3,579,105,264 字节。此前关闭 TBL/TBX 的关机修复轮为 292.446387 秒，两轮来自不同构建且未交替重复；这里只确认功能完成，尚无桌面提速结论。

当前保留默认关闭的查表实验选项，继续评估代码校验与跳转表。按 reclaim-code-entropy 审查，新增分类只用于识别 TBL/TBX，编译标志复用已有页缓存标志；实际调用方为独立检查、Linux 启动配置和同构建 benchmark。移除该分类会恢复 Unicorn 回退，关闭设置已经提供这一对照。没有新增向量状态、回退执行器或新的缓存。编译发现与代码生成共享局部分类函数，解决首版关闭组范围不一致的问题。benchmark 的新负载参数复用原有构建和验收入口，服务与桌面另外保留数据盘摘要及卸载检查。
