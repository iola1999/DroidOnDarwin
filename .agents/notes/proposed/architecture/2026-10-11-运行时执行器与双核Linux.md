# 决策记录: 运行时执行器与双核 Linux

状态: proposed

## 问题

双核原生 NCE 已确认同 mm 用户线程能够并行，完整 Android 仍在共享窗口切换期间产生大量映射和等待，详见[双核记录](2026-10-11-LKL双核用户态与映射同步.md)。单核 [Direct 执行器](2026-10-11-运行时ARM64代码块执行.md)已经用客体地址转换访问 RAM，并完成真实桌面检查；它具备为不同进程同时使用相同客体地址的实现基础。

上一项每进程只读映射没有显示稳定的桌面收益，且提高了内存峰值。下一阶段优先评估双核 LKL 与 Direct 的组合，继续沿用平坦地址表。不同进程的客体指针保持原值，每 CPU 使用当前任务的地址表与独立执行状态；减少共享窗口限制后，实际并行收益仍需完整系统测量。

## 提案

### 执行和同步约定

先固定两个 CPU，采用独立构建。每 CPU 拥有 Direct 和必要的回退执行器、代码缓存、当前任务状态与停止请求。任务迁移后使用目标 CPU 的执行器，任务只保存客体寄存器。Linux、RAM、文件和设备仍在同一宿主进程内，运行组件随手机包交付。

首先检查两个执行器同时编译和执行、相同客体地址下的私有数据、共享原子数据、独立抢占和代码更新。现有 Direct 用 LDAR/CAS 模拟独占访问；另一个 CPU 将值改动后恢复时，CAS 可能成功。增加原生 LDXR/STXR 候选，检查竞争重试、远端写入、地址变化、寄存器状态与执行边界。已有单核选项继续作为对照。

随后复用 LKL SMP 的 CPU 身份、IRQ、调度与 RAM 别名访问保护，增加按 CPU 发布的页表与映射状态。客体进入后，页表及代码映射必须在执行区间保持稳定；修改前请求相关执行器停止，确认离开后提交更新。退出执行区间先于任何可能等待 Linux 锁的操作，防止持锁方与执行器相互等待。初版可先停止全部两个 CPU，确认正确性后再按实际 mm 缩小范围。

每 CPU 的代码缓存可以独立编译与回收，共享物理代码的写入与失效仍需要跨 CPU 通知。原子指令和回退执行器必须使用同一 RAM，不能用互不共享的副本完成原子更新。当前只读宿主范围的信号处理只允许一个活跃执行者，本阶段使用 `flat`，该候选的并发改造不作为前置条件。

停止请求必须覆盖登记客体后、真正进入生成代码前的区间。检查该边界后再决定复用周期请求或增加持续停止标志；不能依赖一次可能被新执行入口清除的通知。计时线程只请求停止，执行器缓存仍由所属 CPU 修改。

### 参考与实施顺序

2026-10-11 核对 [QEMU MTTCG 文档](https://www.qemu.org/docs/master/devel/multi-thread-tcg.html)：每 CPU 的执行状态、跨 CPU TLB/代码失效和原子操作分别需要同步；其同步原语一节也记录了 CAS 模拟独占访问的 ABA 限制。本项目使用 ARM64 宿主，可直接评估硬件独占指令，实际行为由本机检查确认。

顺序为独立双执行器与原子检查、SMP/PTE 进入退出与核心 Linux 回归、Bionic/ART 和完整桌面，再进行同构建或明确构建变体的单核/双核对照。记录阶段耗时、每线程 CPU 时间、实际重叠、停止等待、代码缓存及内存平均值/峰值/最后值。微基准只确认并行与语义，完整系统结果决定产品集成。

## 曾考虑的替代方案

- 继续延长共享窗口的调度时间片：已有 12 ms 对照仅显示有限启动变化，双核完整桌面仍失败，无法消除两个 mm 共用相同宿主地址的问题。
- 继续扩大每进程只读宿主范围：首轮完整桌面的 footprint 峰值增加约一半，未显示稳定提速，先保留对照记录。
- 多个 Linux CPU 共用一个 Direct 实例并加互斥锁：会把用户代码再次串行执行，不满足本阶段并行验收。

## 验收标准

1. 两个独立执行器可以同时编译与执行，私有地址隔离、共享原子更新、TLS/x18/向量、定向停止和退出正确；CLI/GCD 均覆盖。
2. 原生独占指令处理竞争重试与远端写入，不将已失效的预留用于成功写入；明确记录跨宿主返回的允许失败行为。
3. 两核 Linux 的线程迁移、系统调用、信号、futex、fork/COW、mprotect/unmap、代码发布与正常退出检查成功；两个不同 mm 可以实际同时执行。
4. Bionic/ART 与真实 Android 桌面、Clock/Files、数据保留及干净关机成功；随后比较单核/双核耗时、交互和内存，不以线程数量或微基准倍数判定完成。
5. 本机结果通过后再推进 iOS 执行内存和 App 集成，集中交付有完整体验的阶段包。当前产品继续使用已验证的执行路径。

## 风险

每 CPU 缓存增加内存；过多全局停止可能抵消并行收益。代码写入、页表回收、宿主线程与 Linux CPU 迁移之间存在不同的生命周期。独占指令可在宿主调度后失败，生成代码必须允许正常重试；执行器之间的原子语义还需覆盖回退路径。Mac 并行成功后，iPhone 的 JIT 写保护、容量及热状态仍需验证。


## 实施进展

### 独立双执行器与原生独占指令

已增加 `NceDirectConfig.native_exclusive` 和 Linux 实验开关 `--direct-native-exclusive 0|1`，默认关闭。原生候选使用 LDXR/LDAXR、STXR/STLXR 和 CLREX；进入和离开生成代码时清除宿主预留。原来的 LDAR/CAS 路径保留为单核对照。共享普通数据可以并发访问，代码、地址表及引擎销毁仍由调用者保证生命周期；此时还未允许两个 Linux CPU 进入当前集成。

独立检查覆盖两个引擎同时编译、相同客体 VA 对应不同 RAM、共享计数的 8/16/32/64 位独占操作及两种顺序、TLS/x18/向量、代码替换与定向停止。另有两类 ABA 检查：客体返回宿主后，和客体一直在同一生成代码页等待远端写入期间。原生候选报告写入失败；LDAR/CAS 对照仍可能报告成功，保留这一差异用于验证测试的区分能力。

首版通过独立 CLI/GCD 和单核 Linux 核心检查，但 Bionic/ART 对照的原生候选触发 ART 内部 90 秒期限。该轮累计约 19.88 亿次代码查询与 19.88 亿次跨块返回；采样集中在生成代码入口、出口和代码查询。代码分析确认：原生预留会在返回宿主查询目标页时失效；两个目标发生跳转表冲突时，反复查询会使同一独占序列持续失败。原始日志在 `work/native-linux-nce/android-direct-native-exclusive-matrix/`，该轮按失败保留。

先实现同页控制流预扫描：从 LDXR 到 STXR/CLREX 只接受限定指令，其他片段从加载处整体回退。八轮 Bionic/ART 检查成功，但该规则使单轮回退次数由约 53 增至约 344,338，ART 阶段耗时中位数增加约 26.5%，Bionic 阶段增加约 33.7%。该预扫描已撤回；结果保留在 `work/native-linux-nce/android-direct-native-exclusive-local-matrix/`。

当前实现只增加每次执行调用内的 `exclusive_interrupted` 标志：持有客体预留期间返回宿主时设置；STXR 按硬件结果返回失败；下一次 LDXR 在开始新重试前返回 UNSUPPORTED，交由回退执行器继续。这样保留了程序已执行的副作用及当前寄存器，无须复制寄存器快照或回滚内存。新增两个 4 KiB 代码页相距 1 MiB、占用同一跳转表项的回归，要求第一次受中断的重试返回，且共享数据未写入。后续双核集成时，含回退执行器的区间需与其他客体执行互斥，直到其并发原子语义另行验证。

当前实现的独立 CLI/GCD 各 83 项命名检查、Linux 核心 CLI/GCD 及八轮 Bionic/ART 交替对照成功。关闭 `exclusive_interrupted` 更新的对照构建会在代码页冲突检查失败，结果保存在独立检查的 `negative-control/result.json`。完整 Linux 双核、完整桌面和 iPhone 均待后续接入，当前阶段没有新的整机提速结论。

### 本机测量

环境为 Apple M5 Ultra、macOS 27.0 / 26A428、Clang `-O2`。独立执行器使用每引擎 2 MiB 代码缓存、256 项跳转表、16 KiB 数据页和 `flat` 访存；每个线程执行 4,000,000 次数组更新。CLI 的墙钟耗时为 5.121 ms、两个线程 CPU 时间合计 10.217 ms、重叠 5.097 ms；GCD 分别为 5.086 / 10.156 / 5.074 ms。这些数据确认两个引擎实际同时工作，测量包含首次编译，仅覆盖独立数组负载。

Linux 与 Android 对照仍使用单个 Linux CPU、1 GiB RAM、16 KiB 页、2 ms 定时抢占、每执行器 128 MiB 缓存、256 项跳转表、`flat`、代码写入跟踪和跨页处理；跳转复用与访存合并关闭。Android 使用 nterp，expanded JIT / fast baseline 关闭。相同二进制交替开启和关闭原生独占，每种设置四轮，结果为中位数：

| 阶段 / 指标 | LDAR/CAS | 原生独占 |
| --- | ---: | ---: |
| Bionic 阶段耗时（ms） | 851.968 | 697.778 |
| ART 阶段耗时（ms） | 1242.235 | 1250.824 |
| ART footprint 平均值（MiB） | 253.898 | 252.750 |
| ART footprint 采样峰值（MiB） | 272.727 | 272.712 |
| ART footprint 最后值（MiB） | 270.384 | 271.259 |

最终这组 ART 耗时增加约 0.7%，内存峰值接近；此前相同实现的一组结果为增加约 0.4%。Bionic 两组结果的方向不同，先前为增加约 3.3%，最终为减少约 18.1%；当前样本不足以确认其稳定收益。最终每轮回退次数：LDAR/CAS 为 49–51，原生独占为 55–60，低于已撤回预扫描版本的约 344,338 次。

[结构化结果](../../../../experiments/native-linux/results-macos-direct-parallel.json)保留 12 轮结果、126 个输入与产物摘要；303 个内存样本已重新计算平均值、采样峰值和最后值。并行独立检查另有 `parallel_execution` 内存阶段；该阶段约 20 ms，在 100 ms 采样下仅取得阶段边界值，未覆盖瞬时 footprint 峰值。宿主进程 lifetime RSS peak 单独保留。

### 复杂度审查

按 reclaim-code-entropy 核对实际使用方：新增布尔设置由 Linux 实验入口和双执行器回归使用，并由 benchmark 同构建对照记录；没有新增产品设置、持久格式或另一套代码缓存。每引擎仍使用现有状态与缓存所有者，独立并发检查单独成文件，复用既有汇编负载、构建和内存采样。执行调用内的中断标志只用于结束受宿主影响的独占重试；删除它会恢复已观察到的重试停顿。已撤回控制流预扫描，减少了指令类别与范围判断。当前保留原 LDAR/CAS 对照，以便量化原生候选的开销与兼容性边界。
