# 决策记录: SDK36 原系统服务观察器

状态: proposed

## 问题

当前原 init 实验分别记录 first-stage 设备发现、挂载、根目录切换和原服务进度。完整系统启动还需要读取实际 `sys.boot_completed`，确认原 Zygote、system_server、SurfaceFlinger 和系统服务可用。一次属性设置请求或 `first_stage.completed` 只覆盖各自的观察范围。

raw first-stage 分支在恢复固定 ramdisk 后直接返回，随后原 PID 1 执行 `/init`；该分支没有消费 staging 的 `root/` 和 `files.tsv`。原 first-stage 新挂载的 `/dev` tmpfs 会覆盖 ramdisk 内预先写入的同名路径。当前无加密候选只声明 vendor fstab 的改动，观察器采用独立的 `/dev` 文件部署。

## 提案

本阶段已获主会话授权。tracked rc、POSIX shell 脚本和固定 payload 生成、导出验收模块已完成宿主检查。主会话已接入实际 guest syscall 部署、exec 后读回、`--sdk-system-observer` 入口与停止后的只读磁盘导出；原 PID 1 的部署与完整启动继续验证。

### 原 init 加载与部署位置

实际部署文件为 `/dev/droid-plain-init-wrapper.rc` 和 `/dev/droid-plain-system-observer.rc`。wrapper 按原 `LoadBootScripts` 顺序导入 `/system/etc/init/hw/init.rc`、`/system/etc/init`、`/system_ext/etc/init`、`/vendor/etc/init`、`/odm/etc/init`、`/product/etc/init`，最后导入 observer rc。原 Parser 保留各目录内的文件排序和嵌套 import；原配置的文件路径保留，vendor 配置继续匹配原 subcontext。`ImportParser::EndFile()` 在文件全部解析后才处理 import，独立 observer rc 保持观察器服务和 action 在原默认配置之后注册。

实验 cmdline 明确增加 `androidboot.init_rc=/dev/droid-plain-init-wrapper.rc`。原 PropertyInit 将该值写入 `ro.boot.init_rc`，原 `LoadBootScripts` 随后只解析 wrapper。固定 vendor 的 `plat_sepolicy_vers.txt` 为 `202504`，原 `ParseMountAll` 的延迟导入条件 `SelinuxGetVendorAndroidVersion() <= __ANDROID_API_Q__` 未满足。该 wrapper 契约限定于当前固定 SDK36 输入。

静态来源为 AOSP system/core 提交 `68be0c2c0006a0740d0b1809abe4717308f90d15`：`init/init.cpp:337`、`init/import_parser.cpp:47`、`init/parser.cpp:159`、`init/property_service.cpp:1390`、`init/util.cpp:521`。固定原 init ELF 包含上述加载路径和 `ro.boot.init_rc`。这些核对尚未验证实验 wrapper 的实际解析结果。

部署必须使用原 first-stage 的实际 namespace。部署入口为 raw original `/init` 的 PID 1 成功挂载 `/proc` 后：原 `/dev` tmpfs 已先建立，`/proc/sys/kernel/random/boot_id` 也可读取。集成使用已有 NCE `run_syscall`、单页 guest scratch 和 `copy_user(..., 1)`，用 `O_EXCL` 创建两份固定文件并赋予 `0644`、`root:root`；逐项读回 `statx` 与内容，临时映射解除后记录实际 boot_id。原 PID 1 后续成功执行 `/system/bin/init` 后再次读回内容和属性；策略加载后的 exec_index=3 还要求有效标签精确为 `u:object_r:tmpfs:s0` 加末尾 NUL。该两文件方案的实际部署继续验证。宿主 syscall 任务的根目录无法代替原 PID 1 的 namespace。

两个文件必须为普通文件，权限 `0644`，`uid=gid=0`。文件保持原 tmpfs 的有效标签。原 `SwitchRoot` 用 `MS_MOVE` 保留 `/dev` 挂载及其子项，原 `SelinuxRestoreContext` 对 `/dev` 本身只做非递归 restorecon。固定原初始化只递归处理 `/dev/block` 和 `/dev/dm-user`，固定 system/vendor/system_ext rc 也没有覆盖这两份文件的 restorecon。策略加载后的有效 SID 必须通过原 `fgetxattr` 读回确认；文件路径匹配的 `device` context 不决定未调用 restorecon 的 inode 标签。

### 观察器与文件接口

[rc](../../../../experiments/native-linux/translation/stock-init-system-observer.rc) 在实际 `sys.boot_completed=1` 后准备 `/data/local/tests` 和 `/data/local/tests/system`，两目录均为 `0701 shell shell`，与固定原 `init.rc:853/855` 一致，再 restorecon 并启动 disabled、oneshot 的 shell 服务。原 `/system/bin/sh -c` 使用 `u:r:shell:s0`，命令参数由 tracked 脚本正文生成。原 `plat_file_contexts` 将 `/system/bin/sh` 标为 `shell_exec`，将 `/data/local/tests(/.*)?` 标为 `shell_test_data_file`；原策略允许 init 执行 shell、转入 shell 域，并允许 shell 创建和写入该数据目录。APEX 默认 mount namespace 的实际选择仍需在运行中核对。

[脚本](../../../../experiments/native-linux/translation/stock-init-system-observer.sh) 在 `/data/local/tests/system/<boot_id>/` 写入 `result.incomplete.tsv` 和每条查询的 stdout、stderr。19 项检查覆盖首尾实际 `sys.boot_completed`、原 zygote 与 surfaceflinger 服务状态、zygote64/system_server/surfaceflinger PID、activity/package/window/input/lock_settings/SurfaceFlinger 的 Binder 注册、五条固定 `cmd` 查询和结束时的同一内核 `boot_id`。每条外部命令使用原 `/system/bin/timeout -k 1 5`；完成查询并成功 sync、rename 后，文件名变为 `result.passed.tsv` 或 `result.failed.tsv`。`input help` 只检查服务命令接口，输入事件和 APK 启动由后续阶段验证。

[Python 模块](../../../../scripts/stock_init_system_observer.py) 提供两个接口：`prepare(output)` 生成 `stock-init-system-observer-data.h` 与 `stock-init-system-observer.json`，清单声明两份固定 payload 的路径、字节数、SHA-256、权限、所有者和策略加载后的 SELinux 标签；`validate_export(export_dir, boot_id)` 验收调用方已经停止并导出的同一 boot_id 目录。`observe_deployment()` 核对原 PID 1 的部署、exec 后文件读回和同一 boot_id。SDK36 raw probe 调用上述接口，原 PID 1 的文件操作由 [C header](../../../../experiments/native-linux/translation/stock-init-system-observer.h) 使用已有 guest syscall 完成。tracked 脚本是生成命令参数的来源，其源文件 SHA-256 随清单保存。

脚本通过命令返回码和首行内容记录查询状态。宿主验收同时检查完整 stdout：PID 必须为正整数列表，window 的物理尺寸与可选覆盖尺寸必须为正整数，属性和 Binder 输出必须符合整条固定格式，成功输出必须有结束换行。脚本写出的状态与上述内容检查矛盾时，`validate_export` 抛出 `ValueError`；完整、内容一致的失败记录返回 `complete=True, passed=False`。stderr 保留为原始查询文件，验收返回值仅含状态、大小与 SHA-256。

### 使用方、状态与复杂度审查

payload 清单和 header 的使用方是主会话正在集成的 SDK36 plain raw-original probe，实际调用与部署仍待验证。实际读取方为原 PID 1 的 Parser 和原 shell。TSV 与查询文件跨越 guest 运行及宿主导出边界，宿主独立校验命令身份、格式和内容，不能只读取 guest 写出的 passed 字段。

`incomplete` 文件表示查询或最终写入尚未完成；最终文件名、完整结束记录和实际查询文件共同确定完成状态。boot_id 由部署调用方记录并传给宿主验收，阻止沿用其他内核轮次的目录。上述状态各自覆盖运行身份、查询完成和写入完成；模块没有另外维护启动、进程或磁盘恢复状态。

消融判断：移除 wrapper 会使 `ro.boot.init_rc` 指定的入口缺失，原目录也无法按声明顺序导入；提前写入 ramdisk `/dev` 会被 tmpfs 覆盖；移除 boot_id 比对会允许读取此前轮次的结果；移除查询文件内容验收会允许仅修改 TSV 状态；移除最终文件与结束记录校验会允许接受中断结果。实际 namespace、进程组回收与磁盘恢复继续由原启动流程负责，模块只提供固定数据格式和验收。

### 原 namespace 部署的首轮结果

`--sdk-system-observer` 只用于无加密原 init 的完整观察入口。两次 raw lifecycle 与 mounted-partition recovery 不注入观察文件。部署以原 `/init` 的 exec 计数、PID 1 及其成功的 `/proc` 挂载为条件，临时 scratch 使用一页 guest 映射；脚本按可用字节分段，支持短写、短读和 EINTR。文件使用 O_EXCL 创建，显式设置 mode、uid/gid 和 SELinux 标签，随后逐项 statx、内容和标签读回。SELinux xattr 保留末尾 NUL，与当前原文件元数据及运行器既有 setxattr 一致。临时映射解除后记录实际 boot_id；PID 1 后续成功 exec 原 init 后再次读取文件、内容和标签。

v7 的 CLI/GCD lifecycle 成功，CLI original 首次部署了三份文件，共 5642 bytes；200-byte wrapper、430-byte rc、5012-byte shell 的内容、`0644`、`root:root`、`system_file` 标签及 scratch 回收均成功。该次条件尚未区分启动辅助程序 `/probe-guest` 和原 `/init`；辅助程序也会先挂载 `/proc`，随后卸载并 exec 原 `/init`。部署提前执行，exec_index=1 后的 boot_id open 因 `/proc` 尚未建立而失败，宿主退出 -6，wrapper 为失败，26.776416 秒。GCD original 和 recovery 未执行，完整 boot 未观察。失败记录见 `work/sdk-plain-validation-v1/init-16k-v7.json` 和本轮 `summary.json`；两盘在停止前后摘要相同且为 clean，两个宿主组已停止，源码摘要保持。

修复使用既有 `stock_init_exec_count`：计数为 0 的 `/proc` 挂载不注入；原 `/init` 已执行后，匹配的实际挂载再部署。没有增加执行状态副本。宿主验收还要求唯一 raw exec_index=1 位于匹配挂载之前，后续 PID 1 exec 索引为正整数并严格递增，拒绝布尔数值、缺失、重复和顺序变化。v8 使用相同原内核及磁盘进行复验，当前内核尚无 BPF JIT，完整 boot 仍需处理原 NetBpfLoad 的失败。

实际固定 Linux `security/selinux/hooks.c` 的 `selinux_inode_post_setxattr()` 在策略初始化前保留无效标签状态；`selinux_inode_getsecurity()` 此阶段返回 EOPNOTSUPP，VFS 读取文件本身的 xattr。策略初始化后的标签与读取权限由后续原 init exec 读回确认，不能只依据首次 setxattr 成功。

### 两份 rc 与原 sh -c

主会话选择保持原加载顺序的两份 rc 方案，已实现并通过宿主验证。脚本继续以 tracked `.sh` 为生成来源，正文作为原 `/system/bin/sh -c` 的一个参数。wrapper 最后导入独立 observer rc；原 19 项查询、命令时限、同步和完成记录保持。已有脚本首尾读取实际 `/proc/sys/kernel/random/boot_id`，导出继续与部署记录的 boot_id 比较。

权限核对使用主仓库固定 `work/native-linux-nce/android/android36/etc/selinux/plat_sepolicy.cil`，SHA-256 为 `c3390caf754eb7924b638c9f1a156336e80391fae12afbccb56ba01faa790883`。合并 platform、`202504` mapping/genfs、vendor public/versioned/vendor、system_ext/product 及对应 mapping 共 9 份 CIL，完整展开 3096 个有赋值属性、3222 次赋值和全部 3685 条 file allow。init 对 `tmpfs:file` 的 read/open/getattr 来自 21219、21326，后者经 `base_typeattr_780:34292` 和 `fs_type:702` 包含 tmpfs；原 Parser 的 `ReadFile` 使用 open/fstat/read，所需权限已有。shell 对 `tmpfs:file` 没有读取 allow。kernel 可重赋的 file 类型仅有 `init_exec`、`snapuserd_exec`、`overlay_remounter_exec`，三者均缺少 shell 读取权限。因此保留实际 tmpfs rc，并由原 shell 从命令参数取得正文。

原 init 执行 `shell_exec` 并转入 shell 域的规则在 CIL 21093–21095，原 init self:setexec 在 21445。输出父目录由原 init 按 `plat_file_contexts:505` 设置 `shell_test_data_file`，mkdir 使用 `init/util.cpp:246–257` 的 setfscreatecon。init 的目录创建、属性和 restorecon 权限在 21288、21289、21298；shell 在该目录建立子目录和写文件的权限在 27804、27805。ext4 的 filesystem 类型为 `labeledfs`，文件 associate 规则在 16825；无适用的 shell dir/file 类型转换，固定 Linux 的 `security_transition_sid` 默认继承父目录对象类型。三组 `SHA-256(policy 原字节 + mapping/202504.cil 原字节)` 都与输入 sidecar、vendor precompiled sidecar 相符；预编译文件 SHA-256 为 `2ba00834f56ea900ac80657912e17639898eeaf17ce3ba716d7fd652a0783073`。上述核对针对固定来源，客体实际策略加载与执行结果继续验证。

原 `init/tokenizer.cpp` 在未加外层引号的 token 内解码转义。生成器逐字符编码反斜杠、空格、tab、LF、双引号和 `#`，每个 `$` 编码为 `$$`；`ExpandProps` 在 service exec 前展开一次并还原字面 `$`。原 quoted token 内不处理反斜杠转义，生成器使用单个未加外层引号的 token。当前 5012-byte 正文编码为 6091 bytes。原 Parser 和 ServiceParser 使用 string/vector，单参数内核限制为 `32 * PAGE_SIZE`，4KiB 配置为 131072 bytes，当前正文小于该限制。源码核对基于上述固定 system/core 提交，实际参数往返检查须编译原 `init/tokenizer.cpp` 并调用源文件中的 `ExpandProps` 实现。

部署清单使用 `contract=2`，TSV 仍使用原 `droid_plain_system_observer_v1` 格式。两份 rc 创建和 exec_index=2 读回只验内容与普通文件属性，`label_hex` 为空；exec_index>=3 的读回还必须包含精确的 `tmpfs` 标签及末尾 NUL。部署继续复用既有 flag、boot_id 和 init exec 计数，字节分段和 scratch 回收保持。早期重标记实现和对应失败报告保留为本记录的历史结果。

消融判断：原 shell 取得正文的途径改为现有 exec 参数，脚本仍由一个 tracked 源文件维护；两份 rc 分别负责默认 import 顺序和追加服务注册。策略加载前的字节、属性检查与加载后的有效标签检查分别使用既有 exec 计数限定。完整 boot 的验收条件继续由原属性、原服务和导出结果确定。

### 共享宿主进程观察

SDK36 raw probe 和独立 BPF probe 都需要观察实际宿主进程退出、日志限额与进程组回收。BPF 原有监督实现缺少观察器收到 SIGTERM 后的清理行为，本轮使用已经通过真实进程回归的实现，放入 `scripts/process_observer.py`。raw probe 导入 `observe as _observe` 与 `OBSERVATION_MAX_BYTES as _OBSERVATION_MAX_BYTES`，保留原调用签名、返回字段和日志读取限额；JSON 单行和记录数限额仍由原读取函数维护。

两个实际调用方共用同一个函数，实现只更名函数与常量，没有增加参数、运行入口或生命周期状态。原进程测试继续调用 `probe._observe`，patch 的 `time`、subprocess、os 和实际日志上限常量改为共享模块；JSON 读取测试仍 patch 原 probe 的读取限额。probe 和真实进程回归的来源记录同时包含共享 helper 的 SHA-256，原运行结束后的来源核对覆盖该文件。验证范围包括既有真实父子进程、中断与查询失败回归、观察上限，以及观察器部署顺序和原参数生成。

## 曾考虑的替代方案

- 直接增加 system 分区内的 rc 和脚本：可由原目录解析，但需要扩展当前 vendor-fstab-only 候选的修改范围，并核对 system 元数据与读取结果。本阶段采用 `/dev` 部署。
- 只在 staging `root/` 中增加文件：raw first-stage 分支未读取该目录。
- 只记录 `sys.boot_completed` 设置请求：缺少实际属性读取与系统服务检查。
