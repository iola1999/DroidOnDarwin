# 决策记录: Android 主页导航验证

状态: proposed

## 问题

完整桌面对照打开 Clock 后，后续 Files 操作未产生首帧。原有检查只验证输入提交和 evdev 事件，未覆盖离开应用后的主页导航。失败轮次保存在 `work/native-linux-nce/benchmarks/native-direct-desktop-comparison/0-native-previous/20261011-213323-f16972/summary.json`。

最初依据 `Generic.kl` 的键码解释尝试将 102 改为 172。实际运行日志随后确认设备加载 `/system/usr/keylayout/NCE_Touch.kl`，源码 `experiments/native-linux/services/NCE_Touch.kl` 已将 102 映射为 HOME。旧轮次在请求后确实启动 Launcher；修改为 172 的试验无法返回主页。这次判断遗漏了设备专用键表，修改应撤回。主页动画和自动操作时序仍需检查。

## 提案

保留专用键表的 102，宿主导航、benchmark 和客体 uinput 使用共享导航常量。完整桌面检查在 Clock 已显示后通过现有输入 socket 发送主页键，并确认 Launcher 获得焦点且完成首帧；打包要求包含该检查。自动化序列应等待主页转换完成，再打开应用列表和 Files。

## 曾考虑的替代方案

- 按 `Generic.kl` 改为 172：设备使用专用键表，试验导航失败，撤回该修改。
- 通过 Android activity 命令返回桌面：能够启动 Launcher，但无法检查宿主输入所使用的 uinput 路径。

## 验收标准

- 宿主 socket 检查接受专用键表中的 HOME 键值，并核对实际数据包。
- Swift benchmark 与 macOS 导航检查使用相同常量。
- CLI/GCD 完整桌面包含 Clock → 主页 → Launcher 的实际导航检查，保持 Files、持久化和正常卸载检查。
- 新 macOS 产品窗口实际完成主页导航，重新进行完整桌面对照；macOS/iOS 产品使用匹配的宿主和系统镜像。

## 风险

固定等待可能在较慢配置上不足。正式对照同时要求 Clock 与 Files 的实际首帧日志，缺失时整轮功能检查失败。iOS 导航等待与交互需要真机阶段检查。

## 实施进展

新增检查复用现有 socket 与首帧等待，仅在非交互完整桌面检查中运行。复杂度审查：没有增加运行状态、协议字段或兼容分支；删除共享常量会使 Swift、窗口和输入校验再次分别维护相同数字；删除实际导航检查会遗漏离开应用后的导航行为。

自动化流程调整期间，较早的原生预跑被中断，`20261011-212635-6a021a` 目录中的报告没有完整运行结果，已排除性能统计。随后视觉检查和失败的桌面轮次均正常结束。共享测试盘离线 `e2fsck -fn` 成功，五项检查均完成，退出码为 0；日志位于 `work/native-linux-nce/benchmarks/home-navigation-data-check.log`。

错误键值试验已结束：Launcher 等待超时，顶层仍是 Clock，原生探针退出码为 1。原始日志移至 `work/native-linux-nce/home-key-172-failure/`，该目录记录命令和失败镜像摘要。已恢复 102，随后按 nterp 开启、应用 AOT 关闭重建功能检查。

恢复 102 后，原生 CLI 的 `linux_host_input_thread_protocol` 与 `android_home_navigation` 均成功，完整桌面结果为 passed，数据盘干净卸载。GCD 与重新打包的 Direct 变体继续验证。旧失败对照的主页请求后约 5 秒仍在处理转换，原序列仅等待 2 秒即滑动；已调整为主页后 12 秒、应用列表滑动后 5 秒、应用打开后 30 秒，再以实际首帧日志确认操作完成。时序是否为原轮次失败原因仍需完整复跑确认。

`benchmark_dod.py` 新增可重复的 `--require-displayed-package` 参数，要求本次会话首次打开应用时出现对应包的 `ActivityTaskManager: Displayed` 记录，缺失时保留日志并判定该轮失败。检查使用完整包名，单测覆盖名称前缀相同的其他包及缺失首帧。可复现 Direct 配置与操作保存在 `experiments/native-linux/benchmark-desktop.json`；同一 Activity 恢复时可能没有新 Displayed 日志，本参数只检查本轮首次打开。

原生 NCE 的 CLI/GCD 完整桌面均已成功，包含主页返回、Clock/Files、持久数据和正常卸载。构建命令使用 `NCE_MM_MODE=demand NCE_SYSTEM_SERVER_PROBE=1 NCE_ART_NTERP=1 NCE_ART_AOT=0 python3 scripts/probe_lkl.py --processes --graphics-angle work/angle-macos/prefix/lib`；结果摘要见[导航验证](../../../../experiments/native-linux/results-home-navigation.json)。

Direct 单核与双核的 CLI/GCD 完整桌面、主页导航、同盘数据恢复和正常卸载均成功。对应 Mac 产品通过宿主检查，两种 iOS 变体完成构建，产物标识与摘要同样记录在导航验证 JSON 中。单核实际窗口独立复跑成功，Clock 和 Files 均有首帧。完整产品性能对照继续执行；另一次长窗口会话的偶发停止等待见[调查记录](2026-10-11-交互会话图形线程停止等待.md)，该问题尚未解决。
