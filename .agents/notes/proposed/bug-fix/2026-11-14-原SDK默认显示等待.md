# 决策记录: 原 SDK 默认显示等待

状态: proposed

## 问题

原 SDK ashmem v6 的 CLI/GCD 六入口完成观察、停止回收和同盘恢复，两个 original 均成功创建 `ApplicationSharedMemory`。system_server 的阶段消息均到 `StartDisplayManager` 完成、`WaitForDisplay` 和 `Starting phase 100`，随后没有完成消息，完整 boot 继续 failed。实际运行与设备结果见[ashmem 记录](../architecture/2026-11-14-原SDK的ashmem设备.md)。

`Starting phase 100` 是 SystemServiceManager 的总阶段消息，随后按服务注册顺序逐一调用 `onBootPhase`。它使用原有 `OnBootPhase_100_<服务类名>` 文本记录各回调，当前过滤范围尚未包含这些消息；现有日志无法确认具体等待服务。

固定 SDK 的 `DisplayManagerService.onBootPhase` 在 phase 100 先获取 `mSyncRoot`，随后开始计时，等待 `LogicalDisplayMapper.getDisplayLocked(0)` 与 `mVirtualDisplayAdapter` 均非 null；默认期限为 10000 ms。CLI 的 phase 100 消息后还有约 65 秒其他日志，单独增加观察时长无法解释当前等待。默认 adapter 注册处理也持有 `mSyncRoot`，同步执行 `LocalDisplayAdapter.registerLocked`，查询 SurfaceFlinger 的物理显示信息后创建 VirtualDisplayAdapter。当前尚未确认 DisplayManagerService 回调开始执行；初始化线程持锁等待 SurfaceFlinger/Binder 仅为推断，需各服务阶段、线程栈及调用状态确认。

## 提案

先核对固定 SDK DEX 中实际使用的 DisplayManager 与 LocalDisplayAdapter 标签，并增加原 `OnBootPhase_100_` 服务阶段文本。在独立 v7 扩展现有有界采集，保持共享 128 条预算、原 FATAL/ERROR 和六入口验收。LocalDisplayAdapter 查询静态/动态信息、模式、active mode、color mode 和 desired specs 的六类失败使用 WARN，按固定 DEX 原文采集；DisplayDeviceRepository 的设备增改消息按原 INFO 采集。同步核对原 ART SIGQUIT 线程转储所需的信号权限、SignalCatcher、tombstoned 和写入路径，采用能够保留原策略的实际采集方式。用各服务阶段、线程栈、锁持有关系和对应 Binder 或显示调用确定等待位置，再决定修正范围。

原 system_server、SurfaceFlinger、Composer、Android 属性与 SELinux 策略继续保留，设备读取和资源回收契约沿用 ashmem v6。完整 boot 仍要求 `sys.boot_completed=1`、真实进程、Binder 服务与 `cmd` 查询；原系统完成后的观察器继续按原触发条件运行。

## 曾考虑的替代方案

- 只增加 180 秒观察期限：phase 100 消息后已有超过默认 10000 ms 期限的后续运行，缺少能够解释等待的依据，先查锁与调用状态。
- 修改默认显示等待条件：会改变原 Framework 的初始化要求，当前未查明实际等待位置，先保留原条件。
- 用部署观察器文件的成功结果判断系统启动：部署与完整系统查询的范围不同，完整 boot 继续采用原实际查询条件。

## 验收标准

1. 原 v6 报告、日志与失败状态保持，新增采集来源对应固定 SDK DEX，缺失和超限结果可辨认。
2. 取得 DisplayManager 的实际初始化位置、锁与 Binder 或显示调用状态；无法采集的路径记录真实失败。
3. 修正后 CLI/GCD 均通过原 phase 100，并完成完整 boot 查询、停止回收及同盘恢复，iOS 编译和最终执行入口链接继续检查。
4. 默认显示与完整系统成功后继续真实桌面、APK 和持续性能验收；设备条件按离线目标保留待真机验证。

## 风险

新日志与线程转储会增加诊断负载，本轮结果用于功能定位。SIGQUIT 转储可能受原域权限、tombstoned 协议或原 ART 的写入路径限制，采用前核对实际行为。锁获取前的等待和已进入定时等待需要分别确认，当前阶段消息不足以区分。
