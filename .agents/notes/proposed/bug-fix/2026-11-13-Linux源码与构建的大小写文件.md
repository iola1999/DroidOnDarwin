## 提案

在项目 `work/` 创建区分大小写的 APFS 稀疏映像和独立验证工作树。源码检查点提交后用 Git checkout 生成仓库文件，固定 archive 直接读取现有文件，在该工作树的 `work/native-linux-nce/` 展开 Linux、准备 base，并在同一文件系统完成独立 APFS 克隆和两页构建。Android 原输入与已有四个候选盘继续由原绝对路径引用，来源不新增副本。

Linux 构建入口先用 `df -P` 取得现存目录所属设备，再用 `diskutil info -plist` 查询设备的 `FilesystemName`，要求 source 与输出使用 `Case-sensitive APFS`，并以现存目录的 `st_dev` 核对同一文件系统。独立 builder 的检查先于创建输出、替换已有源码和补丁，输入检查只读取目录与文件系统信息。主构建入口分别在路径选定后检查实际 SMP source、OUT 与 BUILD，再进行复制、创建目录或补丁；已有 SMP source 链接被拒绝，复制原 SOURCE 前解析其顶层链接。固定源码中 TCPMSS 两种路径的内容与 inode 另由来源验收检查。源码准备和构建输出都使用区分大小写的目录，原文件名、Kbuild 对象名与模块身份保持。

新准备先按 archive 普通文件的完整路径与摘要核对，再应用固定主线 NCE 与 Darwin host-tool 修改。符号链接按实际 `data` filter 结果记录，保留原 target 文本与规范化结果之间的关系。独立审阅核对全部 prepared 文件与实际 base，随后冻结本轮源码身份，重新运行两页 core、原 first-stage CLI/GCD、同盘恢复和 iOS 编译。

阶段完成后归档结构化结果、摘要日志、首次失败和构建身份，删除独立工作树及其生成目录，再卸载并清理本轮 APFS 映像；操作进入 `work/cleanup-2026-11-13/` 清单。已有恢复结果保留原 SHA，补充其大小写文件范围，不改写历史清单。

## 曾考虑的替代方案

- 为冲突的源码与对象改名并修改 Kbuild：同时涉及源码路径、对象名和模块身份，会增加上游兼容修改；区分大小写的文件系统可以保留原关系。
- 关闭 TCPMSS 目标或匹配配置：改变现有网络功能范围，完整 Linux 目标仍需要这些原配置。
- 只将源码放入区分大小写的目录：O 目录中的 `.o` 与 `.cmd` 仍会合并，源码与输出需要同时调整。
- 继续使用 16 KiB v2 core 产物：该产物已经记录实际身份，大小写冲突对应的网络功能尚未验收，下一轮重新生成。

## 验收标准

1. 固定 archive 的 SHA、PAX commit 与全部普通文件路径/摘要匹配；13 对大小写路径各自存在且 inode 独立。符号链接的原文本、过滤后文本和实际目标分别登记。
2. 实际 base 与 prepared 全清单匹配，固定主线准备输入与已知 17 项摘要保持；新内核按本轮源码重新生成来源身份。
3. 默认 APFS 上的小目录输入在替换、复制或补丁前被拒绝；区分大小写的 APFS 输入可完成真实克隆，来源文件保持。源码与输出跨文件系统的输入在克隆前被拒绝。
4. 新 core 的 TCPMSS target 与 match 源码、对象和 `.cmd` 路径独立，符号各自来自对应固定来源；两页 CLI/GCD 的现有 core 检查成功。实际网络 target 功能单独注明覆盖范围。
5. 新 first-stage、恢复和 iOS 编译按冻结命令推进，保存首次实际失败。原系统镜像与候选来源保持，候选 after 按实际运行记录。
6. 增量实现按 reclaim-code-entropy 和 humanizer-zh 复核，检查文件系统要求、输入读取、生成目录和挂载生命周期的实际使用方。

## 风险

现有主线历史构建可能包含同类大小写合并，已完成的局部运行结果继续归属各自的实际内核。当前 full boot、网络规则、原 vold/default-key/FBE 和持续性能继续待验收。APFS 映像挂载属于本机构建条件，手机包交付已生成的组件；iPhone 运行和资源条件仍待真机验证。
