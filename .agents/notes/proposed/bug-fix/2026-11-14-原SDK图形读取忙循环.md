# 决策记录: 原 SDK 的 512 KiB 读取与等待

状态: proposed

## 问题

原 SDK v11 的 syscall 采样中，CLI 的 PC `426683378440`、FD `9` 与 GCD 的 PC `533200366344`、FD `10` 都有请求 `524288 bytes`、返回 `-11/EAGAIN` 的后期记录。失败组中的第 `67108864`、`134217728` 次采样均包含这一请求。该组 `seen` 合计所有 read 负结果；汇总中的 `last_result=-512` 只描述末次请求，不能用于解释整组计数。原始来源与运行条件见[全局 Binder 阶段结果](../../../../work/sdk-vold-linux-v1/mount/plain-repo/experiments/native-linux/results-sdk-binder-state-init-20261114.json)和[原显示等待记录](../../../../work/sdk-vold-linux-v1/mount/plain-repo/.agents/notes/proposed/bug-fix/2026-11-14-原SDK默认显示等待.md)。

本机源码与二进制调查找到 `QemuPipeStream::commitBufferAndReadFully` 的 `512 * 1024` 读取和立即重试路径。`qemu_pipe_open` 使用 `O_RDWR | O_NONBLOCK`，`qemu_pipe_try_again` 对 EAGAIN/EINTR 返回继续重试；自有 `lkl-graphics-pipe.c` 根据 `O_NONBLOCK` 使用 `MSG_DONTWAIT`。上游 goldfish 驱动同样接受非阻塞请求并返回 EAGAIN。当前没有采集这些 read 所属任务、FD 路径和当前 ELF 映射，实际调用与上述路径的对应关系继续核对。

## 提案

本工作已包含在持续离线开发范围内。先完成固定 SDK ELF 与本机源码、读取参数和重试分支的核对。v12 仍使用冻结的 `774e47a` 与既有内核，保留其六入口、450 秒采样、完整 boot、回收和恢复结果。

若静态核对仍不能确认任务和 FD，下一次独立原 init 诊断在当前 read 返回位置取得一次身份快照。条件限定为 syscall `63`、请求 `524288 bytes`、返回 `-11`，复用现有 seccomp 模式 0 检查、完整寄存器恢复和一页临时映射。记录 PID/TID、原 FD、FD 标志、FD 与 executable 的 procfs 路径，以及原 syscall 的 PC、LR 和对应映射；查询失败、截断、errno、FD 关闭与映射解除分别保存。诊断仅访问当前 Linux 执行线程持有的 `Process`，资源在该次采样结束前释放。

确认实际等待路径后，再比较保持非阻塞设备、在 `QemuPipeStream` 的 EAGAIN 分支使用现有 poll 等待的改法，以及设备内部等待的兼容影响。原始 APK 签名与完整系统目标保持，修改限于实际触发问题的系统组件。任何行为变化先在独立输出覆盖数据就绪、关闭、信号、线程并行读写及停止回收，再运行原系统观察；尚未测量的性能结果继续注明。

## 曾考虑的替代方案

- 根据汇总的末次 errno 解释全部 read 计数：汇总结构只保存整组计数与末次参数，独立采样已经出现不同结果。
- 将自有字符设备的非阻塞 read 一律改为等待，并写为上游兼容修复：上游 goldfish 的非阻塞行为同样返回 EAGAIN，强制等待会改变可观察的文件契约。
- 在宿主后台线程读取所有 `Process` 或长期缓存 FD 与 executable：当前执行器的任务与地址映射由 Linux 调度，跨线程读取和长期缓存需要额外并发与生命周期处理；一次当前任务采样足以核对本问题。

## 验收标准

1. 保存固定源码、实际 ELF、请求大小及重试分支的对应关系；任务或 FD 尚未确认的部分明确保留。
2. 如需动态诊断，两项 original 入口分别记录实际任务、FD 查询与 PC/LR 映射，覆盖 seccomp 跳过、查询失败、截断和全部资源回收。
3. 等待修改覆盖无数据、数据到达、关闭、信号、并行读写和停止边界；保持可比较的原运行与修复后结果。
4. 原 SDK 六入口、同盘恢复、SQLite、完整 boot 与图形检查按实际结果记录。诊断观察和局部等待回归各自保留范围，启动、应用操作和持续性能另行测量。

## 风险

原 SDK 可能有其他请求同样使用 512 KiB。当前日志的 PC 可指向公共 read wrapper，仍需要 LR、任务和映射关系确认调用来源。一次身份采样只描述该次查询，不能解释所有历史负结果。系统图形库修改需要匹配固定 SDK 的接口与依赖；强制设备等待需要核对其他非阻塞使用方。iOS 实际运行、JIT 授权、设备资源与持续热状态待真机验证。
