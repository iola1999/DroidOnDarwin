# 决策记录: 原 SDK 的 512 KiB 读取与等待

状态: proposed

## 问题

原 SDK v11 的 syscall 采样中，CLI 的 PC `426683378440`、FD `9` 与 GCD 的 PC `533200366344`、FD `10` 都有请求 `524288 bytes`、返回 `-11/EAGAIN` 的后期记录。失败组中的第 `67108864`、`134217728` 次采样均包含这一请求。该组 `seen` 合计所有 read 负结果；汇总中的 `last_result=-512` 只描述末次请求，不能用于解释整组计数。原始来源与运行条件见[全局 Binder 阶段结果](../../../../work/sdk-vold-linux-v1/mount/plain-repo/experiments/native-linux/results-sdk-binder-state-init-20261114.json)和[原显示等待记录](../../../../work/sdk-vold-linux-v1/mount/plain-repo/.agents/notes/proposed/bug-fix/2026-11-14-原SDK默认显示等待.md)。

本机源码与二进制调查找到 `QemuPipeStream::commitBufferAndReadFully` 的 `512 * 1024` 读取和立即重试路径。`qemu_pipe_open` 使用 `O_RDWR | O_NONBLOCK`，`qemu_pipe_try_again` 对 EAGAIN/EINTR 返回继续重试；自有 `lkl-graphics-pipe.c` 根据 `O_NONBLOCK` 使用 `MSG_DONTWAIT`。上游 goldfish 驱动同样接受非阻塞请求并返回 EAGAIN。v13 已确认两次匹配 read 所属任务、FD 和 PC/LR 映射；具体上层调用继续核对，历史计数的全部来源尚未采集。

## 提案

本工作已包含在持续离线开发范围内。先完成固定 SDK ELF 与本机源码、读取参数和重试分支的核对。v12 仍使用冻结的 `774e47a` 与既有内核，保留其六入口、450 秒采样、完整 boot、回收和恢复结果。

若静态核对仍不能确认任务和 FD，下一次独立原 init 诊断在当前 read 返回位置取得一次身份快照。条件限定为 syscall `63`、请求 `524288 bytes`、返回 `-11`，复用现有 seccomp 模式 0 检查、完整寄存器恢复和一页临时映射。记录 PID/TID、原 FD、FD 标志、FD 与 executable 的 procfs 路径，以及原 syscall 的 PC、LR 和对应映射；查询失败、截断、errno、FD 关闭与映射解除分别保存。诊断仅访问当前 Linux 执行线程持有的 `Process`，资源在该次采样结束前释放。

确认实际等待路径后，再比较保持非阻塞设备、在 `QemuPipeStream` 的 EAGAIN 分支使用现有 poll 等待的改法，以及设备内部等待的兼容影响。原始 APK 签名与完整系统目标保持，修改限于实际触发问题的系统组件。任何行为变化先在独立输出覆盖数据就绪、关闭、信号、线程并行读写及停止回收，再运行原系统观察；尚未测量的性能结果继续注明。

### v13 一次读取身份采集

独立 v13 的 build-03 已完成 CLI/GCD 编译和链接、八项 macOS/iOS 语法检查及最终独立审阅，原准备失败分别保留。诊断仅在第 65536 项或之后的匹配负 read 返回中采样一次；保留当前任务完整 800-byte 寄存器、最多 40 次临时 syscall、四次清理调用预算和一页映射。FD 查询、路径、cmdline、maps、截断、原错误码与实际清理返回分别记录，`status=recorded` 只表示终末记录。进程 starttime 未采集，任务身份和映射关系限定于本次采样。

v13 使用 v12 实际原内核与部署图形盘，六入口、停止回收、同盘恢复和 SQLite 成功，3457 项输入保持。两个 original 各观察 180 秒，原 450 秒 Binder/SIGQUIT 条件未触发并保留 incomplete；完整 boot 和原 ashmem original 检查为 failed，wrapper 返回 1。结果见[阶段报告](../../../../work/sdk-vold-linux-v1/mount/plain-repo/experiments/native-linux/results-sdk-read-identity-init-20261115.json)及[独立结束审阅](../../../../work/v13-read-identity-result-review-v1/final-summary.json)。

CLI PID255/TID342、GCD PID245/TID332 均为 `/system/bin/surfaceflinger`，原 FD `10`、dup FD `12`、路径 `/dev/goldfish_pipe_dprctd`，`F_GETFL=133122/0x20802` 含 `O_NONBLOCK`。PC 为原 libc `read+8` 的 `0xd2b08`，LR 为原 `/vendor/lib64/egl/libEGL_emulation.so` 的 `qemu_pipe_read+0x14`，偏移 `0x1a344`。两入口每次 syscall/copy 和整次 800-byte 寄存器恢复、三次 close 及 16 KiB munmap 成功。SDK manifest、原 libc 和 EGL 的摘要已独立核对；动态 FP 链、starttime、PID namespace、原 FD_CLOEXEC 和全部映射文件字节未采集。

固定 ELF 的 Common 含 `commitBufferAndReadFully@0xe170`，两处 524288-byte read 经 `qemu_pipe_read@plt`；Common 的 GOT `0x18d20` 为 `R_AARCH64_JUMP_SLOT`，EGL 定义 `qemu_pipe_read@0x1a330`。实际叶函数已确认，上层方法和运行时绑定仍待直接验收。独立 Common 基线与等待候选已完成重建和 SDK 比较，等待候选只为该方法的 EAGAIN 分支增加现有 poll 等待；其他 read/write、部分读取、EINTR 和非阻塞设备契约保持。准备依据见[等待计划](../../../../work/sdk-plain-validation-v1/qemupipe-wait-plan-v1/README.md)，本机边界与原 SDK 结果见下文。

### Common 候选与原 SDK 比较准备

原 Common 完整重建基线与仅修改 EAGAIN 等待的候选已完成链接，静态 ABI 检查保留 230 项原导出、依赖顺序、版本要求、16 KiB LOAD 和对象布局。Mac 的实际非阻塞 socket 边界检查完成 40 次运行，等待、部分读取、关闭、EINTR、EIO、poll 失败、并行读写与回收成功。[独立审阅](../../../../work/qemupipe-wait-independent-review-v1/report.json)核对 765 个实际文件、36 个编译对象和 30 个 archive 成员，1679 项检查成功。该结果范围为读取边界，原 Android 服务使用该方法及其运行时绑定继续采集。

两项候选已从 v14 冻结的实际图形盘分别 APFS 克隆，只替换实际 vendor 中的 `libOpenglSystemCommon.so`。原 Common 独占 25 个块，vendor 有 51 个空闲块，截断后可用 76 个 4096-byte 块，共 311296 bytes；完整调试 ELF 超过该容量。部署采用 `llvm-strip --strip-debug` 的独立副本，基线为 173640 bytes，等待候选为 173664 bytes，各占 43 个块，剩余 33 个空闲块。完整 ELF 保留，程序段、动态 ABI、非调试 section、静态符号和方法地址已核对；LOAD 中的差异限定为 ELF 头的 section table 位置及数量字段。

[候选交付报告](../../../../work/sdk-plain-validation-v1/common-sdk-candidates-v1/delivery-summary.json)与[原始 inode 复核](../../../../work/sdk-plain-validation-v1/common-sdk-candidates-v1/raw-inode-review.json)成功。每盘检查 800 个原始 inode，Common 以外的 799 个 inode 字节保持，其余 784 个已记录 inode 的状态、xattrs 和 blocks 保持；inode bitmap、权限与 SELinux、vendor 外部字节、LP 元数据和 AVB 尾保持，两个只读 e2fsck 均退出 0。原内容 SHA256 覆盖 541 个普通文件；[已分配块复核](../../../../work/cleanup-2026-11-15/common-other-inode-block-review.json)进一步逐字节比较其他 inode 的 27651 条块引用、24249 个唯一物理块，包含 45 个目录的 50 个目录块，全部保持。目录 inode 和块号保持但块内一字节变化的反例被拒绝。14 项实际依赖按 8 个 vendor、6 个 system 核对，源盘摘要保持。两盘使用 [read_common_allocated_blocks.py](../../../../work/cleanup-2026-11-15/read_common_allocated_blocks.py) 的 `read_full_candidate()`，该入口复用冻结的 base/raw reader 并检查全部其他 inode 块，原图形盘的三文件报告继续保留。

本次比较复用完成诊断地址修正的 v15 宿主和同一 regset 内核，通过 `NCE_STOCK_INIT_SYSTEM` 选择候选只读盘。图形传输、allocator、mapper、其余 SDK 内容、相同初始 data/metadata、180 秒观察、450 秒诊断条件和六入口验收保持。重建基线运行后，等待候选串行完成原六入口；原 SDK 上层方法、GOT 解析结果、等待行为、完整 boot 和持续性能继续按实际采集验收。

### Common 原 SDK 比较结果

2026-11-15 的[重建基线](../../../../work/sdk-plain-validation-v1/common-sdk-comparison-v1/baseline/run/report.json)与[等待候选](../../../../work/sdk-plain-validation-v1/common-sdk-comparison-v1/wait/run/report.json)均完成六入口、观察回收、同盘恢复、metadata 原 rc 属性与 SQLite 检查，每项退出 0；4401 项输入及 83 个 Python 输入前后保持，[独立结果审阅](../../../../work/sdk-plain-validation-v1/common-sdk-comparison-v1/independent-result-review-v1/comparison.json)成功。两变体完整 boot 均为 failed，原 ashmem 的 450 秒诊断契约在每个 original 的 180 秒观察窗口内保持 incomplete。

本机环境为 Apple M5 Ultra、macOS 27.0（26A428），使用共享 v15 宿主、regset 内核、Direct、16 KiB guest/host 页、单 CPU、1 GiB guest RAM、128 MiB translation cache、50000 instruction batch、2 ms timer preemption 与 100 ms 内存采样。两变体使用同一 seed 的独立 APFS 克隆 data/metadata，只读系统盘分别使用已核对的 Common 基线与等待候选。wrapper 总耗时覆盖克隆、六入口、回收、导出与复核，完整 Android 启动耗时和持续交互性能尚未获得。

v15 和重建基线的 CLI/GCD 均缺少 DisplayManager phase 100 完成消息；等待候选的两个入口均记录该阶段与 PackageManager 完成，并继续到 `startCoreServices`。等待候选 taglog 的 CLI `seen=129`、GCD `seen=200`，两入口均记录 128 条，分别遗漏 1 条和 72 条。六次身份快照均取得 SurfaceFlinger 的非阻塞图形 FD `10`，PC/LR 文件偏移保持 `0xd2b08` 与 `0x1a344`。全局 read 负结果计数包含其他服务与 FD；成功 ppoll、pollfd 内容、上层调用帧和 Common GOT 尚未采集，实际等待调用关系继续确认。

### 本次调用帧与 GOT 采集计划

既有快照缺少 SurfaceFlinger 本次 SP、x29、帧字节和 Common GOT 内容，logd 的帧属于不同任务。[独立计划](../../../../work/sdk-plain-validation-v1/surfaceflinger-read-fp-got-candidate-v1/plan.json)保持原匹配 read 的条件及单次采样，在本次 SP 的可读 VMA 与一页范围内读取最多四个 16-byte 调用帧，再读取所选 Common 的一个 8-byte `qemu_pipe_read` GOT 槽。复用已有 maps 读取、帧 helper、TBI 处理和完整 800-byte 寄存器恢复，每次读取分别记录 seccomp 模式、完整或部分复制、停止原因及恢复结果；原临时 syscall 数量、FD 关闭和 scratch 映射保持。

原、重建基线和等待候选的地址由各自部署 ELF 的符号、relocation、PT_LOAD 和真实调用指令生成，保存对应 SHA；`NCE_STOCK_READ_COMMON_LAYOUT` 选择本次布局，默认 original，未知值记录未完成。新诊断改变宿主源码及构建身份，当前 Common 比较继续使用原 v15 宿主，后续诊断独立构建和运行。验收覆盖地址、对齐、溢出、TBI、部分复制、maps 缺项与冲突、布局不匹配和恢复失败；实际调用帧与 GOT 结果按后续采集保存。

扩展诊断已在原会话完成[本机验证](../../../../work/sdk-plain-validation-v1/surfaceflinger-read-fp-got-candidate-v1/validation-01/report.json)，`status=passed`、`guest_started=false`。4 KiB 与 16 KiB 的 native/sanitizer 四项构建、252 项用例和 84 项错误记录拒绝检查成功，输入摘要前后保持。该结果覆盖本机 fixture 与地址、部分复制、映射和恢复边界；独立审阅及实际 guest 调用帧、GOT 与完整寄存器恢复继续验收，Common 比较仍使用原 v15 宿主。

随后的审阅发现校验器接受最后一帧模式变化或 helper 失败后仍读取 GOT 的记录，停止原因也未与复制结果关联。[修复](../../../../work/sdk-fp-got-review-20261115-v2/review.json)逐帧核对 helper 返回值，从最后一帧派生是否允许读取 GOT，并让 `stop_reason` 与帧和 GOT 结果互相约束；普通和带标签空 `previous_fp` 的 `chain_end` 继续允许读取 GOT。改动限于 `read_fp_got_validation.py` 与 `validate.py`，新增七项应拒绝的记录变体。[validation-02](../../../../work/sdk-plain-validation-v1/surfaceflinger-read-fp-got-candidate-v1/validation-02/report.json) 的四项构建、252 项用例和 112 项错误记录拒绝检查成功，110 项输入前后保持，`guest_started=false`。一次 maps 采样与后续帧、GOT 读取之间有时间差，运行时调用帧、GOT 绑定和后续 poll 仍待 guest 采集确认。

## 曾考虑的替代方案

- 根据汇总的末次 errno 解释全部 read 计数：汇总结构只保存整组计数与末次参数，独立采样已经出现不同结果。
- 将自有字符设备的非阻塞 read 一律改为等待，并写为上游兼容修复：上游 goldfish 的非阻塞行为同样返回 EAGAIN，强制等待会改变可观察的文件契约。
- 在宿主后台线程读取所有 `Process` 或长期缓存 FD 与 executable：当前执行器的任务与地址映射由 Linux 调度，跨线程读取和长期缓存需要额外并发与生命周期处理；一次当前任务采样足以核对本问题。

## 验收标准

1. 保存固定源码、实际 ELF、请求大小及重试分支的对应关系；任务或 FD 尚未确认的部分明确保留。
2. 如需动态诊断，两项 original 入口分别记录实际任务、FD 查询与 PC/LR 映射，覆盖 seccomp 跳过、查询失败、截断和全部资源回收。
3. 等待修改覆盖无数据、数据到达、关闭、信号、并行读写和停止边界；保持可比较的原运行与修复后结果。
4. 原 SDK 六入口、同盘恢复、SQLite、完整 boot 与图形检查按实际结果记录。诊断观察和局部等待回归各自保留范围，启动、应用操作和持续性能另行测量。

## 风险

原 SDK 可能有其他请求同样使用 512 KiB。当前日志的 PC 可指向公共 read wrapper，仍需要 LR、任务和映射关系确认调用来源。一次身份采样只描述该次查询，不能解释所有历史负结果。系统图形库修改需要匹配固定 SDK 的接口与依赖；强制设备等待需要核对其他非阻塞使用方。重建记录尚未确认 SDK r07 的原始 Soong 命令、vendor API 配置与 protobuf 生成器；当前依赖文件使用 `-MMD`，未列系统头。两变体 SDK 比较已完成，完整 boot、实际等待调用关系及 sensors 后续等待继续验收。iOS 实际运行、JIT 授权、设备资源与持续热状态待真机验证。
