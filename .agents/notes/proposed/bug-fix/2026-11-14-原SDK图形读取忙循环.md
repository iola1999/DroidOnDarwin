# 决策记录: 原 SDK 的 512 KiB 读取与等待

状态: proposed

## 问题

原 SDK v11 的 syscall 采样中，CLI 的 PC `426683378440`、FD `9` 与 GCD 的 PC `533200366344`、FD `10` 都有请求 `524288 bytes`、返回 `-11/EAGAIN` 的后期记录。失败组中的第 `67108864`、`134217728` 次采样均包含这一请求。该组 `seen` 合计所有 read 负结果；汇总中的 `last_result=-512` 只描述末次请求，不能用于解释整组计数。原始来源与运行条件见[全局 Binder 阶段结果](../../../../work/sdk-vold-linux-v1/mount/plain-repo/experiments/native-linux/results-sdk-binder-state-init-20261114.json)和[原显示等待记录](../../../../work/sdk-vold-linux-v1/mount/plain-repo/.agents/notes/proposed/bug-fix/2026-11-14-原SDK默认显示等待.md)。

本机源码与二进制调查找到 `QemuPipeStream::commitBufferAndReadFully` 的 `512 * 1024` 读取和立即重试路径。`qemu_pipe_open` 使用 `O_RDWR | O_NONBLOCK`，`qemu_pipe_try_again` 对 EAGAIN/EINTR 返回继续重试；自有 `lkl-graphics-pipe.c` 根据 `O_NONBLOCK` 使用 `MSG_DONTWAIT`。上游 goldfish 驱动同样接受非阻塞请求并返回 EAGAIN。v13 已确认两次匹配 read 所属任务、FD 和 PC/LR 映射；具体上层调用继续核对，历史计数的全部来源尚未采集。

## 提案

本工作已包含在持续离线开发范围内。先完成固定 SDK ELF 与本机源码、读取参数和重试分支的核对。v12 仍使用冻结的 `774e47a` 与既有内核，保留其六入口、450 秒采样、完整 boot、回收和恢复结果。

若静态核对仍不能确认任务和 FD，下一次独立原 init 诊断在当前 read 返回位置取得一次身份快照。条件限定为 syscall `63`、请求 `524288 bytes`、返回 `-11`，复用现有 seccomp 模式 0 检查、完整寄存器恢复和一页临时映射。记录 PID/TID、原 FD、FD 标志、FD 与 executable 的 procfs 路径，以及原 syscall 的 PC、LR 和对应映射；查询失败、截断、errno、FD 关闭与映射解除分别保存。诊断仅访问当前 Linux 执行线程持有的 `Process`，资源在该次采样结束前释放。

确认实际等待路径后，再比较保持非阻塞设备、在 `QemuPipeStream` 的 EAGAIN 分支使用现有 poll 等待的改法，以及设备内部等待的兼容影响。原始 APK 签名与完整系统目标保持，修改限于实际触发问题的系统组件。任何行为变化先在独立输出覆盖数据就绪、关闭、信号、线程并行读写及停止回收，再运行原系统观察；尚未测量的性能结果继续注明。

### v13 一次读取身份采集

独立 v13 的 build-03 已完成 CLI/GCD 编译和链接、八项 macOS/iOS 语法检查及最终独立审阅，原准备失败分别保留。诊断仅在第 65536 项或之后的匹配负 read 返回中采样一次；保留当前任务完整 800-byte 寄存器、最多 40 次临时 syscall、四次清理调用预算和一页映射。FD 查询、路径、cmdline、maps、截断、原错误码与实际清理返回分别记录，`status=recorded` 只表示终末记录。进程 starttime 未采集，任务身份和映射关系限定于本次采样。

v13 使用 v12 实际原内核与部署图形盘，六入口、停止回收、同盘恢复和 SQLite 成功，3457 项输入保持。两个 original 各观察 180 秒，原 450 秒 Binder/SIGQUIT 条件未触发并保留 incomplete；完整 boot 和原 ashmem original 检查为 failed，wrapper 返回 1。结果见[阶段报告](../../../../work/sdk-vold-linux-v1/mount/plain-repo/experiments/native-linux/results-sdk-read-identity-init-20261115.json)及[独立结束审阅](../../../../work/v13-read-identity-result-review-v1/final-summary.json)。

CLI PID255/TID342、GCD PID245/TID332 均为 `/system/bin/surfaceflinger`，原 FD `10`、dup FD `12`、路径 `/dev/goldfish_pipe_dprctd`，`F_GETFL=133122/0x20802` 含 `O_NONBLOCK`。PC 为原 libc `read+8` 的 `0xd2b08`，LR 为原 `/vendor/lib64/egl/libEGL_emulation.so` 的 `qemu_pipe_read+0x14`，偏移 `0x1a344`。两入口每次 syscall/copy 和整次 800-byte 寄存器恢复、三次 close 及 16 KiB munmap 成功。SDK manifest、原 libc 和 EGL 的摘要已独立核对；动态 FP 链、starttime、PID namespace、原 FD_CLOEXEC 和全部映射文件字节未采集。

固定 ELF 的 Common 含 `commitBufferAndReadFully@0xe170`，两处 524288-byte read 经 `qemu_pipe_read@plt`；Common 的 GOT `0x18d20` 为 `R_AARCH64_JUMP_SLOT`，EGL 定义 `qemu_pipe_read@0x1a330`。实际叶函数已确认，上层方法和运行时绑定仍待直接验收。下一步在独立目录无行为改变重建原 Common，核对 ABI、布局和依赖后，只为该方法的 EAGAIN 分支增加现有 poll 等待；其他 read/write、部分读取、EINTR 和非阻塞设备契约保持。准备依据见[等待计划](../../../../work/sdk-plain-validation-v1/qemupipe-wait-plan-v1/README.md)，等待边界通过后再运行 SDK。

## 曾考虑的替代方案

- 根据汇总的末次 errno 解释全部 read 计数：汇总结构只保存整组计数与末次参数，独立采样已经出现不同结果。
- 将自有字符设备的非阻塞 read 一律改为等待，并写为上游兼容修复：上游 goldfish 的非阻塞行为同样返回 EAGAIN，强制等待会改变可观察的文件契约。
- 在宿主后台线程读取所有 `Process` 或长期缓存 FD 与 executable：当前执行器的任务与地址映射由 Linux 调度，跨线程读取和长期缓存需要额外并发与生命周期处理；一次当前任务采样足以核对本问题。

## 验收标准

1. 保存固定源码、实际 ELF、请求大小及重试分支的对应关系；任务或 FD 尚未确认的部分明确保留。
2. 如需动态诊断，两项 original 入口分别记录实际任务、FD 查询与 PC/LR 映射，覆盖 seccomp 跳过、查询失败、截断和全部资源回收。
3. 等待修改覆盖无数据、数据到达、关闭、信号、并行读写和停止边界；保持可比较的原运行与修复后结果。
4. 原 SDK 六入口、同盘恢复、SQLite、完整 boot 与图形检查按实际结果记录。诊断观察和局部等待回归各自保留范围，启动、应用操作和持续性能另行测量。

## 风险

原 SDK 可能有其他请求同样使用 512 KiB。当前日志的 PC 可指向公共 read wrapper，仍需要 LR、任务和映射关系确认调用来源。一次身份采样只描述该次查询，不能解释所有历史负结果。系统图形库修改需要匹配固定 SDK 的接口与依赖；强制设备等待需要核对其他非阻塞使用方。iOS 实际运行、JIT 授权、设备资源与持续热状态待真机验证。
