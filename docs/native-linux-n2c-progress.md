## 本次实现

### 进程切换时更新实际变化的映射

原实现每次切换进程都会撤销整个用户地址窗口，再逐页恢复 Linux 页表中的
驻留页面。新实现记录宿主窗口已经安装的物理页和权限，保留相同映射，并将
连续物理页或连续撤销区域合并为一次宿主调用。代码继续使用 iOS 最初准备的
执行地址，源页或权限发生变化时才更新对应内容。

数据映射默认按需恢复。第一次访问时，最多恢复 32 个物理连续的 16 KiB
页面，并在 Linux `mm_struct` 中记录因进程切换而重新访问的页面。后续切换
提前恢复这些页面，减少密集访问反复触发 Darwin 信号的成本。初次分配和
COW 缺页不计入访问记录，解除映射时清除相应记录。

这一记录会保留到解除映射或地址空间销毁。密集访问转为稀疏访问后的记录
淘汰尚未实现，本阶段测试分别建立各个工作集，未测量该转换的长期表现。

### Linux 系统调用检查用户内存

Linux 的 `copy_from_user`、`copy_to_user`、`get_user`、`put_user` 与清零操作
现在通过客体页表检查地址和权限。需要时调用 Linux 缺页处理，再经物理 RAM
别名复制；内核原子区或禁止缺页时返回未完成的字节数。系统调用因此可以
返回 `EFAULT`，也能报告跨有效页和无效页边界的部分读写。

宿主发起的显式 LKL 调用仍使用宿主缓冲区。客体不能调用内部进程启动操作
246；调用返回 `ENOSYS`。长度为零的 iovec 接受空指针，覆盖 musl 的实际
`writev` 用法。检查依赖单 Linux CPU 的串行执行；并行执行需要重新处理
页表与实际复制之间的同步。

这部分只覆盖 Linux 用户内存访问接口。原生客体指令仍能寻址整个宿主进程，
当前执行器没有恶意程序隔离。客体直接访问非法地址时的 Linux 信号递送仍
待实现，当前版本仅用于受控程序。

## 同一构建的性能对照

Mac 上串行运行 `full`、`diff`、`lazy` 三种策略，各三次，交替运行顺序；三种
策略使用相同内核和程序。`full` 保留完整映射恢复，`diff` 更新页表差异，
`lazy` 再加入按需恢复和访问记录，默认启用 `lazy`。因此下表比较的是地址
空间策略，原始 B2 的其他实现差异未包含在倍数中。

每次运行包含 28 个场景：2、4、8、16 MiB 驻留工作集，0%、50%、100%
共享页，访问每类区域的首页或每页，并包含同地址空间的线程对照。每个场景
先完成子进程私有页的 COW，再通过 pipe 完成 128 次请求与回复；每次访问
检查数据，子进程退出后检查父进程的全部私有页面。

以下为 16 MiB 场景的三次中位数；单位为每次请求与回复的微秒。

| 共享比例 / 访问范围 | full | diff | lazy | full / lazy |
| --- | ---: | ---: | ---: | ---: |
| 0% / 首页 | 2,741.664 | 557.328 | 31.554 | 86.9 倍 |
| 50% / 各区域首页 | 2,157.664 | 764.296 | 25.054 | 86.1 倍 |
| 100% / 首页 | 1,417.687 | 608.351 | 18.140 | 78.2 倍 |
| 0% / 每页 | 4,097.023 | 2,165.562 | 2,248.046 | 1.82 倍 |
| 50% / 每页 | 3,997.101 | 1,609.171 | 1,686.195 | 2.37 倍 |
| 100% / 每页 | 3,884.437 | 71.351 | 110.281 | 35.2 倍 |
| 同地址空间线程 / 每页 | 15.546 | 15.789 | 15.539 | 1.00 倍 |

16 MiB 全私有、首页访问的 `lazy` 三次范围为 23.984–31.828 μs；全私有、
每页访问范围为 2,111.343–2,337.164 μs。每页访问全共享数据时，`diff` 比
`lazy` 更快；默认选择 `lazy` 是为了降低稀疏访问的大量无效映射成本。

28 个场景及其内存检查中，宿主数据映射调用的中位数从 2,673,335 次降为
370,125 次，代码复制从 311,918,592 字节降为 491,520 字节。单独采用冷按需
恢复的前期试验，在密集私有访问时发生退化，因此增加了访问记录。

大幅收益目前限定于上述进程通信负载。频繁扫描全部私有页面仍需要替换大量
映射，完整 Android、ART、Binder 和图形负载的收益尚未测量。

原始记录、全部场景的范围、中位数、源文件与内核哈希保存在
`experiments/native-linux/results-memory-macos.json`。命令与 GCD 基础回归
保存在 `work/native-linux-nce/processes/lkl-summary.json`。

## 正确性与持续运行

新增 `mm-tests.c` 在真实 Linux 用户态检查：空 iovec、空指针、越界地址、
错误路径地址、`PROT_NONE`、只读页、futex 错误地址、跨页部分读写，以及
64 轮父子进程间的共享写入、COW、权限变化、`MADV_DONTNEED` 和固定地址
解除映射后复用。三个策略的重复运行均通过这些检查。

额外的 256 轮用户态压力测试完成 2,048 次命令、14,336 个 pthread 线程，
用户态各轮累计 16.973 秒；全部检查后，18,814 个上下文分配与释放数一致。
各轮物理占用为 22,872,664–24,379,992 字节，首轮 23,233,088 字节，末轮
22,872,664 字节。这次 Mac 采样未观察到随轮次持续增长，iOS 的应用占用与
长期发热仍需设备数据。

默认策略通过命令行和 GCD 两种入口，分别完成 1,294 个上下文的分配与释放。
GCD 路径解除 49 个线程继承的信号屏蔽。8 项 ELF 单测、5 项调试器断开检查、

`experiments/native-linux/results-n2c-build.json`。

## 其他实现尝试与复杂度审查

独立 Mac 实验尝试为进程保留完整宿主映射视图，再通过 `vm_remap` 替换整个
数据区域。共享写入与权限检查可通过，但重新访问大量页面仍有较高成本。
另一组实验用命名内存入口逐页映射，仅减少部分映射调用成本。两者均未接入
当前执行器，后续是否采用取决于更大真实负载的结果。

按 reclaim-code-entropy 审查本次实现：

- 宿主已安装映射与 Linux 页表分别描述实际宿主窗口和目标进程页面；删除
  已安装记录就无法跳过相同映射。临时 `desired` 数组只用于一次更新计算。
- 每个 `mm_struct` 的访问位图为 512 字节，无额外分配与释放流程。去掉它
  会恢复密集访问时重复信号处理的退化；解除映射和初始化负责清除记录。
- 三种映射策略由同一对照脚本使用，保留用于消融实验。iOS 界面只显示优化
  版和基线版。没有增加通用后端接口或第二套进程调度。
- 用户内存读写共用一个逐页复制函数，底层页表查询也与映射共用。删除权限
  检查会使错误指针与只读页回归失败；删除零长度例外会使 musl `writev` 失败。
- 程序运行入口从既有用户态测试提取，供 `/init-user` 和 `/mm-bench` 共用。
  临时系统调用跟踪已经移出最终代码，未引入额外运行依赖。

## N2-C1 手机结果与后续交付要求

用户提供的日志 (4) 为 `lazy`，(5) 为 `full`，同属构建
`N2-C1-iOS-20261009-034855`。两轮均完成 28 个场景、64 轮内存边界检查，
1,294 个上下文全部释放，最终结果为 `passed`。

16 MiB 工作集中，私有页稀疏访问从 2,666.578 μs 降到 25.820 μs，约
103.3 倍；50% 和 100% 共享的稀疏访问分别约 76.7 和 82.3 倍。访问全部
共享页从 3,732.835 μs 降到 66.570 μs，约 56.1 倍；访问全部私有页从
3,755.406 μs 降到 1,842.328 μs，约 2.04 倍。每种模式仅运行一次，设备

1.03 倍。优化版应用物理占用从 59,885,600 字节增至末轮 124,799,032 字节，
